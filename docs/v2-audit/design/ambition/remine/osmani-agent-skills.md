# Ambition Re-mine — Addy Osmani's agent-skills ("Study the Formats, Don't Install the Skills")

## What this source is (plain English, 2-3 sentences)

This source is a curator's verdict on `addyosmani/agent-skills` — a 23-skill prose library (Meta→Define→Plan→Build→Verify→Review→Ship lifecycle, three reviewer personas, an orchestration doctrine, anti-rationalization tables in every skill, portable to Cursor/Gemini/Windsurf/Copilot). The verdict's spine is "study the formats, don't install the skills": against a structurally-gated harness, importing prose skills is an advisory *downgrade*, so harvest the repo for three formats/borrows and reject the other twenty. The catch the deeper passes expose: the verdict scores that screen against an *idealized, canon-level* picture of our harness, not against what actually runs on disk — and the disk floor is far thinner (mostly-advisory) than the rejections assume.

## The full-ambition moves this source teaches

### Move: Anti-rationalization tables as a *machine-greppable, enforced* constraint store (not prose)

- **Plain-English what & why:** Every skill in Addy's repo ends with a small table: a list of excuses an agent might use to skip a step, each paired with why it's wrong and what to do instead. The world-class insight (recovered in pass2) is *not* "write down excuses" — the model already knows these. It's that **canon is worthless as prose the model already knows, but valuable as a machine-greppable shape that survives in a file and gets enforced by something other than the model's goodwill.** The failure it prevents: an agent under deadline pressure invents excuse #N+1 ("tests are flaky, I'll skip", "this is trivial, reviewed already") and rationalizes past a gate. A finite, enforced blocklist converts open-ended rationalization into a checkable signal. This is exactly the failure mode our own memory already records repeatedly: `feedback_sentinel_bypass`, `feedback_pipeline_steps_not_skippable`, `feedback_best_practice_first` — every one is an agent rationalizing past a rule.
- **The mechanism:** Build `learned-patterns.md` (today a phantom) as a three-column table — `excuse → why-wrong → MUST-FIX action` — AND wire an enforcer that greps it. Concretely: (1) a `/cr` pass that reads the table and fails if any logged anti-pattern signature appears in the diff or the agent's own justification text; (2) a `session-end.sh` Stop hook that auto-proposes new rows when a correction happens. Without the enforcer it's the advisory downgrade the page itself warns against — pass2/pass3 are emphatic that "enforce" must mean a hook/CI greps or blocks it, not that a CLAUDE.md line mentions it.
- **Citation:** `learned-patterns.md` confirmed phantom — ground-truth §6 ("referenced on disk, never built on disk *or* in canon"; map header line 26 lists it as a remaining phantom). `session-end.sh` (Stop → memory candidates) **canon-declared, absent on disk** — §3e / §5 (map line 209: "Canon's memory-capture hook — absent; disk's memory is fully manual").
- **Conservative disposition:** §C-style demoted borrow. MASTER-FINDINGS / pass3 kept it as "REAL GAP" but reframed it down from "restructure an existing template" to "decide whether to build the store at all, then bind its format to an enforcer," noting the target file doesn't exist and the page omits the enforcer.
- **RE-JUDGMENT under the new charter: ELEVATE.** The conservative reframing ("first decide whether to build the store at all") is exactly the deferral the new charter retires. Under "self-improving loops are first-class," a *learned-constraint store that an enforcer greps* is not optional — it is the literal substrate of a self-improving harness. The page's framing was too small (one borrowed table); the disk reality is too empty (phantom file, no writer). Build the full triad now: the table format, the `session-end.sh` writer, AND the `/cr` grep-enforcer. This is bigger than the source proposed because the source assumed the store and writer existed; they don't. Make it a first-class autonomy primitive: every unattended run that hits a correction writes a new enforced row, and the next run cannot repeat that excuse.

### Move: Subtractive enforcement — make *deletion* a first-class, guarded action

- **Plain-English what & why:** Addy's `code-simplification` + `deprecation-and-migration` skills make *removing* code a disciplined, named operation, guarded by Chesterton's Fence (don't delete what you don't understand the reason for). The world-class point: every enforcement mechanism we own *prevents adding* (net-diff floors, slop linters, scope guards) and *nothing drives removal*. A harness that only ratchets additions accretes dead code, dead skills, and dead canon forever — the exact drift the source warns about, but turned inward. The failure it prevents: an agent fleet that can only grow the codebase, never prune it, until the context and the codebase both rot.
- **The mechanism:** Wire `/simplify` (documented in canon, absent on disk) as a real skill with a Chesterton's-Fence guard pass: before any deletion it must state *why the code exists* and *what proves it's dead* (no callers, no tests reference it, flag is fully rolled out). Fold deprecation into the change/feature flow for `task-type: migration`, with a documented rollback path. This is the harness's first subtractive enforcement point.
- **Citation:** `/simplify` **documented in canon, ABSENT on disk** — §5 canon-only registry (map lines 167, 282: "Documented skills with no disk dir … `/simplify`"; line 358: "`/simplify` is a [canon-only absence]"). Subtractive enforcement absent everywhere — §5/§6 registries contain only additive/guard mechanisms.
- **Conservative disposition:** Pass3 (b)#1 graded it "REAL GAP … build-or-reject" and called it "the page's strongest gap," but framed as a single skill adoption.
- **RE-JUDGMENT under the new charter: ELEVATE.** The pass3 grading was already correct in direction — this is the one borrow even the conservative pass flagged as strongest. Under the new charter it grows from "adopt one skill" to "establish the *subtractive pillar's first enforcement point* as a designed-in capability." At parallel-fleet scale across 5+ repos, additive-only harnesses are a guaranteed slow-motion failure: every repo accumulates dead skills and stale canon (we already carry an un-synced `/tdd` fork and an internally-inconsistent canon — §1, §7). Build `/simplify` now AND make "does this have a removal path?" a standing question in the change flow. Bigger because it should also drive *harness self-pruning* (dead skills, phantom files like `learned-patterns.md` before it's built, stale canon), not just product-code deletion.

### Move: Stop-the-line for unattended runs (halt a defect class until root-caused)

- **Plain-English what & why:** From the orchestration doctrine — when a recurring defect appears, *halt forward work on that defect class until it's root-caused*, rather than continuing to produce artifacts on a known-broken foundation. The failure it prevents, in the source's own words: "without it an unattended run keeps stacking PRs on a known-broken foundation." This is the single most autonomy-relevant idea in the source.
- **The mechanism:** A defect-class halt in the unattended/`/loop`/`/queue` path: when CI or `/cr` flags the same failure signature N times in a row across a batch, the harness stops opening new PRs in that class, writes a stop-the-line marker, and surfaces it (Slack/Linear notification) for human root-cause — instead of the fleet grinding out 20 PRs all built on the same broken assumption. Pair with the learned-patterns store (move 1): the root-cause becomes an enforced row.
- **Citation:** Disk `/cr` has **"no UNATTENDED branching"** — §3c (map line 182: "No REJECT tier, no UNATTENDED branching"). The only UNATTENDED-mode mechanism on disk is the worktree prod-key firewall — §3e (line 212). CI (`ci.yml`) runs per-PR but nothing halts a *series* of agent PRs on a recurring failure — §3f. Confirmed absence of any defect-class halt.
- **Conservative disposition:** Pass3 (b)#4 "REAL GAP … bears on the map's headline V2 driver (autonomous/unattended operation)" — graded real but left as a gap, not a build item. MASTER-FINDINGS folded it into the deferred autonomy cluster (§C).
- **RE-JUDGMENT under the new charter: ELEVATE — to in-scope-now, first-class.** This is precisely the kind of move the old "defer autonomy" charter suppressed and the new charter reverses. Cloud `/schedule` exists and runs unattended fleets; the durability objection is moot. An unattended fleet *without* stop-the-line is actively dangerous — it amplifies a single broken assumption into a flood of bad PRs across repos. This is not a nice-to-have; it is a **safety precondition for running autonomous fleets at all.** Build it now alongside the `/queue` and cloud-schedule paths. Bigger than the source framed it: the source treated it as one orchestration note; for a parallel-fleet harness it is the circuit breaker the whole autonomy story depends on.

### Move: Turn the source's enforcement lens *on ourselves* — close the honor-system verification holes

- **Plain-English what & why:** The source's central proof against Addy's repo is "evidence-based verification is self-reported — the agent checks its own box; nothing captures and verifies the runner's output." Pass2's sharpest finding: the page never turns that lens on *us*, and when the ground-truth map does, the answer is uncomfortable. Our review gate has the *exact same honor-system hole* the page indicts in Addy's TDD checklist. The failure it prevents: we ship a "9-pass reviewed" PR whose review was never actually verified — a green checkbox with no oracle behind it.
- **The mechanism:** Close the two map-confirmed self-reported holes: (1) **CI never verifies the `.cr-ok` sentinel** — the file is gitignored and never reaches CI, so the review gate is honor-system; wire CI to require a valid, non-stale `branch:sha` sentinel. (2) The live pre-commit is a **67-byte husky shim** that lacks the canon's main-branch agent hard-block, while the canon-matching `.githooks/pre-commit` is wired out (`core.hooksPath=.husky/_`) — re-point the hooks path or port the block so the enforced floor matches canon. Make verification *captured and checked*, not self-graded.
- **Citation:** §3f — "Node 8.5(c) gap (CI never verifies `.cr-ok`) is a disk fact; canon's `.cr-ok` chain has the same hole (gitignored, never reaches CI)" (map lines 229–230). §3e — "overwhelmingly advisory … neither has a deterministic backstop" (lines 218–220); 67-byte husky shim / `.githooks` wired out (line 213).
- **Conservative disposition:** Pass3 (b)#5 and (c)#1 raised it ("REAL GAP … the most direct application of the page's 'evidence-based verification is honor-system' insight to us"), but it was a critique of the article's blind spot rather than a promoted build item; MASTER-FINDINGS did not elevate it into the 6 wiring moves as a named deliverable.
- **RE-JUDGMENT under the new charter: ELEVATE / NEW.** The conservative synthesis noticed the hole but treated it as an article weakness, not a build target. Under "world-class is the only goal," a review gate that nothing verifies is *not* world-class — CodeRabbit/Ramp-grade harnesses make the gate deterministic. For autonomous fleets this is doubly load-bearing: in unattended runs there is no human to confirm `/cr` ran, so the sentinel *is* the only signal — and today CI ignores it. Promote to a first-class build item: deterministic, CI-verified review gate. This is the move the source's best insight points at, aimed where the source declined to look.

### Move: The adopt / borrow / reject *screen* as a reusable, enforced harness rule

- **Plain-English what & why:** Pass2's deepest finding: the real deliverable of this source is *not* the 23 verdicts — it's the **screening function** behind them. For any external skill/library, score `structural_gain − (context_tax + drift_surface + maintenance_cost)` and bucket it: **adopt** (a structural capability you lack), **borrow** (a format you can bind to an existing gate), **reject** (a prose duplicate of something you already *enforce*). The failure it prevents: a marketplace world where you bolt on 23 plausible-looking skills and quietly 23× your drift surface with zero new measurable capability.
- **The mechanism:** Lift the screen into an AGENTS.md-level (or `/cr`-able) standing rule for vetting any external skills library before install — with pass2's correction baked in: **"enforce" means a hook/CI/gate greps or blocks it, not that a CLAUDE.md line mentions it.** This becomes the gate every plugin/marketplace import passes through.
- **Citation:** Confirmed absence — no such vetting rule exists in any map layer (§3a–§3f, §5/§6 registries contain no skill-import screen). The need is named by the source itself and by the map's multi-project/installable headline (§0, §8).
- **Conservative disposition:** Pass3 (d) named it "the single highest-value synthesis artifact" — but parked it under "synthesize, don't research," i.e. a doc to write later, not a mechanism to build.
- **RE-JUDGMENT under the new charter: ELEVATE.** "Clarity beats minimalism" and "distribution = plugin + marketplace" make this *more* important than the conservative pass allowed. The moment the harness is shared across 5+ repos via a marketplace, an import-vetting screen is the thing that stops every repo from accreting a different pile of advisory skills. It should be an *enforced* gate on imports (a `/cr`-style check when a new skill lands), not a paragraph in AGENTS.md. Bigger because the new charter makes the harness a *distributed* artifact, which is exactly the condition under which an unenforced screen drifts.

## Autonomy angle

Strongly yes — this source is unusually autonomy-relevant for a "prose skills" critique. Three of its moves are autonomy primitives:

- **Stop-the-line** (move 3) is the headline autonomy contribution: an explicit circuit breaker for unattended fleets so a single broken assumption doesn't get amplified into a flood of bad PRs. The source states the exact failure mode ("an unattended run keeps stacking PRs on a known-broken foundation"). With cloud `/schedule` running real unattended fleets, this is a safety precondition, not a deferral.
- **Self-improving loop** (move 1): the learned-patterns store + `session-end.sh` writer + `/cr` grep-enforcer is a closed loop — corrections during a run become enforced rows the next run cannot violate. That is the literal mechanism of a self-improving harness.
- **CI-verified review gate** (move 4): in unattended runs the `.cr-ok` sentinel is the *only* signal that review happened — and today CI ignores it. Making it deterministic is what makes "bug → reviewed PR" trustworthy without a human in the loop.

No direct teaching on Slack/Linear summon as a trigger front-door — but stop-the-line's "surface for human root-cause" is the natural place a Slack/Linear notification hangs off.

## The single biggest move (one paragraph)

**Stop-the-line for unattended runs** (move 3). It is the move the vision synthesis should pick up first because it is the load-bearing safety mechanism the *entire autonomy story* rests on: the new charter makes parallel agent fleets and cloud `/schedule` first-class, and the ground-truth map confirms disk `/cr` has "no UNATTENDED branching" and nothing anywhere halts a *series* of agent PRs on a recurring failure (§3c, §3f). Without it, the more autonomous and parallel the harness becomes, the more catastrophic a single broken assumption is — the fleet doesn't fail once, it fails twenty times across five repos before anyone looks. It is world-class because elite autonomous systems are defined not by how fast they go but by how cleanly they *stop*: a defect-class circuit breaker that halts forward work, writes an enforced learned-patterns row (move 1), and pings a human (the Slack/Linear seam) turns an unattended fleet from a liability multiplier into a trustworthy operator. The conservative synthesis deferred it under the old "defer autonomy" charter; that charter is now reversed, the durability objection is moot, and this is the first thing to build.
