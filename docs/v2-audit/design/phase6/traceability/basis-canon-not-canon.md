# Traceability — "Basis: canon vs not-canon" pass-3 → V2 design

**Source:** `passes/basis-canon-not-canon/pass3-apply.md` §(b) REAL gaps (the core) + the load-bearing
pass-3 conclusions and §(c) caveats that shape adoption.
**Method:** each distinct gap/insight classified APPLIED / CUT / DROPPED against the V2 corpus
(MASTER-FINDINGS, phase3/phase45/phase6 reconciliations, V1-TO-V2-CARRYFORWARD, enforcement-sort,
target-file-tree, distribution, compounding-loop). Every classification grounded by grep, cited inline.

**The article's transferable core:** "context is a production artifact with the same failure economics
as code, so it needs the same lifecycle machinery — ownership, CI validation, drift detection, automated
repair" (pass2). Pass3's discipline: the article *sharpens framing*, it doesn't introduce a new unknown —
its gaps map onto already-cited map rows (§4, §5, §6, §7, §3e). The two load-bearing pass-2/3 refinements
that must travel are (1) canonicality is an **authority claim that decays**, so the fix is a *precedence
rule* + a *maintenance loop*, not a binary label; and (2) the **owner** is the out-of-loop verifier, not
metadata — keep maintenance detection automated, keep repair human-gated.

## (b) REAL DROPPED gaps — the misses

**DROPPED #1 — The precedence rule is applied *once* (human reconciliation), not made *machine-checkable* / standing.**
Pass-3 §(c) bullet 2 is explicit that the resolution our §7 contradictions need is "a *precedence rule*
(the 'later-dated wins' convention) made explicit **and machine-checkable**" — because the article assumes
canon is self-consistent and "§7 proves ours is not." The design carries the *explicit* half (resolve the 9
contradictions during export, later-dated wins — a **one-time** convergence checklist [distribution.md:254;
V1-TO-V2-CARRYFORWARD:55]). It does **not** carry the *standing machine-checkable* half: there is no CI rule
that, going forward, *detects* two canon artifacts making contradicting truth-claims and arbitrates by date.
The drift detector (`scan-context.sh`) catches doc-stale, doc-fiction (phantom refs), and decay
[memory-model §8] — but **a phantom-ref check is not a contradiction-detector**: two pages that each
reference real things while asserting *opposite* truths both pass the existing FICTION/STALE/DECAY passes.
The article's whole §7 point is that *canon-vs-canon contradiction* is a distinct failure class from
staleness, and the one mechanism that would catch it recurring (a standing precedence/contradiction check in
the drift CI) is neither built nor registered. **Where it belongs:** an added assertion class in
`scan-context.sh` (memory-model §8 / R65's drift CI) — "two `kind: decision` or two canon entries asserting
the same `superseded-by:`/topic with conflicting claims → flag, arbitrate by date." **Why it matters:** the
one-time reconciliation clears today's 9 contradictions, but the article's economic-reframe thesis ("a
defect hit thousands of times instead of occasionally") applies precisely to a contradiction that *re-opens*
after convergence — which is the exact way `HARNESS-AS-IS.md` itself rotted (map §0). Without the standing
check, gap #1's fix decays the moment a new contradiction lands, and nothing detects it.
