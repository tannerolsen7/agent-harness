# The V2 Roster — Every Skill / Agent / Command / Hook

> **What this is.** The complete V2 disposition for every harness asset: every skill, every agent, every
> hook, with disposition, an actual-job description grounded in the per-file grounding passes (not the name),
> the failure it prevents, and the frontmatter/delivery change. New additions cite the vision move they serve.
>
> **Charter.** World-class only · autonomy first-class · clarity beats minimalism (more files fine when each
> earns its place) · scale = parallel agent fleets across 5+ repos · KEEP THE RIGOR (every disposition cites a
> ground-truth row, a grounding file:line, or a confirmed absence; a failure mode is named per item;
> doer ≠ checker).
>
> **Ground truth re-verified on disk 2026-06-11.** 26 skill dirs (`dep-update` is an empty stub — no
> `SKILL.md`), 23 agent bodies, 5 Claude hooks (`block-dangerous-git.sh`, `block-npm-install.sh`,
> `permission-logger.sh`, `session-start.sh` near-empty, `worktree-create.sh`). **ABSENT and confirmed:**
> `block-dangerous-bash.sh`, `session-end*.sh`, `enforce-scope.sh`, `/goal`, `/lfg`, `/verify`,
> `/scan-context`, `.claude/rules/`, `.claude-plugin/`, `cr-golden/`. The existing Stop hook plays a SOUND
> only. `.cr-ok` is gitignored — never reaches CI.
>
> **The §9 survivor pass verdict (RECONCILIATION §D):** all 26 skills + 23 agents carry a failure-mode line;
> the only outright CUT is `dep-update/` (empty stub). The "collapse 23 agents → 1" and "lens/spike agents
> are reuse-cuts" reflexes were tested on disk and **rejected** — every lens is spawned by `reviewer.md`,
> every spike agent by `spike-orchestrator.md`; all wired, all distinct failure modes.

## Commands vs skills

Commands are the **legacy** form; skills are the unified form, and the harness is **correctly all-skills**.
There is no `/commands` directory on disk and none should be added — the slash-prefixed names (`/cr`,
`/feature`, `/goal`) are skill invocations, not separate command files. The real lever is **per-skill
invocation control**, not a command/skill split: `disable-model-invocation: true` removes a skill from the
model's context so it can only be summoned by a pinned orchestrator step (F9), and the situational
`description` field controls *when* the model may auto-invoke. The V2 work here is therefore entirely inside
skill frontmatter (the F9 activation-tier audit + the P6 per-skill frontmatter contract), not a new file
class. **No `/commands` dir.**
