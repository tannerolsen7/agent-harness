Shell hooks that block dangerous bash commands, block reads of credentials/secrets, and block unauthorized outbound network calls. All fail closed — if the guard script itself errors, the action is denied.

Phase 1 — Trust
Bug-catch test suite with a real-defect scoreboard
8 seeded real defects (security holes, logic bugs, type errors) that the AI reviewer must catch. A score script measures the catch rate and will gate the upcoming review-consolidation work.
Unforgeable CI pass required before any review
cr-ok.sh records a branch + commit SHA after CI passes. The review skill refuses to run if the token is absent or mismatched — you cannot fake a CI pass. Works with both GitHub and GitLab.
Bug fixed: the old flow consumed the .cr-ok token before running preconditions — so a failed review destroyed the token. Now preconditions run first; a trap restores the token on failure.
4-lens adversarial reviewer wired into /cr
Four independent AI reviewers attack every PR from different angles: abuse (wrong usage), assumptions (what's taken for granted), cascades (what breaks downstream), and composition (conflicts with existing code). All four run in parallel.
Bug fixed by /cr on itself: the reviewer agent was missing the Task tool, so it could not actually spawn the four lens agents. Fixed and added a regression test that verifies the spawn wiring.
Each AI agent now uses the right model for its job
Audit of all 23 agents mapped each role to the appropriate model tier. The two reviewer agents (code review + security review) were promoted to Opus. The doc-update agent was moved to the faster/cheaper Haiku. Guard files are OS-locked so the AI cannot change its own model assignment.
Code review now hard-stops broken approaches and has a 2-attempt ceiling
A new REJECT verdict closes the PR with an exact command when the approach is fundamentally wrong (not just buggy). Fix attempts are capped at 2 — on the third failure, the review hands back to the human with the exact failing test command and stops.
Automatic risk scoring on every change (HIGH / MEDIUM / LOW)
A deterministic script classifies every diff by path and content — no AI judgment needed. When uncertain, it over-classifies to HIGH. Includes 59 test cases; 100% recall on "trap" cases (changes that look trivial but are actually high-risk). Feeds into the bug-catch scoreboard.
Spawn doctrine: documented rules for when to use sub-agents
SOUL.md defines exactly when spawning a sub-agent is justified (independence, parallelism, or scale) and when it isn't. Prevents agent sprawl and keeps work in a single context when that's sufficient.
Git hook blocks direct commits or pushes to main/master/develop
A pre-commit + pre-push hook rejects any direct write to protected branches. Includes a stub-git test harness so the guard itself is tested without touching the real repo. Verified on push.

Phase 2 — The build loop
2
Single /goal entry point
One adaptive command that figures out what to build next based on the state of the repo — replaces the current "run the right skill manually" flow.
3
Required design review before any code is written
Gate: AI must produce a data shape → UX description → UI sketch before a single line of implementation. Prevents building the wrong thing.
4
Design agent (schema + API + frontend in one pass)
One agent designs the full feature slice — database shape, API contract, and frontend — then another agent stress-tests it before implementation starts.
5
Feature doc as the hub for every change
Each feature produces one doc that links its spec, implementation choices, and review verdict together — the "why" stays attached to the "what."
6
Incident response sub-system
Structured triage flow for production incidents: classify → reproduce → fix path, with human always driving the recovery decision.
7
Learning loop + knowledge integrity check
Harness reads its own output after each task to improve context docs. A reference-integrity check catches broken cross-links before they rot.
8
Context slicing (send relevant code, not everything)
Instead of dumping whole files, the harness sends only the slice of code relevant to the task. Keeps the AI focused and reduces noise.
9
Progress narration + end-of-session summary hook
A hook that fires when Claude stops working — emits a plain-language summary of what was done, what's in flight, and the exact command to continue next session.
Phase 3 — Quality systems
10
UI token lint + design-system enforcement
Auto-install a design system if missing. Lint every UI change for token usage — no hardcoded colors or spacing. Gate review on design-system compliance.
11
UX reviewer with accessibility gate
Tiered UX review that runs axe accessibility checks. Distinguishes regressions (must fix) from new friction (flag only). Never fakes human-facing metrics.
12
Security red-team pass for auth-adjacent changes
Scoped adversarial pass that only runs when a diff touches authentication, permissions, or data access — not on every PR.
13
Performance budget with measured warnings
Core Web Vitals targets defined per project. Measured and logged on each build. CI warns when a budget is breached — doesn't silently pass.
14
Mutation testing (verify tests by breaking the code)
Automatically deletes and corrupts implementation code to verify that tests actually fail when they should. Catches tests that pass vacuously.
15
Comments-earned lint + all 6 data states required
Lint blocks comments that describe "what" (the code already says that) — only "why" comments are allowed. Separately: every UI component must handle all 6 states (empty, loading, error, no data, some data, lots of data).

New behavior / UX / architecture tasks must have a linked design doc in TASKS.md before the queue starts working on them. Bug fixes and small changes proceed without one. Without this, the spec-writer agent makes wrong assumptions and blocks overnight — wasted run.
Gate out-of-band deploy steps (deploy-drift gate) Explore
The harness gates code at PR → CI → merge, but manual deploy steps (database migrations, environment variable changes, feature flags) happen after that boundary with no gate. A sibling project's ungated manual migration broke production. Proposed: a deploy-targets manifest + two checks — one deterministic (no creds, can run in CI) and one stateful live-drift check (credentialed, separate job). First slice is the manifest + the free deterministic check.
