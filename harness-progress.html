Phase 2 — Build loop
Design gate: a confirmed design is required before any code is written
A check runs at the start of each feature branch. If no confirmed design doc is linked, the branch is blocked from proceeding to implementation. A follow-up fix corrected an ancestry-check gap where the gate could incorrectly pass.
Design agent: full-slice design in one pass
One agent designs the full feature slice — database shape, API contract, and frontend — in a single pass. A second design-griller agent then stress-tests the design before any implementation begins.
Feature-doc hub: one permanent record per feature
Every feature now produces one doc linking its spec, implementation choices, and review verdict together — the "why" stays attached to the "what." A companion /compound skill captures non-obvious patterns as reusable solution docs for future work.
Incident triage: structured first-response packet
The /incident skill produces a thorough, human-actionable packet: what happened, how to reproduce it, a classification, a proposed fix route, and an ordered checklist. The AI gathers evidence. The human makes every recovery decision.
Learning loop: doc-updater read-back + reference integrity check
After each task, the doc-updater reads back what it wrote to improve context docs over time. A new check-integrity.sh script verifies that cross-references between docs are intact — catches broken links before they rot. 14 tests, wired into CI.
Context slicing: only the relevant code reaches the AI
Instead of sending whole files, the task-runner assembles only the slice of code relevant to the current task. Reduces noise and keeps the AI focused on what matters.
Progress narration hook: plain-language session summary
A session-stop hook fires automatically when Claude stops working. It emits three sections: what was done, what's in flight, and the exact command to continue next session. No setup required — fires on every session end.

Phase 3 — Quality systems
UX reviewer with accessibility gate
The ux-reviewer agent gained a third review pass powered by the axe-core engine. Accessibility regressions — violations that existed before this change — are MUST FIX. Net-new a11y issues are flagged but don't block the PR. Only real axe results appear in the report; no faked scores or estimated percentages.
Design synthesizer: one coherent design system from any sources
The @design-synthesizer agent takes 1–N design sources (refero files, described systems, or your own) and always produces one output: docs/design/DESIGN.md. A single source is normalized and written directly. Multiple sources are compared across 12 axes (color, typography, spacing, motion, etc.) — the agent asks you to resolve only the genuine conflicts, then synthesizes one system. Includes a validate script and test coverage for both paths.
UI token lint and design-system enforcement
Every UI change is linted for hardcoded colors and spacing values — no raw hex, no px values outside a token reference. If a design system is missing, the linter says to run @design-synthesizer first instead of silently passing. Also bakes in 13 absolute bans from impeccable (gradient text, glassmorphism, identical card grids, etc.) as static checks. Wired into /cr and the pre-commit hook.
Performance budget with measured warnings
Core Web Vitals targets (LCP, CLS, FID) are defined per project in a config file. scripts/perf-budget.sh measures and logs them on each build. CI warns — but does not block — when a budget is breached. A breached budget never silently passes.
Mutation testing: verify tests by breaking the code
scripts/mutation-test.sh deletes and corrupts implementation code to confirm that tests actually fail when the code is wrong. Catches tests that pass vacuously regardless of the implementation. Uses a loop-until-dry pattern: keeps running until 2 consecutive rounds find no new survivors, guaranteeing saturation rather than a single random sample.
Comment lint + all 6 data states required
Two lint rules shipped together. (1) Comment lint: blocks "what" comments — the code already says what it does; only "why" comments (hidden constraints, workarounds, non-obvious invariants) are allowed. (2) Data state lint: every UI component must handle all 6 states: empty, loading, error, no data, some data, and lots of data. Both run as pre-commit hooks.
