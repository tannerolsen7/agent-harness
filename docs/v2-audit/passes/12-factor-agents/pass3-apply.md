## (a) What we ALREADY do

This is real: `block-dangerous-git.sh` / `block-npm-install.sh` are `exit 2` PreToolUse guards [§3e], `.husky/pre-commit` + pre-push are blocking git hooks [§3e], and `pr.sh`/`gc.sh`/`worktree-add.sh` are deterministic scripts [§3f]. The decision/execution split the article prizes (F1, F8) is structurally present: the model proposes, the hook disposes. The article's own Pass-3 claim "skills are the tool schema; the agent decides, the hook executes" is **correct** and maps to [§3e].
- **Own our prompts as files (F2).** SOUL.md, CONTEXT.md, AGENTS.md, CLAUDE.md, agent-contract.md, AI-WORKFLOW.md all exist on disk as version-controlled context [§3a]. The article's claim that F2 ↔ "SOUL.md, skills as owned prompt templates" is **correct** [§3a].
- **Human-in-the-loop as a workflow gate, not a special interrupt (F7), and pause/resume (F6).** We have the `.cr-ok` sentinel chain, the pre-push human-confirm prompt, and NEEDS-HUMAN tiering in `/cr` [§3c, §3e]. The AFK/worktree model and human-checkpoint gates the article's Pass-3 cites do exist in substance. Pause/resume across sessions is real via per-worktree state and the sentinel `branch:sha` handoff [§3e/§3f].
- **Small, focused specialists exist (F10, partially).** Disk has **23 agents** including the 4 review lenses, hotfix-guard, refactor-extractor, solution-evaluator, incident-responder, 6 spike agents [§3d]. The *roster* embodies F10 even if the *discipline* isn't codified (see gaps).
- **Context engineering is already the organizing problem (F3).** The entire memory model — `memory.md`, `RECURRING-FINDINGS.md`, `PITFALLS.md`, `docs/solutions/`, `docs/adr/`, plus auto-memory — is context-window engineering [§4]. The canon/not-canon and live-doc/stale-spec distinctions the article maps to F3 are already named problems in our map [§3a "AGENTS.md None-open contradiction"; §4 "stale authority"].

## (b) REAL gaps this article exposes (each cited)

- **F3 / authority-within-context — the harness has no machine-enforced doc-authority level.** Pass-2 isolated the article's blind spot (flat context window) and inverted it into our gap: our context bag mixes authority levels with *no tooling to separate them*. Ground truth confirms the pollution: the project audit artifact itself rots — `HARNESS-AS-IS.md` carries stale absence-claims and "any 'ABSENT' claim sourced to it must be re-verified" [§0 Correction log]; `AGENTS.md` has a "None open" contradiction [§3a]; PITFALLS/memory are assigned to *both* Layer 1 and Layer 3 depending on the page and read-time is specified for only ~5 of ~14 knowledge files [§4 "admitted ambiguities"]. F3 says context ordering/authority *is* the product; our map says authority is undefined for most of the context corpus. **Real gap.**
- **F5 / unify execution + business state — confirmed absent enforcement, broader than the article's example.** The article's Pass-3 names "the `updateProposal` enforcement gap" as a F5 violation; I cannot cite that to a ground-truth row (it is not in this map — see (c)). But F5 *does* land on a real, cited gap: our map prescribes that status transitions needing a server-side timestamp or atomic audit write MUST use Postgres triggers, and the canon's whole memory model is "execution state" that the map says is **not unified** — the same corrected-mistake fact lives simultaneously in `memory.md` + `PITFALLS.md` + auto-memory `feedback_*`, a triple-duplication the canon "both sanctions and forbids," reconciled "only in prose, encoded in no tooling" [§4]. That is precisely F5's "two (here: three) state systems you spend your life keeping in sync." The auto-memory store (MEMORY.md + 51 siblings) is "a sixth store the canon's model doesn't account for" [§4, §6] — a literal second state system outside the canonical one. **Real gap, and the strongest factor-to-row mapping in the article.**
- **F9 / errors-into-context — confirmed-absent convention.** The article's Pass-3 proposes this as a *new* gap; ground truth supports the absence: there is no error-handling-strategy hook, skill rule, or PITFALLS entry anywhere in the component inventory [§3e lists every hook; none handle tool-error compaction], and the memory/PITFALLS model [§4] captures *human-corrected mistakes*, not *runtime tool failures fed back to the agent*. Pass-2's caveat sharpens this into a *better-scoped* gap than the article states: the convention we lack is not "errors→context" (naive) but **"errors→context + a deterministic max-retry/circuit-breaker in a hook"** — because F8 says the give-up decision is control flow, and our control flow lives in hooks [§3e]. **Real gap; needs the F8-aware framing, not the article's raw F9.**
- **F10 / one-agent-one-job discipline — uncodified.** We have the *roster* (23 agents [§3d]) but the map shows canon's agent taxonomy is itself inconsistent ("8 specialist agents" header over a 9-row table; "Ten" templates over 8 roles [§3d, §7.6]) and there is **no scope-limiting design rule** anywhere in SOUL/AGENTS/CLAUDE per the §3a inventory. The article's proposed rule ("an agent's job description fits in one sentence") has no home in our docs today. **Real gap** — and it intersects the §9 Model Capacity Audit, which is *about* removing scaffolds the model no longer needs; F10 discipline is one of the few that is reasoning-discipline (keep), not capability-proxy (cut).
- **F11 / trigger-from-anywhere — confirmed structural absence.** Ground truth: "The harness has **never been installed anywhere but event-vendor**" [§8], the global layer has "**no** global agents, hooks, commands" [§2], and the only trigger surfaces are Claude Code sessions + git hooks [§3e/§3f] + CI [§3f]. No webhook/cron/email/Slack path exists in the entire inventory. The canon backlog itself lists "GitHub Publishing — in progress; next gate: 3 real installs" and "apply engineering system to Recyclops" as **unmet** [§8]. The article reframes this as a F12-enabled "plumbing problem"; our map says it's blocked on a deeper fact — there is no *installable shared harness* to trigger [§0 "the central structural fact of V2"], so F11 for us is downstream of the global-install gap, not a standalone plumbing task. **Real gap, correctly re-scoped.**

## (c) Weaknesses / blind-spots in the article's OWN reasoning

- **F12 oversold as a property (pass-2).** "The agent is a stateless reducer / test it like a function" is true of the *step*, not the *agent*; the model isn't deterministic given identical context, and the agent accretes state across iterations. Useful discipline, false-as-stated invariant.
- **Single-loop assumption breaks F10/F11 (pass-2).** The clean reducer model holds only for one loop/one process; hand-offs (F10) and multi-surface triggers (F11) need a stateful orchestrator the article hand-waves as "plumbing." For us that orchestrator is the *actual* hard part (worktrees, `/queue`, parallel sessions) — the easy-for-the-article part is the hard-for-us part.
- **F9 vs F8 latent conflict (pass-2).** "Errors are just context" (F9) collides with "keep control flow in code" (F8): retry/give-up is control flow. The article never reconciles them; a naive F9 invites unbounded retry loops with no circuit breaker.
- **"Frameworks are evil" contradicts its own pragmatic quote (pass-2).** F8's absolutism vs. "take small modular concepts into your existing product." It never draws the line between must-own and safe-to-borrow — and read literally it condemns the very vendor harness (Claude Code) we and most readers operate inside.
- **"Model choice is a rounding error" collides with capability-driven scaffold retirement (pass-2).** Directly contradicts our §9 Model Capacity Audit premise that a model upgrade (Sonnet 4.6 → Opus 4.8) *retires* context-engineering scaffolds. The article assumes context-engineering investment compounds; under fast capability gains it can depreciate into overhead — the article cannot see this because it treats the model as a fixed substrate.
- **The page's own Pass-3 contains at least one unverifiable/likely-stale claim.** It asserts "the `updateProposal` enforcement gap in event-vendor is exactly a F5 violation," but no such row exists in CANONICAL-HARNESS-AS-IS (the map's status-transition rule is about Postgres triggers, not an `updateProposal` gap). This is a *product*-layer claim smuggled into a *harness* audit; it should not be cited as a harness gap without independent verification. (It may be true at the app layer — but this map is the harness ground truth, and it isn't here.)
- **Snapshot is `canonical: false` and frozen 2026-05-28.** The page itself routes gap updates "to Research Delta only" — so its Pass-3 self-claims are explicitly non-authoritative and must be re-grounded, which is exactly what this pass does.

## (d) Does it warrant fresh external research?

**Mostly no — synthesize, don't re-research.** The 12 factors are a known, stable framing and our map already contains the rows each one lands on; the work is *mapping and decision*, not discovery. Two narrow exceptions where a short external look would pay off:

1. **F9 done right (errors-into-context + circuit-breaker) under a vendor harness.** Our open question (pass-2/F9) is how to compact tool errors into context *and* enforce a deterministic max-retry when we don't own the loop — i.e., what can a Claude Code hook actually intercept on a failed tool call? This is a *Claude Code capability* question, not a 12-factor question; worth a focused check of the harness's PreToolUse/PostToolUse hook surface (load the `claude-api` / harness hook docs), not a literature review.
2. **F11 trigger-from-anywhere on top of an un-installed harness.** Tractable only after the global-install gap [§8] is closed; research here should be *deferred* until V2 has a shared installable harness, then look at webhook/cron entry points. Premature now.

Everything else (F1–F8, F10, F12) is adequately covered by this map plus the existing research corpus the page cross-links (Basis, Stripe, Ramp, Linear, Harness). The article's value to us is as a **coherent vocabulary** that names five already-present-in-the-map gaps (F3 authority, F5 state unification, F9 error convention, F10 scope discipline, F11 triggers) — not as a source of new external facts.
