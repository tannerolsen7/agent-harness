# Ambition Re-mine — Harness Engineering & Agent-Ready Repos (Deep Survey)

## What this source is (plain English, 2-3 sentences)

A frozen May-2026 Notion survey that named "harness engineering" as a discipline and synthesized ~30 sources (Hashimoto, Stripe Minions, OpenAI/Lopopolo, ETH Zurich, ECC, Nimbalyst, AgentLint, Böckeler) into a single doctrine: **"the model is a commodity, the harness is the moat."** It catalogs what world-class agent-ops teams actually build — deterministic hooks, isolated devboxes, a portable cross-project harness, a self-improving instinct loop, a "sensors" measurement layer, and bounded-retry stopping conditions — then grades "our system" against them. The conservative pass3 then ground-truthed half its gap claims stale and shrank the rest to a handful of wiring tweaks.

This source is the *spine* of the whole v2-audit corpus — it supplies the vocabulary (guides/sensors, the Hashimoto ratchet, harness-as-moat) that every other source's pass3 leans on. Re-mining it under the new charter is high-leverage: its biggest moves were precisely the ones the conservative synthesis deferred or scaled-to-solo.

## The full-ambition moves this source teaches

### Move: The Hashimoto ratchet as enforced machinery, not a note

- **Plain-English what & why:** Mitchell Hashimoto's definition of harness engineering is mechanical, not aspirational: *"anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again."* The failure it prevents is mistake-recurrence — an agent that re-commits the same error every session because the correction lived in a chat reply, a memory note, or an advisory CLAUDE.md line the next agent may or may not read. Ghostty's AGENTS.md is offered as the canonical artifact: every line traces to a past agent failure that is now *structurally* prevented. The world-class team's bar is that a corrected mistake becomes an *enforced rule* (a hook that blocks the act), not a *recorded rule* (a sentence the agent must choose to honor).
- **The mechanism:** A "ratchet" pipeline that closes the loop from observed-mistake to deterministic-enforcement. Concretely in our harness: when `/compound` or a post-mortem identifies a recurring mistake, it must classify it — *can this be a deterministic block (PreToolUse/PreCommit hook), or is it inherently advisory?* If a block is possible, the ratchet generates the hook (or extends `block-dangerous-bash.sh` / a new guard) in the same flow, not a CLAUDE.md bullet. Pass2-F1 nails it: this is "testable against any harness: does a corrected mistake become an enforced rule, or just a note?" Right now our answer is "just a note" — the map shows the system is "overwhelmingly advisory" [map §3e net picture] and every memory store (`.claude/memory.md`, `PITFALLS.md`, auto-memory `feedback_*`) is a *note*, not a *gate*.
- **Citation:** Confirmed absence — map §3e "Both agree the system is overwhelmingly advisory — neither has a deterministic backstop for the bulk of skill bodies, CLAUDE.md rules, or the autoMode lists." No row anywhere in §3–§9 records a mistake→enforcement pipeline. The closest existing mechanism is the manual memory-write rule in CLAUDE.md, which produces notes.
- **Conservative disposition:** pass2-F1 honored the *idea* ("the survey's most durable idea") but pass3 demoted it to vocabulary — section (d) concludes the article's "value is as a cross-check and vocabulary source… not as a research target." MASTER-FINDINGS kept the ratchet as a *framing* and never made it a build item. The ratchet became a way to *talk about* gaps, not a gap to *close*.
- **RE-JUDGMENT under the new charter: ELEVATE.** This is the source's single most under-built idea and it goes from "vocabulary" to a first-class harness primitive. The conservative read treated "is it a note or a rule?" as a diagnostic question; the world-class read treats it as a *build target*: a ratchet skill (`/ratchet` or a `/compound` sub-phase) that, on each recurring mistake, attempts deterministic enforcement and only falls back to a note when a block is genuinely impossible. Under autonomy-is-first-class, this is load-bearing — an unattended bug→PR loop that can re-commit the same mistake forever is worthless; the ratchet is *how* a self-improving fleet actually improves. The conservative bias was treating "advisory is what we have" as the ceiling rather than the gap. How much bigger: from a zero-line "framing" to a committed skill + the hook-generation path that makes self-improvement mechanical.

### Move: Sensors layer — the harness can instruct but cannot measure

- **Plain-English what & why:** Böckeler's guides-vs-sensors taxonomy splits harness mechanisms into *feedforward* (guides: system prompts, AGENTS.md, rules that tell the agent what to do before it acts) and *feedback* (sensors: evals, validation loops, drift detectors that measure whether the instruction actually worked). Pass2-F3 sharpens the real payload: **almost every harness is all guides, no sensors** — it can instruct but cannot tell whether the instruction is landing. The failure it prevents is silent quality drift: you keep adding rules, but nothing measures whether agents are getting *better or worse*, so you fly blind and only discover regressions when a human notices a bad PR.
- **The mechanism:** A measurement store + a small set of sensor signals wired into the pipeline. Concretely: 3–5 falsifiable signals captured per run — e.g. `/cr` MUST-FIX count per PR over time, CI-retry-rounds-to-green, percentage of commits that trip a guard hook, rate of memory entries flagged redundant by `/compound`. Stored in one append-only place (a `docs/sensors/` ledger or a structured log), surfaced when a signal crosses a threshold. This is distinct from the deterministic floor (pass2-B): the floor *blocks bad acts*, sensors *detect quality drift*. We have a rich floor and ~zero sensors.
- **Citation:** Confirmed absence — map §3e net picture (no deterministic measurement); pass3 (b)3 "No sensors / measurement loop — CONFIRMED ABSENT… There is no eval/drift/quality-scoring store anywhere in §3–§9."
- **Conservative disposition:** pass3 (b)3 confirmed it as a real gap but framed it minimally ("the survey's sharpest surviving diagnostic"), and the wider synthesis left the *prescription* ("build an eval framework") flagged as the "weaker" half (pass2-F3). It survived as a named gap but with no scoped build and an implicit "eval frameworks are heavy" hesitation.
- **RE-JUDGMENT under the new charter: ELEVATE.** Sensors are *the* prerequisite for autonomy, and the new charter makes autonomy first-class. A self-improving loop with no sensors cannot know if it is improving — it is a thermostat with no thermometer. At fleet scale (parallel agents across 5+ repos), the human cannot eyeball quality on every run; sensors are the only way drift becomes visible before it ships. The conservative hesitation ("eval framework = heavy") is exactly the scaled-to-solo bias the charter retires: a world-class fleet operator *needs* the dashboard. Bigger by: moving from "named diagnostic" to an in-scope-now build of a sensor ledger + threshold alerts, and explicitly feeding sensor signals into the ratchet (a rising MUST-FIX count *is* the mistake-signal that triggers a new guard).

### Move: The portable harness — it must be able to leave the repo it was born in

- **Plain-English what & why:** Saul Fernandez's three-repo architecture (agent-library = the brain, agent-setup = symlink deployer, resource-catalog = inventory) encodes one principle, stripped of enterprise packaging (pass2-G): **the harness must be a versioned, deployable artifact that can install into any repo and rebuild from a clone in minutes.** The failure it prevents: the harness ossifies into a single project, every other repo starts from zero, and improvements never compound across projects. Stripe's deeper lesson (pass1 Part 2 source 5) is the same in disguise — the infrastructure existed *before* LLMs and was *shared*, which is what made 1,000 PRs/week possible.
- **The mechanism:** Extract the project-agnostic harness (skills, agents, hooks, the ratchet, the sensor ledger schema) into a distributable **plugin + marketplace**, with a thin `/init` template laying down per-repo files. Per the resolved facts: a plugin is the portable mechanism (it physically can't carry permissions, so permissions stay in the per-repo `/init` template). GitHub becomes the single source of truth. The principle pass2-G isolates — "one editable source, deployed outward, version-controlled, rebuildable from clone" — is exactly the plugin+marketplace+thin-template shape the new charter names.
- **Citation:** Confirmed absence — map §0 "the harness the canon describes as 'global / multi-project' is, on disk, a single-project artifact… There is no installable, shared, version-controlled harness"; map §8 "The harness has never been installed anywhere but event-vendor. 'Multi-project' is a goal, not a state." Confirmed by the canon backlog's own unmet gate: "GitHub Publishing — in progress… next gate: 3 real installs."
- **Conservative disposition:** pass3 (b)4 called this "the central structural fact" and "the single most important real gap" — but immediately applied the pass2-G de-scope: "take the *principle*… not the three-repo packaging." The conservative move was *de-risking by shrinking*: keep the goal, drop the machinery (no per-tool adapters, no Backstage catalog, no second source of truth).
- **RE-JUDGMENT under the new charter: ELEVATE (partial UPHELD-CUT on the over-specified packaging).** The *gap* elevates to the #1 structural workstream — it already is the canon's central V2 driver, and under "world-class fleet across 5+ repos" portability is non-negotiable, not a someday. The pass2-G caution against the *three separate repos + per-tool adapters + Backstage catalog* still holds and is a legitimate UPHELD-CUT: those are genuinely a large-org shape, and each adapter folder is a second source of truth that drifts (pass2-D). The plugin+marketplace+thin-`/init`-template path achieves the *principle* (deploy outward, rebuild from clone) without the *packaging* failure mode. So: ELEVATE the portability mandate to in-scope-now (resolved facts already commit us to it), UPHELD-CUT only the specific three-repo/adapter mechanism, with the named failure mode being manifest-drift across N adapter folders. This is not the conservative "shrink to principle" dodge — it is keeping the full ambition (a real distributable harness) while cutting one packaging variant that has a concrete failure mode.

### Move: Bounded-retry stopping condition — "max 2 CI rounds, then human"

- **Plain-English what & why:** Stripe Minions defines a concrete, falsifiable stopping rule: an unattended agent gets at most 2 CI retry rounds to fix a failing build, then it hands back to a human (pass1 Part 2 source 5; pass2-F2). The failure it prevents: an autonomous agent burning tokens and time in an infinite fix-fail-fix loop on a problem it can't solve, with no escape hatch — the classic unattended-run death spiral. It is the cheapest possible autonomy primitive and most harnesses have *no* defined stopping condition at all.
- **The mechanism:** A bounded-retry + handoff primitive wired into `/cr`, the feature loop, and any unattended/cloud-scheduled run. Concretely: `/cr` (and the future bug→PR loop) gets a REJECT/UNATTENDED tier — after N failed auto-fix or CI rounds it stops, writes a structured handoff (what it tried, why it's stuck, the failing signal), and either summons a human (Slack/Linear) or marks the PR as needs-human. This pairs with the sensor signal "CI-retry-rounds-to-green."
- **Citation:** Confirmed absence — pass3 (b)2 "No defined stopping condition for retries — CONFIRMED ABSENT. The map records `/cr` has 'no REJECT tier, no UNATTENDED branching… no Pass 10' and CI 'never verifies `.cr-ok`'" [map §3c; §3f].
- **Conservative disposition:** pass3 (b)2 confirmed it as "a real missing primitive for AFK runs" and called it "cheap" — but left it as one of five flat "real gaps," with the AFK/unattended context treated as a someday scenario rather than a now-goal. The conservative synthesis deferred the autonomous front-door, so the stopping condition had nothing to attach to and stayed a line item.
- **RE-JUDGMENT under the new charter: ELEVATE.** Under autonomy-is-first-class with cloud `/schedule` confirmed to exist, this is no longer an AFK-someday nicety — it is a *required* component of every unattended loop shipping now. The conservative framing ("cheap real gap") undersells it: a bug→PR loop or a scheduled cloud agent *without* a bounded-retry stop is a token-bonfire and a safety hazard. It elevates from a flat line item to a designed-in primitive of the autonomy front-door, tightly coupled to the summon mechanism (the handoff target is Slack/Linear). Bigger by: from "add a stop count" to a full REJECT/UNATTENDED tier in `/cr` + structured-handoff + human-summon, built alongside the bug→PR loop rather than after it.

### Move: Self-improving instinct loop (ECC Hermes / Instincts)

- **Plain-English what & why:** ECC's "Instincts" are patterns *auto-generated from git history* and applied continuously, and "Hermes" is its self-improving loop (pass1 Part 2 source 2). The world-class idea: the harness mines its own history (commits, corrected diffs, review findings) to *derive* behavioral patterns automatically, rather than waiting for a human to hand-write every rule. The failure it prevents: the harness only learns when a human notices a pattern and manually writes it down — a bottleneck that caps the rate of compounding at human attention.
- **The mechanism:** A derive-from-history pass that mines git log + `/cr` findings + auto-memory for recurring patterns and proposes them as candidate guides or guards. Critically, per pass2-D, the output must be *derived* (regenerated from source at read time) not *maintained* (a hand-kept manifest that drifts). This is the auto-capture upgrade to our memory layer — the map already shows a partial seed: the auto-memory store (`MEMORY.md` + 51 siblings) is "written by the Claude Code subsystem, not any skill" [map §4], so the substrate exists; what's missing is the *derivation-into-enforcement* loop.
- **Citation:** Partial-presence + confirmed gap — map §4/§6 (auto-memory is a real disk-only 6th store, written automatically); pass3 (a)3 "the ECC-Hermes 'auto-captured session history' the article envies partially exists." The *loop* that turns that history into instincts/guards is the absent half — no row in §3–§9 records a derive-from-history pipeline.
- **Conservative disposition:** pass3 (a)3 used the auto-memory store to *defuse* the gap — "partly FALSE… partially exists" — treating the envy as half-satisfied and moving on. MASTER-FINDINGS folded this into "we already have auto-memory" and did not pursue the loop. The conservative move was: presence of the *store* discharged the obligation to build the *loop*.
- **RE-JUDGMENT under the new charter: ELEVATE.** "We have the raw store" is not "we have the world-class version" — exactly the §E existence-bar failure the charter targets. We have the thermometer's mercury but no thermostat. The world-class move is the *loop*: mine the auto-memory + git history, derive candidate patterns, and route them through the ratchet (Move 1) into either a guide or a deterministic guard. This is the engine of self-improvement and the new charter makes self-improving loops first-class. The pass2-D caution (prefer derived over maintained) is the *correct constraint on how to build it*, not a reason to skip it. Bigger by: from "auto-memory exists, gap discharged" to a committed derive→propose→ratchet loop — the literal Hermes the article holds up as north star, which the conservative read waved off.

### Move: Subtraction as a first-class tier (the ETH result the additive plan ignores)

- **Plain-English what & why:** The single result the survey elevates to "most important" is ETH Zurich's finding that *comprehensive, auto-generated, or already-inferable context **degrades** agent performance* (−3% avg across 5/8 settings) and *raises* inference cost 20–23%; LangChain's "max reasoning budget scored worse" echoes it. The failure it prevents: bloating CLAUDE.md/skills with rules the model already knows, which makes agents *slower and worse*, not safer. Pass2-A's sharpest finding is that the survey advances two theses that fight — "add structure" (the whole action map) vs "remove instruction" (ETH) — and never reconciles them; subtraction is left as one MEDIUM line item where it should be a *tier*.
- **The mechanism:** A standing subtraction discipline wired into the audit cadence — a recurring pass that scores CLAUDE.md/skill bodies against "does the current model already know this?" and removes capability-proxy scaffolding. The map already pre-authorizes this: Page 13's Model Capacity Audit gives a 14-row keep/replace table, distinguishes reasoning-discipline (keep) from capability-proxies (remove), and is explicitly *due for re-audit on a model update* — we are now on Opus 4.8, the judgments were made against Sonnet 4.6 [map §9].
- **Citation:** Confirmed pre-authorization + confirmed neglect — map §9 (the Model Capacity Audit and its golden rule "if you can't name a failure mode the constraint prevents, the constraint is overhead"); pass3 (c)1 "Our map *already authorizes* the subtraction the article underweights… The article never reaches this conclusion its own evidence demands."
- **Conservative disposition:** pass3 (c)1 correctly identified the unreconciled contradiction and noted the map authorizes subtraction — but filed it under "weaknesses in the article's own reasoning," i.e. as a *critique of the source*, not a *build move for us*. It diagnosed the article's blind spot without committing us to run the very audit it points at.
- **RE-JUDGMENT under the new charter: ELEVATE (this is the one move the charter's own "clarity beats minimalism" must be careful with).** Subtraction elevates to an in-scope-now workstream: run the Page-13 re-audit against Opus 4.8 and cut capability proxies. This is *not* in tension with "more files is fine when each earns its place" — the charter says reject ideas only when they *don't* earn their place; the Page-13 proxies (structural option-count forcing, phrase-keyed triggers, anti-rationalization tables) are precisely the ones that *stopped* earning their place when the model got stronger. The conservative bias was treating this as the source's flaw rather than our overdue task. Bigger by: from "noted critique" to a committed Opus-4.8 capacity re-audit using the existing 14-row table as the work list, paired with the golden-rule test on every surviving constraint.

## Autonomy angle

This source teaches a surprising amount about autonomy, mostly buried by pass3's "defer the front-door" posture:

- **Bounded-retry / handoff (Stripe "max 2 CI rounds then human")** is a *direct* autonomy primitive — the stopping condition + human-summon every unattended bug→PR loop needs. Under the new charter it is required infrastructure for cloud `/schedule` runs, not an AFK someday (Move 4).
- **The self-improving loop (ECC Hermes/Instincts)** is literally a self-improving-loop exhibit — mine history, derive patterns, apply continuously. Combined with the ratchet (Move 1), it is the "bug→reviewed-PR→permanent-fix" cycle the charter wants designed-in (Move 5).
- **Stripe's isolated devboxes** (pre-warmed, QA-isolated, no prod data/network, 10-second spin-up) are the execution-isolation model for safe unattended runs — and the map shows we already have a real seed of this (the `worktree-create.sh` Tier-0 prod-key firewall, pass3 (a)2), so the autonomy-safe execution environment is *partly built*, not absent.
- **Sensors** are the measurement substrate without which a self-improving loop is blind (Move 2).

Nothing in this source addresses Slack/Linear summon *transport* specifically — but the *handoff target* it implies (bounded-retry → human) is exactly where a Slack/Linear summon plugs in.

## The single biggest move (one paragraph)

**The Hashimoto ratchet built as enforced machinery (Move 1)** — closing the loop from observed-mistake to deterministic-enforcement, not from observed-mistake to advisory-note. It is the biggest because it is the *mechanism of compounding itself*: it converts the entire "overwhelmingly advisory" harness the map describes [map §3e] into one that gets structurally harder to break with every mistake it sees, and it is the connective tissue between the other four moves — sensors (Move 2) supply the mistake-signal, the self-improving loop (Move 5) supplies the derived candidate pattern, the ratchet decides block-vs-note, and the portable harness (Move 3) carries those earned blocks to every other repo so the whole fleet inherits each fix once. The conservative synthesis reduced Hashimoto's own definition — "engineer a solution such that the agent never makes that mistake again" — to a vocabulary word for *talking about* gaps; the world-class move is to make it the engine that *closes* them. Under autonomy-is-first-class, a fleet that cannot ratchet its own mistakes into permanent enforcement is a fleet that re-breaks the same things forever; the ratchet is what makes self-improvement real rather than rhetorical.
