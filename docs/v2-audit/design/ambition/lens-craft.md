# Lens: Craft — World-Class Review, Verification, Spec & Testing + the Compounding Engine

> Pillar scope: the quality stack the autonomous loop *passes through* and the self-improving engine that makes it smarter every cycle. Review (`/cr`, `/cr-security`, the 4 lenses), verification (`/verify`, the evidence bundle), the per-feature spec layer, money-math property testing, the §9 deletion engine, and the compounding loop (memory read-back, finding→enforcement, scan-context drift, effectiveness sensors).
>
> Companion pillars own the things this one *feeds into*: the trigger front-door, `/goal`, the cloud heartbeat, egress/credential firewalls, MCP-trifecta gate, distribution. This file cites them where they interlock but does not re-specify them.

---

## The pillar in one paragraph (plain English, no jargon)

When agents write most of the code, the bottleneck is no longer writing — it is *checking*. The harness already has a deep reviewer (`/cr`: 9 analytical passes plus a 4-lens adversarial pass), real tests, and a learning-capture ritual (`/compound`). The problem is that almost none of it is *trustworthy when a human stops watching*. The review verdict dies in a `.cr-ok` file that is gitignored and never reaches CI, so a cloud agent that clones the repo can't even read whether review happened. The adversarial reviewer shares the coder's own context, so it inherits the coder's blind spots instead of attacking the work fresh. There is no way to *refuse* a wrong-but-polished PR — only to fix or escalate it. Nobody has ever measured whether the reviewer catches 1-in-5 bugs or 4-in-5. The locked decisions (ADRs, Rejected Patterns, PITFALLS) that make our reviewer better than any SaaS tool are sitting unused as review input. The product's money math — where a wrong total is a $30k-client disaster — has only example tests the model can quietly weaken. And the learning loop is write-only: findings get counted into a file no implementer ever reads, never converted into a rule that *blocks* the next occurrence, and never pruned when they stop happening. World-class Craft means: the verdict becomes a queryable GitHub artifact behind a hard CI gate; the reviewer attacks from isolated solution-context but full project-canon; a REJECT tier kills wrong work and re-queues it; the reviewer is calibrated against a labeled defect set on every model bump; behavior is verified by a runnable spec and a CI-resident render/evidence bundle, not by a "review ran" token; the money math is pinned by human-authored invariants the model cannot argue with; and the compounding loop closes — findings read back into the implementer's starting context, recurring findings ratchet into deterministic guards, drift is detected in both directions on a schedule, and decay prunes what stopped mattering.

### STRAND A — Review as an enforced, visible, independent, calibrated artifact

#### A1. Review verdict as a first-class GitHub artifact + hard CI gate — **P0**

- **What + why.** `/cr` does the deepest review in the corpus, but its only durable output is `.cr-ok` — a gitignored `branch:sha` sentinel consumed by the local pre-push hook and never seen by CI or the PR. Depth on an invisible surface is worthless to a fleet: a Slack/Linear-summoned or cloud-`/schedule` agent that clones the repo has no `.cr-ok` and no laptop to honor it, so an autonomous merge cannot even assert review happened. **Failure prevented:** an autonomous loop merging on an unverifiable, forgeable "review passed" token — the only thing standing between "the model agreed with itself" and "shipped to `main`."
- **Mechanism.** Two coupled changes. (1) `/cr` writes its full verdict (MUST-FIX-resolved, NEEDS-HUMAN, SUGGESTION, REJECT, RECURRING-FINDINGS delta, lens findings) to a structured file that `scripts/pr.sh` posts as the PR body or a sticky PR comment. (2) A CI job (`verify-cr-ok.yml` or a step in `ci.yml`) parses the sentinel's `branch:sha` and **fails the check unless the sentinel SHA equals head SHA AND all required checks are green on that SHA**; branch protection on `main` makes it a required check. The `.cr-ok` sentinel survives as the *readiness signal*; the GitHub artifact + CI gate become the *enforceable boundary*.
- **Citation.** Ground-truth §3f / Node 8.5(c): "CI never verifies `.cr-ok`… gitignored, never reaches CI." Elevated by `coderabbit.md` Move 1, `recursive-self-improvement.md` Move 1, `playwright-mcp-debug.md` Move 1. Kill-list E item 1 + item 2 (WEAK-VERSION-UPGRADE: "the terminal stop authority is forgeable").
- **Tag.** P0 — the keystone of the entire autonomy safety floor; co-sequenced with `/goal` (companion pillar). Everything else in Strand A bolts onto this surface.

#### A2. True adversarial independence — fresh sub-agent, isolated solution context, shared project canon, iterative loop — **P0**

- **What + why.** The strongest *quantified* mechanism in the corpus: Google Gemini CLI #26397 lifted merge-readiness 43%→91% via cross-context adversarial iteration (A writes, B hunts, A fixes, B retests, 3-4 rounds) *before any human looked*. Our 4 lenses run inside the same `/cr` invocation over the same branch diff, sharing the coding session's context — structurally incapable of that independence. But pure "no shared context" would blind the reviewer to our Rejected Patterns and ADRs, which is exactly what makes `/cr` good. **Failure prevented:** the reviewer inherits the coder's rationalizations and polishes a confidently-wrong solution instead of attacking it; *and* the opposite failure — a canon-blind reviewer re-litigating settled decisions and missing tenant/RLS rules that live in `src/data/`, not the diff.
- **Mechanism.** Provision the adversarial pass (`@reviewer` → 4 lens sub-agents) with a **clean solution context** — it does NOT see the coding session's reasoning, the author's justifications, or the edit chain — but **WITH** read access to project canon (CLAUDE.md, AGENTS.md, Rejected Patterns, PITFALLS, ADRs). Task framing inverted: "find what breaks this," not "review this." Run it as the documented 3-4 round hunt→fix→retest loop, bounded by a convergence/iteration cap, gating PR-open. This is a context-isolation change, not a different-model architecture change — cheap.
- **Citation.** Ground-truth §3c (adversarial pass "as part of the same `/cr` invocation over the full branch diff"); §3d (4 lens agents exist on disk). Elevated by `code-review-latentspace.md` Move 2. Kill-list F item 5 KILL-UPHELD ("no shared context" stays dead) + the correct design elevated; F item 9 OVERTURNED slice.
- **Tag.** P0 — the largest evidenced pre-human quality jump; the default inner loop of autonomous runs.

#### A3. REJECT tier + bounded-retry / UNATTENDED branching — **P0**

- **What + why.** `/cr` today has three exits — MUST FIX (auto-fix), NEEDS HUMAN, SUGGESTION — all assuming the PR is worth finishing. There is no exit that says "wrong approach — close it and re-spec." **Failure prevented:** an overnight `/queue` run ships five polished, all-green PRs that solve the *wrong problem*, touch out-of-scope files, or balloon past the reviewable-diff cliff — invisible to a diff read cold, straight to a tired human at 9 AM instead of auto-close-and-re-queue. Plus the death-spiral: an agent burning tokens in an infinite fix-fail-fix loop with no escape hatch.
- **Mechanism.** Add a deterministic `REJECT` classification with triggers: (1) scope explosion (files outside spec scope); (2) diff exceeds a hard ceiling (default 800 lines, tunable); (3) CI failing with no auto-fix path; (4) auth/schema/payment change with zero/negative test delta; (5) diff demonstrably solves a different problem than the spec states. REJECT auto-closes the PR and re-queues with a reason note — it does NOT escalate to a human. Bound it: REJECT→re-spec→REJECT twice = escalate to human (Slack/Linear), never infinite-loop. Stripe's "max 2 CI rounds then human" is the canonical bounded-retry shape; pair with the `CI-retry-rounds-to-green` sensor (D5).
- **Citation.** Confirmed absence — ground-truth §3c: "No REJECT tier, no UNATTENDED branching." Elevated by `code-review-latentspace.md` Move 1, `harness-engineering-survey.md` (bounded-retry move), `agentic-platform-eng-saul.md` (bounded-loop contract). Carry-forward: `/cr` Step 4's existing NEEDS-HUMAN + hook-file escape hatch is the model for the new exit (grounding skills-A).
- **Tag.** P0 — the control surface that makes an unattended loop safe; the loop topology (close → annotate → re-queue → cap → escalate) designed in now, thresholds tuned later.

#### A4. Calibrate the reviewer — golden-set recall, re-run on every model/pass change — **P1**

- **What + why.** Nobody has ever measured whether `/cr` catches 1-in-5 defects or 4-in-5. We just moved Sonnet 4.6 → Opus 4.8 and have never re-scored the reviewer. **Failure prevented:** shipping autonomy on a quality gate with an *unknown and possibly catastrophic* miss rate, discovered only when a defect `/cr` "reviewed" reaches a paying stranger. An uncalibrated always-on reviewer is an accumulating-noise tax at fleet scale.
- **Mechanism.** A `golden-set/` corpus of labeled diffs — known-defective (seeded bugs: missing fallback, `as` cast without narrowing, cross-tenant RLS hole, open-redirect) each paired with expected findings, plus clean diffs. **Adversarially seeded**, not friendly-history-only (a friendly corpus reports a recall number optimistic by construction). A `/cr-calibrate` command / CI job runs `/cr` over it and emits recall + false-positive-rate per pass and per lens. Recall is re-measured on any change to `/cr` passes, the tier-merge rule, or the model version — calibration is a CI concern, not a one-time blessing. A stale recall number blocks promotion of `/cr` as a trusted autonomous gate. Doctrine: a calibrated `/cr` is a **triage** layer that sizes the human/CI net beneath it — never a *terminal* authority (the terminal authority is A1's CI-green-on-SHA).
- **Citation.** Confirmed absence — ground-truth §6 (`@benchmark-runner` phantom); no §3–§9 row measures `/cr` recall. Elevated by `coderabbit.md` Move 2, `recursive-self-improvement.md` Moves 2 & 4, `when-is-llm-call-worth-it.md` Move 1 ("golden-PR evals-in-CI"). Kill-list E item 1, C item 7 (golden-set calibration PROMOTES-NOW, distinct from outcome-tracking which stays gated).
- **Tag.** P1 — runs against a curated corpus (no live-volume dependency); gate model-upgrade adoption on recall not regressing. Best run as a cloud `/schedule` routine opening a regression issue on drop.

#### A5. Wire the governance corpus (ADRs, Rejected Patterns, PITFALLS) into review as criteria — **P0/P1**

- **What + why.** CodeRabbit's structural blind spot is *memory locality*: it can reason over the diff and code-graph neighbors but *cannot* reason over historical design decisions and locked conventions. That second set is exactly our moat — CLAUDE.md, AGENTS.md Rejected Patterns / Open Decisions, `docs/adr/`, PITFALLS. A migration violating a locked ADR, a role-check in RLS (explicitly rejected), a schema-file/folder collision (known PITFALL) are diff-local in *text* but governance-global in *meaning*. **Failure prevented:** a reviewer that re-litigates settled decisions or silently lets a PR violate one. Our `/cr`'s governance-awareness today is *asserted, not wired*.
- **Mechanism.** A dedicated `/cr` lens (or pass) whose input is `docs/adr/` + AGENTS.md Rejected Patterns + PITFALLS, instructed to flag any diff hunk that contradicts a locked decision and cite the specific ADR/pattern. This is the move that makes our in-process reviewer categorically better than any SaaS reviewer — they structurally cannot see our durable memory; we have it sitting unused. It composes with A2 (the isolated-context reviewer reads this canon) and with D2 (a generated lens criterion *is* a finding→enforcement artifact).
- **Citation.** Ground-truth §5 (`docs/adr/` store), §4 (PITFALLS + promotion lifecycle). Confirmed absence — no §3c/§4 row wires the locked-decision corpus as review input. Elevated by `coderabbit.md` Move 3.
- **Tag.** P0/P1 — the highest-defensibility move; the thing that converts "a local copy of CodeRabbit" into "a reviewer no SaaS tool can replicate." Wire alongside A2.

#### A6. Deterministic risk-based auto-approval (Ona L4) — non-LLM classifier takes most PRs out of the human path — **P1 (conservative thresholds)**

- **What + why.** Ona ships a deterministic risk-classification layer that auto-approves low-risk PRs with no human review (independent operator, 74% lead-time reduction). The classification is non-LLM: paths touched, diff size, test delta, scope. **Failure prevented:** the human-review-capacity model ("cap output to 5 PRs <400 lines a human can read in 2h") is a human-throughput bottleneck bolted onto a machine-throughput pipeline — the exact solo-dev framing that caps a fleet's output at one person's reading speed.
- **Mechanism.** A deterministic risk-classifier (a hook/script, safe under `disable-model-invocation`, no model judgment in the merge decision) emitting a tier from paths (auth/middleware/RLS/schema/payment/`next.config.ts`?), diff size, test delta, in-scope-ness. LOW (small, in-scope, no blast-radius paths, positive test delta, CI green, `/cr` clean — **all simultaneously**) auto-merges. MEDIUM → existing `/cr` flow. HIGH (auth/schema/payment) → forced `/cr-security` + mandatory human sign-off (L4 blast-radius escalation made *enforced*, not advisory). **Honest caveat:** for a $30k-client tool the LOW threshold must be conservative — that tunes the gate, it does not reject the mechanism. The trigger must be deterministic; a *model-confidence-score* auto-merge stays dead (authority laundering — the model grading its own diff "confident enough").
- **Citation.** Confirmed absence — ground-truth §3e "overwhelmingly advisory"; CLAUDE.md only *instructs* running `/cr-security` "alongside" auth changes, no deterministic enforcement. Elevated by `code-review-latentspace.md` Move 3. Kill-list F item 9: deterministic auto-merge OVERTURNED, model-score auto-merge UPHELD-CUT.
- **Tag.** P1 — the merge-gate realization of the autonomy thesis; reserves scarce human attention for the blast-radius minority. Ships after A1 (needs the CI-green signal) and the risk-classifier hook.

### STRAND B — Verification & the behavioral spec layer

#### B1. The per-feature behavioral contract — `docs/specs/<feature>.md` with an executable Verification section — **P0**

- **What + why.** Repos hold *code* (how) and *project-context docs* (what this codebase is) but rarely the third thing: "what is THIS feature supposed to do, and how do I know it still does it?" CLAUDE.md's doc-update table *names* `docs/specs/` ("behavioral spec / agent-readable contract for a module") but it does not exist on disk. **Failure prevented:** behavioral drift — the spec's real payoff is the fifth modification six months later, made by a stateless cold-start agent with zero memory of the original session that would otherwise silently break behavior nobody re-stated. Bug→PR and Slack-summoned builds are *only* safe if a cold-start agent can re-establish what a feature is *for* and verify it without a human.
- **Mechanism.** A per-feature doc class `docs/specs/<feature>.md` with three required sections: **Behavior** (what it does), **Implementation pointers** (where it lives), **Verification** (executable steps that prove it works). Wire `/feature` to write/update the spec *first*, commit it, build against it; future edits update the spec then reconcile code. The spec's git history is a human-and-agent-readable changelog of *intent*. Do NOT absorb it into ADRs (those are cross-feature decisions with no behavior/verification contract) or into developer tests (not a spec-derived oracle). **Ship with an independent review pass on the spec from day one** — spec-first has no built-in adversary; do NOT copy Notion's self-verification-by-implementer.
- **Citation.** Confirmed absence — ground-truth §3a (no per-feature spec among CLAUDE/CONTEXT/AGENTS/SOUL/ARCHITECTURE/TESTING); §4 (ADRs=decisions, solutions=patterns, PITFALLS=traps, no behavioral contract). Elevated by `notion-spec-driven.md` Move 1. Kill-list C item 6 PROMOTE-NOW. Carry-forward: `/feature` already has a `docs/specs/[task-slug].md` + `human-approved: false` frontmatter gate for Medium+ (grounding skills-B) — build the spec class to fill it.
- **Tag.** P0 enabling substrate — the load-bearing, tool-agnostic autonomy primitive (it outlives any agent). Designed in lockstep with A1's unforgeable gate.

#### B2. The autonomy gate verifies the spec's Verification section, not the `.cr-ok` process token — **P0**

- **What + why.** `.cr-ok` is a *process-completion* signal ("review ran") masquerading as a *correctness* signal. **Failure prevented:** an unattended bug→PR loop merging on a "review ran" token instead of a "behavior verified" assertion — a correctness hole the moment a human stops watching.
- **Mechanism.** Make each spec's Verification section a list of **executable assertions** (CLI invocations, scripted checks, render-and-diff, an agent-runnable harness) — not prose. Re-type the autonomy gate: for any feature with a spec, the gate also requires the spec's Verification to *pass*, not merely that `/cr` ran. `.cr-ok` is re-documented as a *readiness signal*; the verification surface is the *capability unlock*. CI can verify it too (closes the §3f gitignored-sentinel hole — same plumbing as A1).
- **Citation.** Ground-truth §3e (agent pre-push validates `.cr-ok`); §3f (Node 8.5(c)); §9 Replace list pre-authorizes exactly this re-typing ("`.cr-ok` as a capability gate → document as a readiness signal, not a capability unlock"). Elevated by `notion-spec-driven.md` Move 2.
- **Tag.** P0 — co-equal with B1; the keystone that makes the autonomy charter safe to switch on.

#### B3. The `/verify` render gate — artifact-producing, CI-resident, fail-closed tenant assertion — **P1**

- **What + why.** When an agent says "I fixed the layout, it renders correctly," a human takes it on faith — no proof attached. **Failure prevented:** an overnight agent merges a PR whose UI is broken because "agent says it works" was the only verification — the single most expensive failure of autonomous agents, the confident-wrong "done." Plus a multi-tenant trap: a browser snapshot taken while authed as the *wrong tenant* renders perfectly (RLS isolation is invisible to the DOM) and yields a confident-wrong diagnosis — a security-incident generator on an RLS product.
- **Mechanism.** A project-owned `/verify` skill (distinct from `/debug` — opposite economics: `/debug` is the capped exploratory hunt, `/verify` is the binary deterministic gate). Against a preview deploy: navigate changed route(s), capture an accessibility snapshot + console errors + a pixel-diff vs a checked-in baseline, **attach the bundle to the PR** as a reviewable artifact, gated by `disable-model-invocation` so the agent can neither fabricate nor skip it. **Fail-closed tenant assertion**: before any snapshot is trusted, assert the active session's `team_id`/tenant matches the intended one (a `data-tenant` marker or a pinned seeded test tenant); re-validate the saved auth session (JWT + expiry), never assume. Because `chrome-devtools-mcp` is **headed-only** (breaks in CI/overnight), the unattended/scheduled verify leg runs as a **CI job against a preview deploy**, not a local MCP — which reinforces the CI-resident design.
- **Citation.** Confirmed absence — ground-truth §3f (CI is tsc/lint/vitest only; no browser job; the live `verify` skill is borrowed, not on disk). Elevated by `playwright-mcp-debug.md` Moves 1, 4, 5; `ramp-inspect-agent.md` (visual artifact guardrail). Kill-list C item 7 (visual gate PROMOTE-NOW P1), F item 9 (Playwright headless OVERTURNED).
- **Tag.** P1 — makes UI fixes mergeable unattended. Pairs with B4 (agent-legible markup) which makes the snapshot trustworthy.

#### B4. Agent-legible == human-accessible markup, mandated + lint-enforced — **P1**

- **What + why.** Whether an agent can navigate and diagnose the app is decided by markup, not tooling. An unlabeled icon button reads as `button [@e3]` and the agent guesses; `aria-label="Approve proposal"` is unambiguous. The deep point: the markup that makes the app *agent-legible* is the exact markup that makes it *accessible to humans* (WCAG) — near-zero extra cost for a well-built app. **Failure prevented:** every browser-verification run produces noisy, guess-laden snapshots the agent misreads, generating confident-wrong diagnoses on UI it literally cannot name.
- **Mechanism.** A CLAUDE.md rule + a `docs/design/` instrumentation entry mandating `data-testid` on key interactive elements, meaningful `aria-label`/text on every interactive element, structured `console.error` (objects not concatenated strings), descriptive error-boundary messages (not "Something went wrong"), `aria-busy`/loading labels. Enforce with a `jsx-a11y` ESLint rule at commit time. Currently `grep` finds **zero** `data-testid` across `src/` and `app/`.
- **Citation.** Confirmed absence — ground-truth: zero `data-testid`; no CLAUDE.md rule, no design-token doc covers it. Elevated by `playwright-mcp-debug.md` Move 3.
- **Tag.** P1 — lightweight but it is the foundation B3 stands on; "bigger" here means *enforced and mandated*, not architecturally large.

#### B5. The machine-enforced self-verification evidence bundle (Stop/PostToolUse hook) — **P0/P1**

- **What + why.** Most agents write code and stop; Ramp's Inspect closes the loop — every session runs its own verification against the real stack (tests, screenshots, runtime logs) *before* the PR exists, which is why ~30% of merged PRs flow through it organically with no mandate. **Failure prevented:** an autonomous agent reports "done," opens a PR, and the regression ships because nothing deterministic re-ran the suite — precisely the advisory-enforcement gap §3e documents we live with.
- **Mechanism.** A machine-enforced gate (a `Stop`/`PostToolUse` hook — *not* a CLAUDE.md sentence or skill-body instruction, so it cannot be rationalized away) that fires at task-completion: runs `npm run test` + `npx tsc --noEmit`, blocks on red, and for any UI-touching diff requires a Chrome-MCP before/after screenshot. At fleet grade, pull the deployment's runtime logs (Vercel `get_runtime_logs` / `get_deployment_build_logs`) into the bundle. The bundle (tests-green + typecheck-clean + runtime-log scan + visual artifact) is emitted as an *evaluable pass/fail object* the PR carries — so a human or scheduled review agent reviews *intent over proof*. Two non-negotiables: it buys **regression-trust, not correctness-trust** (the human/independent-reviewer semantic checkpoint stays), and it must NOT write `.cr-ok` (that would launder a regression check into a capability unlock). The natural host (`session-end.sh` Stop hook) is canon-declared but absent on disk — build it.
- **Citation.** Confirmed absence — ground-truth §3e ("overwhelmingly advisory… no deterministic backstop"); §5 (`session-end.sh` declared, absent). Elevated by `ramp-inspect-agent.md` Move 1. UPHELD-CUT (named): Ramp's *frontend-driving-for-feature-completeness* — there is no finished frontend to drive and the safe envelope is read-mostly (collides with destructive-op rules); adopt only the screenshot/real-test half.
- **Tag.** P0/P1 — the evidence bundle that gates the autonomous PR; the visual-artifact sub-clause is the review-throughput multiplier for a human reviewing 5 repos.

### STRAND C — Testing as a model-immutable correctness oracle

#### C1. Property-based testing on money math — the human-authored invariant the loop cannot weaken — **P1**

- **What + why.** Example tests check the cases a developer (or model) happened to think of — and when the model writes both the implementation and its tests, it tends to test exactly the inputs the implementation already handles. Property-based testing asserts an *invariant* that must hold for **all** inputs; the framework generates hundreds of adversarial inputs trying to break it. **Failure prevented:** a pricing bug that survives because nobody (human or model) wrote the example that exposes it — and a wrong total is a $30k-client-facing disaster. The deep reason this is the *highest-value* lever: a property is "something the model can't argue with" — a human-authored, model-immutable specification of correctness, the actual scarce resource. When the loop authors its own oracle, the human-specified invariant is the *only* check it cannot quietly weaken.
- **Mechanism.** Adopt a PBT library (`fast-check`, vetted against the dependency rule — name/purpose/weekly-downloads/last-publish/ships-its-own-types, confirmed for Vitest 4 / TS 5; a 30-min step, not a gate; **ask before installing** per CLAUDE.md). Define the minimal money-math invariant set: `total = sum(line items)`; tax never on service fees; no negative line totals; discounts never produce negative subtotals; integer-cents round-tripping is exact. PITFALLS rule + a coverage-style blocker: any change to pricing/total logic requires a property test.
- **Citation.** Confirmed absence — grep for `property-based|fast-check|PBT` across the v2-audit corpus + ground-truth returns nothing; testing is example-based Vitest + real-DB integration only. Elevated by `recursive-self-improvement.md` Move 3. Kill-list C item 4 PROMOTE-NOW.
- **Tag.** P1 — immediately after A1/A4 (the unforgeable gate + calibration); the first place the harness demonstrates "human-authored spec the model can't redefine."

#### C2. Carry-forward the TDD ledger discipline as the spec-derived oracle — **P0 (preserve, do not regress)**

- **What + why.** `/tdd`'s `docs/TESTING.md`-as-behavior-ledger is the mechanism that prevents *transcription tests* — the no-transcription rule ("expected behavior comes from TESTING.md or the user, never from reading the implementation; reading the code to derive expected values produces tests that pass even when behavior is wrong"). **Failure prevented:** the autonomous loop writing tests that confirm whatever the implementation does, making the test suite a mirror instead of an oracle.
- **Mechanism.** Preserve verbatim in V2: TESTING.md read in Step 1 as the spec source (stop-and-ask if absent), written back in Step 6 ("Code-observed" → "Confirmed behaviors"); the named Specify→Encode→Fulfill loop; one-behavior-one-test-one-commit; the codebase test patterns (never mock the DB, seed via `supabaseAdmin` in `beforeAll`, the only accepted spy is `vi.spyOn(supabaseAdmin.auth, 'getUser')`). This ledger gives a laptop-closed cloud run durable cross-session memory of confirmed-vs-gap so it doesn't re-test or write transcription tests. It interlocks with B1 — the spec's Verification section and TESTING.md are the two halves of the spec-derived oracle.
- **Citation.** Grounding skills-C (tdd): "the `docs/TESTING.md`-as-spec-ledger wiring is golden-exemplars-class; a summary that drops 'reads/writes TESTING.md' guts the skill." CLAUDE.md → Testing.
- **Tag.** P0 carry-forward — not a new build; a do-not-drop invariant of the V2 testing stack.

### STRAND D — The compounding engine (the self-improving loop, closed)

#### D1. Close the read-path — recurring findings load into the implementer's task-start context, with decay — **P0**

- **What + why.** Bitloops drove violations down 87-100% over 8 weeks purely by recording every caught violation and feeding it back as generation context — *context accumulation*, not model updates. Our harness has the *write* side (RECURRING-FINDINGS.md auto-counted by `/cr` Step 3b) but ground-truth is blunt: it is "**never read by implementers**." We accumulate findings into a store no one reads — a write-only loop; the compounding never closes. **Failure prevented:** an agent making the same class of mistake every run because nothing it was corrected on is read back at the next run's start.
- **Mechanism.** Load recurring findings into the *implementer's* task-start context (not just a pipeline-only file), paired with an **eviction/freshness model**: decay by recurrence — a pattern unobserved 90 days collapses (the recurrence rate *is* the eviction signal). Do NOT build a new `learned-patterns.md` (that is a §6 phantom and duplicates `docs/solutions/` + RECURRING-FINDINGS). Measure first-pass-approval-rate to confirm the read-back is working.
- **Citation.** Ground-truth §4 (RECURRING-FINDINGS "never read by implementers"); §9 (90-day decay rule exists in canon, "encoded in no tooling"). Elevated by `code-review-latentspace.md` Move 4. Kill-list F item 2 PARTIAL (file stays phantom; read-path resurrected).
- **Tag.** P0 — the self-improvement primitive that turns "agent that needs 2-4 review rounds" into "agent approved on first review."

#### D2. The finding→enforcement ratchet — recurring finding becomes a deterministic block, not a note — **P0**

- **What + why.** Hashimoto's definition of harness engineering is mechanical: "anytime you find an agent makes a mistake, engineer a solution such that the agent never makes that mistake again." Our harness is "overwhelmingly advisory" — every memory store (`.claude/memory.md`, PITFALLS, auto-memory `feedback_*`) is a *note*, not a *gate*. The promotion path terminates at a human-read doc; there is no arc that turns a recurring finding into a mechanism that *prevents* recurrence. **Failure prevented:** you keep re-finding the same bug forever instead of making it impossible — a harness that keeps a tally instead of getting structurally harder to break.
