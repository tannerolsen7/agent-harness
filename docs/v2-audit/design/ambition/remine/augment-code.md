# Ambition Re-mine — Augment Code: Context Engine, Contractor vs. Employee & Probabilistic Enforcement

## What this source is (plain English, 2-3 sentences)

A curator's synthesis of Augment Code's vendor guides ("How to Build AGENTS.md", "Harness Engineering for AI Coding Agents") plus a podcast with Augment's VP Engineering Vinay Perneti. Its load-bearing idea: an LLM's compliance with written instructions is *probabilistic* — rules files only shift the odds of correct behavior — so a world-class harness pairs that probabilistic context layer with a *deterministic* outer harness (hooks, CI gates, linters) that makes the violations that matter structurally impossible. It also teaches a three-tier rule-loading taxonomy, an FTE-vs-contractor framing of why context infrastructure is the real investment, and the principle that rules files should hold only what *cannot be inferred from the code*.

---

## The full-ambition moves this source teaches

### Move: Every rule is consciously assigned to a layer — probabilistic context OR deterministic enforcement, never confused

- **Plain-English what & why:** A model does not *obey* a rule the way a compiler obeys a directive; it *probably* follows a written rule, and the probability is below 1.0 no matter how well you write it. So for any rule that actually matters, prose in a context file is the wrong tool — you must encode it as something the runtime physically cannot bypass (a hook that blocks the tool call, a CI check that fails the build, a pre-commit that aborts). The failure this prevents: a team writes a beautifully phrased "NEVER force-push to main" in CLAUDE.md, believes it is protected, and then an agent force-pushes to main at 3am because prose is advice, not a wall. The discipline is to look at every safety-critical rule and ask "is this in the layer that can actually stop it, or just the layer that asks nicely?"
- **The mechanism:** A standing audit pass over CLAUDE.md and the skill bodies that classifies each rule into one of two buckets — *probability-shifter* (fine as prose; a style preference, a naming convention) or *must-be-structural* (a destructive-op block, a scope boundary, a test-green gate). Every rule in the second bucket that currently lives only as prose is a build target for the hooks layer. Concretely for us, this turns the canon's bare §5 hook entries into a *prioritized, principled* build list: `block-dangerous-bash.sh`, `enforce-scope.sh`, `session-end.sh` Stop-test-gate, and the pre-commit main-branch block are not "nice to have" — they are the cases where a safety rule is currently sitting in the wrong layer.
- **Citation:** §3e (`block-dangerous-bash.sh` canon-declared, ❌ absent on disk; `enforce-scope.sh` ❌ absent; `session-end.sh` Stop hook ❌ absent; live `.husky/pre-commit` is a 67-byte shim lacking the main-branch agent block). §5 (canon-only registry of these same structural guards as build-or-reject). §3e confirms `block-dangerous-git.sh` and `block-npm-install.sh` both **fail-open on missing jq**.
- **Conservative disposition:** Pass3 §(a) treats the two-layer architecture as "already exists in skeleton" and §(b)1–4 lists the gaps as real but frames the whole source as "synthesize, do not re-research… one synthesized insight." MASTER-FINDINGS folded ~30 cited gaps into 6 cautious wiring-tweaks; this principle's concrete build targets (the three absent structural hooks, the wired-out pre-commit) were treated as individual §5 line items to be decided one-by-one, not as a single first-class doctrine that *reorganizes the entire enforcement layer*.
- **RE-JUDGMENT under the new charter:** **ELEVATE.** The conservative read stopped at "we have a skeleton + here are some absent hooks." The world-class read is that this principle is the *organizing doctrine of the whole harness*, and under the autonomy charter it becomes the single most important one. The old framing left the structural hooks as optional §5 entries to litigate; the new framing makes them mandatory, because **autonomy removes the human who was silently backstopping every prose rule**. When a bug→PR loop or a cloud `/schedule` run executes with no human watching, every rule that lives only in the probabilistic layer is *unbacked* — there is no person to catch the tail. This should be bigger by an order of magnitude: a "layer assignment" gate added to `/cr` and `/compound` that flags any safety-critical prose rule with no structural twin, plus a committed build of all four absent/wired-out structural controls before any unattended trigger ships. The old reasoning was conservative bias because it scoped the principle to "audit + maybe build a hook" when the principle is actually the spine that makes autonomy safe at all.

### Move: Guard integrity — a deterministic control that fails open is probabilistic enforcement in a costume

- **Plain-English what & why:** This is the corollary pass2 §7 extracted and it is *more* important than the headline. A hook is only "deterministic" if it cannot be silently defeated. Our two existing guards (`block-dangerous-git.sh`, `block-npm-install.sh`) parse their input with `jq`, and if `jq` is missing they **fail open** — they let the operation through. So under exactly the degraded conditions where you most need the guard (a fresh cloud sandbox, a stripped container, a misconfigured worktree), the guard evaporates and *looks like it ran*. A fail-open guard is worse than no guard, because it manufactures false confidence. The failure this prevents: an agent runs a destructive git op in a sandbox that happens to lack `jq`, the guard returns success, and the prose rule was the only thing standing — which is to say, nothing was.
- **The mechanism:** A guard-integrity rule for every structural hook: (1) fail *closed* — if a dependency (`jq`, the parser, the config file) is missing, the hook must `exit 2` and block, not pass; (2) a startup self-test (SessionStart or a CI smoke test) that asserts each guard actually blocks a known-bad input, so a silently-degraded guard surfaces loudly; (3) a CI check that the guard scripts are present, executable, and wired (catching the `core.hooksPath=.husky/_` dormancy where the canon-matching `.githooks/pre-commit` is wired out).
- **Citation:** §3e (both bash guards "jq fail-**open**"; live `.husky/pre-commit` is a 67-byte shim, `.githooks/pre-commit` **dormant** under `core.hooksPath=.husky/_`). §3f (CI never verifies `.cr-ok`; the readiness signal sits entirely in the advisory layer at the CI boundary). This is a confirmed-disk gap the source's principle exposes — the source itself never audited disk, so the gap is ours, named by its principle.
- **Conservative disposition:** Pass3 §(b)1 and §(b)5 name both the fail-open guards and the wired-out pre-commit as real gaps, citing §3e/§3f. But MASTER-FINDINGS treated these as part of the "6 wiring-tweaks" — i.e. small mechanical fixes — rather than as a *class of failure* with its own doctrine. The fail-open behavior was logged as a bug to fix, not as a standing invariant the whole enforcement layer must satisfy.
- **RE-JUDGMENT under the new charter:** **ELEVATE.** Fixing two `jq` fail-opens is a wiring-tweak; establishing **guard integrity as a first-class invariant of every structural control** is world-class, and the autonomy charter makes it non-negotiable. Cloud `/schedule` runs on Anthropic infra in a *restricted-network, minimal-environment* sandbox — precisely the condition that triggers fail-open. So the moment we ship autonomy, every fail-open guard is live-fire vulnerable on every scheduled run. This should be bigger: a committed "fail-closed + self-test + CI-presence-check" contract that applies to `block-dangerous-bash.sh` (when built), the two existing guards (retrofit to fail-closed), and the pre-commit (un-dormant it, or move its block into the live husky shim). The old reasoning under-weighted it because, in a human-in-the-loop world, a degraded guard's tail risk is caught by the human; in an unattended world there is no catcher, so guard integrity *is* the safety boundary.

### Move: Three-tier rule loading (always / agent-requested / manual) as an explicit, designed context-budget mechanism — not an accident

- **Plain-English what & why:** Augment's rules taxonomy keys on *when a rule enters the context window*: `always_apply` (every prompt), `agent_requested` (loaded when the model judges it relevant), `manual` (only on explicit invocation). The world-class insight underneath is that **context is a scarce, budgeted resource and what loads when is a deliberate design decision**, not whatever happens to be in CLAUDE.md. A bloated always-load file taxes every single turn; a rule that should only appear during migrations shouldn't burn tokens during a CSS tweak. The failure this prevents: an ever-growing root context file that degrades every task because nobody decided what *must* be resident vs. what should load on demand.
- **The mechanism:** A deliberate, documented three-tier assignment for our context corpus: `CLAUDE.md`/`SOUL.md` = always-load (kept *small* on purpose); skills loaded on `agent_requested` invocation (the situation triggers them); explicit `/skill` prompts = manual. Crucially, the design discipline is to keep always-load *minimal* and push everything situational into the agent-requested tier — which dovetails with the canon's §9 "shrink the root" and "trigger should be the situation, not the words" mandates.
- **Citation:** Pass1 §B, pass3 §(a)2 maps this to our layers (always ≈ CLAUDE.md, agent-requested ≈ ~26 skill dirs at §3b, manual ≈ explicit prompts). §9 (Model Capacity Audit: "Phrase-keyed skill descriptions → trigger should be the situation, not the words"; structural shrink mandate).
- **Conservative disposition:** Pass3 §(a)2 calls this "the one row where the page's 'already in the system' claim survives contact with disk" — i.e. **fully built, nothing to do.** This is the cleanest "already-built, never re-propose" verdict in the whole file. Pass2 §4 had already noted the taxonomy is a *loading* model that says nothing about *obedience*, which the conservative read used to further discount it.
- **RE-JUDGMENT under the new charter:** **UPHELD-CUT (as a build target), with a NEW sliver elevated.** Honestly: as a *loading taxonomy*, we genuinely have it — CLAUDE.md/skills/prompts already realize the three tiers, and re-proposing the taxonomy itself is a phantom. The named failure mode that justifies *not* rebuilding it: there is nothing to build; a fourth tier or a re-labeling adds files with no failure-mode payoff, which §9's golden rule forbids ("if you can't name a failure mode the constraint prevents, it's overhead"). BUT — the world-class sliver the conservative read buried is the *budget discipline*: we have the three tiers but no mechanism that keeps the always-load tier minimal as it grows. That sliver is **NEW** and lives downstream in the §9 model-capacity work (shrink the root), not here. So: cut the taxonomy-as-novel, keep the budget-discipline pointer.

### Move: Rules files hold only what *cannot be inferred from the code* — and the boundary moves with model capability

- **Plain-English what & why:** Augment's design principle: the Context Engine handles everything derivable from the codebase; rules files are reserved for what *cannot* be inferred (cross-module architectural boundaries, logging standards, "we do X here for a non-obvious reason"). Writing down what the model could already figure out is pure tax — it bloats context and it goes stale. The deeper, world-class extension (pass2 §7) the source itself misses: **the inferable/non-inferable line is not fixed — it moves as the model gets smarter.** Opus 4.8 can infer from the codebase things Sonnet 4.6 needed spelled out. So a rule that was load-bearing scaffolding last quarter is dead weight this quarter. The failure this prevents: a context corpus that only ever grows, accumulating "ghost rules" the current model no longer needs, each one quietly degrading every task.
- **The mechanism:** A periodic re-classification pass — on every model upgrade — that asks of each rule: "can the current model infer this from the code now? If yes, delete it." This is exactly the canon's Model Capacity Audit (§9), which already distinguishes *reasoning discipline (keep)* from *capability proxies (remove)* and explicitly states its judgments were made against Sonnet 4.6 and are due for re-audit on Opus 4.8. The source supplies the *generative principle* (inferable→delete) that the canon's audit operationalizes; what's missing on disk is any *standing mechanism* that triggers the re-cut on a model change.
- **Citation:** Pass1 §B, pass3 §(b)7 ("No store/owner for 'what cannot be inferred' — and the boundary is model-dependent"; PITFALLS.md/memory.md assigned to *both* Layer-1 Context and Layer-3 Memory per §4; §9 exists because the boundary moved Sonnet 4.6 → Opus 4.8). Confirmed absence: no disk mechanism re-classifies a rule as "now inferable → delete" on model upgrade.
- **Conservative disposition:** Pass3 §(b)7 names this as a real gap and §(c)1 notes the FTE metaphor argues *against* the pruning the canon mandates — but MASTER-FINDINGS routed it into the §9 model-capacity bucket as a deferred audit, not a built mechanism. It was treated as "a re-audit we'll do," not "a recurring capability we'll wire."
- **RE-JUDGMENT under the new charter:** **ELEVATE.** Under the autonomy + self-improving-loops charter, this stops being a one-time manual re-audit and becomes a *standing self-improvement loop*: a scheduled (cloud `/schedule`-driven) capability-audit routine that, on each model bump, re-classifies the rule corpus and proposes deletions as a reviewed PR. That is precisely the "self-improving loop" the new charter makes first-class — the harness pruning its own scaffolding as the model outgrows it. The old read deferred it to "a Phase-4/5 audit we'll run manually"; the world-class version is an automated, scheduled prune-PR loop. Bigger by: turning a manual audit into a recurring autonomous capability with a human-reviewed output gate. The conservative bias was treating model-capability drift as an occasional event rather than a continuous force the harness should track automatically.

### Move: Accountability for unattended agents must be technical, because "the person pushing the PR owns it" assumes a person is present

- **Plain-English what & why:** Augment's accountability answer is *cultural*: "the person pushing the PR owns the code, period" — automation bias is countered by the norm that whoever merges an AI PR owns it as if they wrote it. Pass2 §5 lands the killer observation: this is a *human-presence* solution. The instant the agent runs unattended — AFK worktree mode, cloud schedule, a bug→PR loop firing at 3am — there *is* no person pushing the PR in real time. Accountability is deferred to a review that may happen hours later against a branch no human watched form, or may never scrutinize what culture would have caught live. The failure this prevents: an unattended session completes with red or unrun tests, opens a PR, and "ownership" is a fiction because nobody was in the loop to own anything. This is the seam where PocketOS-class incidents live (§9 keeps the destructive-op rules verbatim *because culture is not present at 3am*).
- **The mechanism:** Replace the absent cultural backstop with technical gates that travel with the unattended run: (1) the `session-end.sh` Stop hook that *verifies test output is green before a session can complete* — canon-declared, absent on disk; (2) the `.cr-ok` sentinel chain extended so an unattended PR *cannot open* without a passing review signal that CI actually verifies (today CI never checks `.cr-ok`, §3f); (3) for bug→PR autonomy, `disable-model-invocation:true` on the open-PR / deploy side-effect skills so the autonomous path is *structurally* prevented from skipping the gate. The cultural norm stays for human merges; the technical floor covers the unattended ones.
- **Citation:** §3e (`session-end.sh` Stop hook canon-declared, ❌ absent on disk; UNATTENDED worktree mode + prod-key firewall present). §3f (CI never verifies `.cr-ok`; readiness signal entirely advisory at CI boundary). §9 (destructive-op rules kept verbatim *because* culture is absent at 3am). Pass2 §5, pass3 §(b)3.
- **Conservative disposition:** Pass3 §(b)3 names the gap correctly ("Unattended operation breaks the page's accountability model, and we have nothing technical to replace it… no Stop hook that verifies test output"). But under the *old* charter, unattended operation was something to be cautious about expanding — the conservative synthesis deferred the autonomous trigger front-door entirely. So this gap was logged as "a reason to be careful about AFK," i.e. a brake on autonomy, rather than as "the exact technical floor that makes autonomy safe to ship."
- **RE-JUDGMENT under the new charter:** **ELEVATE.** The new charter makes autonomy first-class and confirms cloud `/schedule` exists and runs committed skills with no human present — which means the unattended path is *the* path, not an edge case to defer. So this move flips from "a caution against AFK" to "the mandatory safety floor that must ship *with* the first autonomous trigger." It should be bigger: the Stop-hook test-gate, the CI-verified `.cr-ok`, and `disable-model-invocation` on side-effect skills are not optional hardening — they are the preconditions for bug→PR and `/schedule` to be safe at all. The old reasoning was conservative bias twice over: it both under-built the technical floor *and* deferred the autonomy that makes the floor essential. Under autonomy-first, you cannot defer either.

## Autonomy angle

The source does not *teach* bug→PR, Slack/Linear summon, or cloud scheduling directly — Augment's product is a human-in-the-loop IDE assistant, and its accountability model explicitly assumes a person merges. But the source is unusually load-bearing for autonomy *by negative space*: its two most important principles are precisely the ones that make autonomy safe, and its blind spot is precisely the autonomy gap.

- **Probabilistic-vs-deterministic enforcement** is the doctrine that makes any unattended trigger safe: without a human catching the tail, every safety rule must live in the deterministic layer. This directly governs how a bug→PR loop or a scheduled run is allowed to take side effects — and connects to `disable-model-invocation:true` (the resolved fact that removing a skill from the model's context is what makes side-effect skills safe). The deterministic layer is *how* you let an autonomous loop deploy or open a PR without it improvising a destructive op.
- **Guard integrity (fail-closed)** is the corollary that matters most for cloud `/schedule`, which runs in a restricted-network minimal sandbox — exactly the fail-open trigger condition. Autonomy literally runs in the environment where our current guards evaporate.
- **The accountability gap (pass2 §5)** *is* the autonomy gap: "cultural, not technical" silently breaks the moment no human is present, so the source hands us the precise list of technical gates (Stop-hook test verification, CI-verified readiness sentinel) that an autonomous trigger must satisfy.
- **Inferable→delete + model-capability drift** is a natural *self-improving loop*: a scheduled capability-audit routine that prunes outgrown scaffolding via reviewed PRs — autonomy applied to the harness itself.

So: no direct trigger mechanism, but the source supplies the safety doctrine that every autonomy mechanism in the vision depends on.

## The single biggest move (one paragraph)

**Pick up the layer-assignment doctrine first — "every safety-critical rule must be assigned to the deterministic layer, and the deterministic layer must be fail-closed" — and make it the organizing spine of the enforcement work.** It is world-class because it is the one principle that turns autonomy from reckless to safe: the entire reason a bug→PR loop or a cloud `/schedule` run can be trusted to take side effects is that the rules that *must* hold are encoded where the model physically cannot bypass them, and those encodings cannot silently degrade in a stripped sandbox. Concretely this means building the three canon-declared-but-absent structural guards (`block-dangerous-bash.sh`, `enforce-scope.sh`, the `session-end.sh` test-gate), un-dormanting the wired-out pre-commit main-branch block, retrofitting the two existing guards to fail *closed*, and adding a `/cr` + `/compound` pass that flags any safety-critical prose rule lacking a structural twin. Every one of these is cited to a real §3e/§3f/§5 gap, every one is a precondition for shipping autonomy safely, and together they convert ~30 scattered "wiring-tweaks" the conservative synthesis buried into one coherent, world-class doctrine that scales across the parallel agent fleet because it is enforced by the runtime, not by a human who isn't watching.
