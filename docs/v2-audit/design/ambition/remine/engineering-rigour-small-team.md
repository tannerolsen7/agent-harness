# Ambition Re-mine — Engineering Rigour for a 1–3 Person Team (Process Over Model)

## What this source is (plain English, 2-3 sentences)
A synthesis of four 2026 sources (Nakazawa's "Modern Engineering Values," Rossi's "My AI Coding Workflow"/"Tolaria," plus an uncredited CodeRabbit-style "process not model" argument) arguing that engineering quality with AI agents comes from the *development process* — the harness — not from the model. Its one original move is a **team-size filter**: a habit only earns its place if it survives the "team-of-1-to-3" test, otherwise it's org-scale ceremony to delete. It pushes three concrete practices — failing-test-first (especially for bug fixes), context-in-the-repo, and risk-tiered review that scales with reversibility not source.

The conservative synthesis treated this source as almost entirely confirmatory ("we already do this, often more rigorously") and harvested only two small wiring tweaks. Under the new charter, the question is whether the *mechanisms* it teaches exist at world-class quality on disk, or whether we have weak/advisory versions that need to become real gates.

## The full-ambition moves this source teaches

### Move: Failing-test-first as an *enforced gate* for every bug fix (not just pure functions)
- **Plain-English what & why:** Before fixing a bug, you write a test that reproduces it and *fails*. Then you make it pass. Nakazawa and Rossi independently land on this as the single highest-leverage habit because it forces the agent to fix the *right* problem — without a failing test, an agent will produce plausible code that may not address the actual defect, and may silently re-break later. The failure mode it prevents: a behavior-changing bug fix with no characterization test can re-introduce the bug or mask it, and nothing catches the regression.
- **The mechanism:** Today TDD is mandatory only for pure functions in `src/data/`, `src/schemas/`, `src/utils/` — a bug fix to a component, a server action (`app/(app)/*/actions.ts`), or the `/p/[token]` renderer has **no reproducing-test requirement**. World-class version: a deterministic backstop. A `/cr` pass (or a pre-push hook) that detects a commit labeled/scoped as a fix and asserts the diff contains a new test that was red-before / green-after. Concretely: a `bugfix-test-guard` that, when the branch/commit type is `fix`, requires at least one new or modified test file in the diff and refuses the sentinel otherwise. This is the "executable constraint" format the harness already aspires to.
- **Citation:** Confirmed absence in the gate inventory — enforcement is "overwhelmingly advisory… neither has a deterministic backstop for the bulk of skill bodies, CLAUDE.md rules" `[map §3e, Net enforcement picture, lines 217–220]`. The article's prescribed home (`learned-patterns.md`) is a confirmed phantom `[map §6, line 295; §0 correction log, line 26]`.
- **Conservative disposition:** §C/partial — pass3 (b)1 accepted it as a "real gap" but immediately narrowed it. MASTER-FINDINGS noted "the bugfix-test rule duplicates `/tdd` (§3b)" `[map line 358]` and the kill-list framing treats it as a candidate that gets *killed at review* for duplicating an existing skill. Net: harvested as "one executable constraint… given a real home," but deflated to a near-duplicate of `/tdd`.
- **RE-JUDGMENT under the new charter: ELEVATE.** The "duplicates `/tdd`" dismissal is the conservative bias. `/tdd` is a *skill the model invokes when it chooses to* and is scoped to pure functions; it is not a gate, and it does not cover the exact surfaces where a bad fix is most expensive (the `/p/[token]` renderer in front of a $30k client, server actions, RLS-adjacent `src/data` edits). A skill the model may skip is precisely the advisory layer this whole audit exists to harden. World-class = a deterministic `bugfix-test-guard` in the gate floor, *not* a reminder in a skill body. In an unattended/background run (pass2 §7) there is no human to notice a missing test, so this gate is *more* load-bearing, not a redundant nicety. Bigger than the conservative read: it's not "add a line to a constraints file," it's a new hook in the same structural-guard slot the map flags as absent.

### Move: Risk-tiered review with a *machine* irreversibility classifier (path/glob → mandatory security pass)
- **Plain-English what & why:** Don't line-review every PR — that burns out a solo dev and isn't world-class, it's ritual. Instead, scale scrutiny with *reversibility/blast-radius*, not with whether a human or agent wrote it. The catch the article misses: reversibility isn't always legible at review time. A one-line `src/data` change can silently widen an RLS query; "low-risk" copy on `/p/[token]` is on the one client-facing surface where one bad render costs the client. So the rule needs a cheap, deterministic classifier — which paths are *always* the irreversible tier — or it decays into "scrutinize whatever the tired dev felt was scary."
- **The mechanism:** A hook that inspects the diff's touched paths against a glob list (auth, middleware, `proxy.ts`, RLS/migration files, `src/data/**`, the proposal-send path, `/p/[token]/**`) and, on a hit, *forces* the `/cr-security` pass — refusing the push sentinel until the security pass ran. Today this rule lives only as **prose in CLAUDE.md** ("run `/cr-security` only when a commit touched auth, middleware, or RLS"). The world-class version makes the classification structural and unskippable.
- **Citation:** The structural guards that would host this are confirmed absent on disk: `enforce-scope.sh` ❌ and `branch-registry-guard.sh` ❌ `[map §3e, lines 207–208; §5, line 277–278]`. The rule is currently advisory prose, not a gate (pass3 (b)3).
- **Conservative disposition:** §C deferred / scaled-down. Pass3 (b)3 named it as a real gap but the synthesis filed it as one of two "wiring tweaks" — and pass3 (a) argued the *policy* already exists ("codified as policy, not vibes"), which understates that policy-as-prose is exactly the advisory layer with no deterministic owner.
- **RE-JUDGMENT under the new charter: ELEVATE.** "We already enforce review-scales-with-reversibility… codified as policy" conflates *having a prose rule* with *enforcing it*. Under autonomy-first, an unattended agent that touches `proxy.ts` and skips `/cr-security` produces an auth regression with no human in the loop — the precise scenario the destructive-op/PocketOS rules exist for, but for review rather than mutation. World-class harnesses (CodeRabbit/Ramp-grade) gate the security review on the *diff content*, not the agent's memory of a CLAUDE.md sentence. This is bigger than a wiring tweak: it's a `blast-radius-router` hook with a committed glob manifest, and it pairs naturally with the bugfix-test-guard as the two halves of a real "risk router" in the gate floor.

### Move: A fourth "G" — Doctrine — with a freshness/ownership rule for the judgment-shaping layer
- **Plain-English what & why:** Rossi's Guides/Gates/Guards vocabulary is clean but lossy. It has no slot for the layer that makes this harness distinctive: the *judgment-shaping doctrine* — SOUL/values, the "honest assessment over validation" principle, the discipline rule's three questions, the PocketOS destructive-op reasoning. These aren't deterministic gates and aren't mere instructions ("do X"); they shape *how the agent reasons*. The article's frame, applied literally, tempts you to demote all of this to "just a Guide" and then ask "can a Gate replace it?" — collapsing reasoning discipline into a checklist. The failure that prevents: the doctrine layer is the *least-governed* part of the harness — no owner, no freshness rule — so it rots silently and no one notices until an agent reasons from stale values.
- **The mechanism:** (1) Name the fourth G — **Doctrine** — explicitly in the harness vocabulary, so it's a first-class layer with its own governance, not a sub-bucket of Guides. (2) Give it the same one-writer/one-reader/one-freshness-rule treatment the memory model needs: every doctrine file gets a declared read-time (which ritual loads it) and a freshness/ownership rule. The map already names this as the Phase-3 crux — "read-time specified for only ~5 of ~14 knowledge files; freshness rules exist for only 3 stores."
- **Citation:** `[map §4, lines 235–265]` (memory model declared-vs-built; freshness rules for only 3 stores, read-time for ~5 of ~14 files). The Doctrine-layer-as-least-governed observation is pass2 §2, confirmed from the outside by the frame's missing slot.
- **Conservative disposition:** §D minor / framing aid. Pass3 (d) called the Guides/Gates/Guards vocabulary a "framing aid… explicitly extended with the fourth 'Doctrine' G," and (b)4 cited the freshness gap — but treated the fourth G as a naming nicety rather than a governance workstream.
- **RE-JUDGMENT under the new charter: ELEVATE.** "Clarity beats minimalism — more layers are fine when each earns its place" directly favors naming Doctrine as a real layer. The conservative read filed it as vocabulary; the world-class read is that the *whole point* of the audit is that this layer is ungoverned, and naming it is the precondition for giving it owners and freshness rules. Bigger: not "use the framing," but "stand up a Doctrine governance pass" — every doctrine file declares its loading ritual and a staleness rule, surfaced at session start exactly like the ritual `last_run > 7 days` check already does. This is the lens that turns "advisory layer has no deterministic owner" `[map §4]` from a known weakness into a fixable workstream.

### Move: Cost as call-volume / blast-radius-scaled fan-out — not vendor swap
- **Plain-English what & why:** The article drops in "Rossi cut AI spend >90% by moving Claude→Codex" as a tool-choice lever. That's correlation-as-cause: a >90% cut from a model swap almost always means the *workload changed* (fewer/cheaper calls, less fan-out), not that one model is 10x cheaper per equivalent unit. The real cost driver for *this* reader is subagent fan-out and parallel worktrees. The failure prevented: optimizing the wrong variable (vendor) and missing that the lever is call volume scaled to blast radius.
- **The mechanism:** Scale subagent fan-out by the blast radius of the task — a trivial reversible change gets a small fan-out; an irreversible/high-blast change gets the full lens fleet. Tie fan-out width to the same irreversibility classifier as the review router (the two moves share one path-classification primitive).
- **Citation:** No ground-truth row asserts a cost-governance mechanism exists; this is a **confirmed absence** of any fan-out-scaling gate (the gate inventory `[map §3e]` lists no cost/volume governor). Tied to the `/goal` cap idea referenced in pass1 §"one more."
- **Conservative disposition:** §F-adjacent reject / under-argued. Pass2 §6 and pass3 (c) correctly dismantled the *vendor anecdote* as weak-proxy reasoning — but in doing so, threw out the *real* lever (blast-radius-scaled fan-out) along with the bad framing.
- **RE-JUDGMENT under the new charter: NEW.** The synthesis correctly killed the vendor anecdote but summarized away the buried-but-real move. Under "parallel agent fleets across 5+ repos," fan-out economics are a genuine first-class concern — and the article half-saw the right lever. Recover it as a candidate: a `blast-radius → fan-out width` policy that reuses the irreversibility classifier. Honest caveat: this is the lowest-confidence of the four moves and should be a backlog candidate, not an immediate build — but it's wrong to leave it fully cut, because at fleet scale call volume *is* the cost.

## Autonomy angle
The article itself is **autonomy-blind** — pass2 §7 is the sharp finding: its entire frame assumes a human-in-the-loop solo dev whose scarce resource is *attention*, and it optimizes to spend attention well. It explicitly tells the reader to use worktree isolation "for safety, not parallel throughput," echoing Nakazawa calling himself "ineffective" at multi-agent runs. Under the new charter this is exactly inverted: when the reviewer is *also an agent* and runs unattended, there is no human attention to economize, so the deterministic gates become **more** load-bearing, not less. The source teaches nothing directly about bug→PR, Slack/Linear summon, self-improving loops, or cloud scheduling — but its blind spot is itself the autonomy lesson: every advisory rule it leaves as prose (bugfix-test, risk-tiered review, doctrine freshness) must become a *gate* the moment the human leaves the loop. The article's "risk-tiered review that lets tests carry the reversible paths" only works with a human watching; the autonomy-first translation is "the classifier and the gates carry it, because no one is watching."

## The single biggest move (one paragraph)
**The bugfix-test-guard + blast-radius review-router, built as one deterministic risk router in the gate floor.** This is the move the vision synthesis should pick up first because it converts the source's two best ideas — failing-test-first-for-bugs and review-scales-with-reversibility — from *advisory prose the agent may ignore* into *unskippable gates keyed off the diff*. They share a single primitive (a committed path/glob irreversibility manifest), so building one gives you most of the other. It's world-class because it directly attacks the map's central finding — that the harness is "overwhelmingly advisory" with "no deterministic backstop for the bulk of CLAUDE.md rules" `[map §3e]` — at exactly the two surfaces where a bad change is most expensive (a $30k-client render, an RLS-adjacent query, an auth/middleware edit). And it is the *only* version of the article's advice that survives the autonomy charter: the moment an unattended agent is the one fixing the bug and reviewing the diff, a gate keyed off the diff is the difference between "rigour" and "a comment the agent didn't read."
