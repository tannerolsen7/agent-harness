# Ambition Re-mine — AI-Pilling a Team (The Readiness Framework, Filtered for a Team of One)

## What this source is (plain English, 2-3 sentences)

A Notion synthesis of Claire Vo and Zach Davis's "AI-Native EPD Org" framework (a three-pillar org-readiness model: Technical, Cultural, Operational readiness), wrapped in a curator's verdict that filters it down to "what survives for a team of one." The framework's load-bearing thesis is "your codebase is the bottleneck, not the models — if a new hire can't get productive in your repo, agents can't either." The curator's move is to keep only the Technical pillar (specs-as-code, centralized agent rules, guardrails, compound skills, background agents) and discard the Cultural and Operational pillars as "large-org change management you don't need yet."

## The full-ambition moves this source teaches

### Move: Centralized, tool-agnostic agent rules — at GLOBAL/cross-repo scope, not just one repo

- **Plain-English what & why:** The world-class version is ONE rules system that every tool and every repo reads from — Cursor, Claude Code, a cloud agent, all obeying the same standing instructions, and those instructions carrying across all your repos, not living inside a single project. The failure it prevents: every tool and every repo drifting into its own private dialect of "how we work here," so an agent that's well-behaved in repo A is feral in repo B, and a rule you fix in one place silently stays broken in four others. The Vo/Davis framing is explicit that this means across Cursor/Claude Code/Devin AND across repos — "one source of standing instruction."
- **The mechanism:** Build the canon-mandated `~/.claude/CLAUDE.md` as the personal-behavior keystone, and make the project's harness *installable* into any repo via the plugin + marketplace + thin `/init` template path (the portable mechanism named in the new charter). The global file carries cross-cutting agent disciplines; the per-repo `/init` template carries the repo-specific files; the plugin carries the portable mechanism (skills/agents/hooks) but cannot carry permissions. Today the harness "has never been installed anywhere but event-vendor."
- **Citation:** CANONICAL §3a — `~/.claude/CLAUDE.md (global behavior)` = Canon ✅ §09 / **Proj ❌ / Glob ❌** "Canon-mandated, absent globally — values live only in project SOUL" (line 142). Reinforced by §"Global config" row (line 79: "No global CLAUDE.md") and §5 registry (line 275: "the global layer's missing keystone") and the narrative (lines 123–127: "the global layer is missing the one file canon says it must have").
- **Conservative disposition:** Pass 3 (b)#1 actually *did* surface this as "the article's most useful contribution" — it correctly re-derived the absent `~/.claude/CLAUDE.md` as the readiness keystone. But MASTER-FINDINGS collapsed it into a single cautious "wiring-tweak" rather than the keystone of a distribution workstream. The conservative framing treats it as "build the one missing file," not "stand up the global+plugin+marketplace+`/init` distribution layer that makes the harness portable across the 5+ repo fleet."
- **RE-JUDGMENT under the new charter: ELEVATE.** Pass 3 named the gap but undersized the move. Under "Tanner runs parallel agent fleets across 5+ repos," a single-repo rules system is not "we're ahead" — it is the harness's defining structural failure. The move is not "create `~/.claude/CLAUDE.md`" (one file); it is the full **distribution workstream**: global behavior file + plugin/marketplace mechanism + thin `/init` per-repo template + the GitHub-as-canon migration that replaces `/notion-sync`. That is at least 5x bigger than the "wiring-tweak" disposition. The old reasoning was conservative because it scored the gap at existence ("the file is absent") instead of at world-class ("the harness is not installable, which is the whole point of a harness").

### Move: Review-bandwidth ≥ generation-bandwidth as a first-class, deterministically-enforced design invariant

- **Plain-English what & why:** The world-class teams discovered that cranking up how MUCH code agents produce is worthless — actively negative — if your ability to *review and verify* that code doesn't scale with it. Their internal finding: +98% more PRs, +154% bigger PRs, and *zero* improvement in DORA delivery metrics. The binding constraint is review bandwidth, not generation. The failure it prevents: building a "throughput trap" — a fleet that floods you with agent output faster than any human or gate can vet it, so quality silently collapses while the dashboard says velocity is up.
- **The mechanism:** Make review/verification capacity a *modeled, enforced* invariant rather than an advisory hope. Concretely: (1) close the CI sentinel hole so `.cr-ok` is verified in CI, not just gitignored locally; (2) elevate the review layer from advisory `/cr` (rationalizable — see memory `feedback_sentinel_bypass`) to deterministic gates the model cannot talk its way past; (3) add automated review-throughput mechanisms that scale with the fleet — visual render gates, property-based tests for money-math, MCP-trifecta verification gates — so the verification side grows when `/queue` grows. The design rule: any change that raises generation bandwidth must raise verification bandwidth in the same step, or it's net-negative.
- **Citation:** CANONICAL §3e (lines 217–221): "Both agree the system is overwhelmingly advisory — neither has a deterministic backstop for the bulk of skill bodies, CLAUDE.md rules, or the autoMode lists." And §3f (lines 229–231): "The Node 8.5(c) gap (CI never verifies `.cr-ok`) is a disk fact … canon's `.cr-ok` chain has the same hole (gitignored, never reaches CI)." The generation side (richness) is confirmed by §3e disk mechanisms (`/queue`, worktrees, 23 agents); no map row establishes review throughput as a first-class enforced constraint.
- **Conservative disposition:** Pass 2 §4 called this "the strongest thing the page contains" and "buried as a caveat"; pass 3 (b)#2 confirmed "no row in the map establishes review throughput as a first-class, deterministically-enforced constraint" and recommended elevating it to "an explicit V2 design invariant." So it was *recognized* — but MASTER-FINDINGS folded it into the general "wiring-tweak" bucket rather than treating the verification fleet as a co-equal build alongside the generation fleet. The conservative synthesis kept the *principle* and deferred the *mechanisms* (property-based testing, visual render gate, MCP trifecta gate — all in §C "deferred / hypothesis-gated").
- **RE-JUDGMENT under the new charter: ELEVATE.** This is the source's sharpest first-order architectural claim and the conservative synthesis under-weighted it exactly as the page itself did. Under autonomy-as-first-class (bug → reviewed PR, self-improving loops, cloud `/schedule` running unattended), the throughput trap is not hypothetical — it is the *guaranteed* failure mode of an autonomous fleet with an advisory review floor. When agents open PRs while the laptop is closed, an advisory `/cr` that can be rationalized away is no backstop at all. The deferred verification mechanisms (visual render gate, property-based money-math tests, MCP trifecta gate) should move IN-SCOPE-NOW as the verification half of the fleet. Old reasoning was conservative because it accepted "we have `/cr`" at existence-level while the charter demands review that scales deterministically with an autonomous generation fleet.

### Move: Agent-role / operational choreography is a PRESENT-TENSE problem (Pillar 3 reframed for a fleet)

- **Plain-English what & why:** The page says "skip Operational readiness — role evolution, process design — you have no team to coordinate." This rests on a category error: the agents ARE the team. A harness that runs parallel agents across worktrees has exactly the coordination problem a 50-person org has — who owns which branch, what scope each agent may touch, how one session hands off to the next, whose credentials have what blast radius. The failure it prevents: two agents silently stomping the same branch, an agent staging files outside its lane, a session ending without persisting what it learned — the precise drift the harness's missing structural guards exist to stop.
- **The mechanism:** Build the structural coordination guards the map flags as canon-mandated but absent on disk: `branch-registry-guard.sh` (one-session-per-branch collision guard backed by `active-branches.json`), `enforce-scope.sh` (block staging files outside the task's ALLOWED FILES), and `session-end.sh` (Stop hook proposing memory candidates so handoff isn't fully manual). These are deterministic hooks, not advice — the operational-readiness pillar translated into fleet primitives.
- **Citation:** CANONICAL §3e — `branch-registry-guard.sh` = Canon ✅ / **Proj ❌** "Canon structural, absent on disk" (line 208); `enforce-scope.sh` = Canon ✅ / **Proj ❌** (line 207); `session-end.sh` = Canon ✅ / **Proj ❌** "Canon's memory-capture hook — absent; disk's memory is fully manual" (line 209). Also §5 registry lines 277–279.
- **Conservative disposition:** Pass 3 (b)#3 got this right at the analytical level — "The page's skip-list would have us defer building structural guards the map already flags as absent. This is a case where the article's advice is actively wrong for us." It bound Pillar 3 to the three absent hooks. So the re-frame survived into pass 3. The conservative *bias* here is narrower: it treated these as three missing hook files (a wiring fix) rather than as the autonomy-enabling substrate — the coordination floor without which an autonomous fleet cannot safely scale.
- **RE-JUDGMENT under the new charter: ELEVATE (modestly).** Pass 3 already overturned the page's skip-it advice, so this is not a buried gap — but its *sizing* was conservative. Under parallel fleets across 5+ repos plus cloud `/schedule` spawning unattended sessions, these guards are not three nice-to-have hooks; they are the deterministic coordination floor that makes autonomy safe. `session-end.sh` in particular pairs with self-improving loops — a fleet that can't auto-capture what each session learned cannot compound. Elevate from "three absent hooks to wire" to "the fleet-coordination + memory-handoff substrate, designed in as a precondition for autonomy." The failure mode (two agents on one branch; lost cross-session learning) is concrete and already accruing per the map.

### Move: Compound engineering — agents write the skills (verify the mechanism, kill the phantom)

- **Plain-English what & why:** The world-class practice is: anything you do more than once becomes a reusable Markdown skill, AND you have the agents *write those skills themselves* — the system improves itself. The failure it prevents: re-deriving the same solution every time and never banking the leverage; your own time as the permanent bottleneck. The page claims we've "built the rigorous version" of this and cites `learned-patterns.md` as the executable-constraints embodiment.
- **The mechanism:** The real compound mechanism (`/compound`) exists and is canon-aligned; the *self-improving* extension is the world-class delta — a loop where agents observe repeated work and propose new skills (paired with `session-end.sh` memory capture above). But the specific file the page validates against, `learned-patterns.md`, does not exist on disk or in canon. The action is twofold: (1) keep `/compound`, (2) build the self-authoring-skills loop as the autonomy extension — do NOT bank credit for the phantom file.
- **Citation:** Confirmed absence — CANONICAL §6 phantom list (line 295): `learned-patterns.md` listed under "Referenced on disk, never built on disk *or* in canon"; and the closing section (line 358): "`learned-patterns.md` is §6 phantom." Real mechanism: `/compound` in runtime skill list (pass 3 (a)).
- **Conservative disposition:** Pass 3 (b)#4 handled this correctly as a *factual correction*, not a build: "the page's confirmation rests partly on a file that does not exist, so its 'you've built the rigorous version' overstates our compound-engineering maturity." MASTER-FINDINGS treated the correction as "drop the validation," full stop.
- **RE-JUDGMENT under the new charter: ELEVATE the forward half (the correction stays UPHELD).** The correction is right and stays — don't credit a phantom. But the conservative synthesis stopped at "we have `/compound`" and missed the world-class delta the source actually teaches: *agents write the skills*. That is a self-improving loop, which the new charter names as first-class autonomy ("self-improving loops, designed in, never deferred"). Having `/compound` (a human-invoked command) is the weak version; an agent-authored skill-promotion loop driven by `session-end.sh` observations is the world-class version. Elevate the self-authoring-skills loop to in-scope-now; keep the `learned-patterns.md` correction as an upheld kill.

But three of its moves are autonomy substrate: (1) **background agents in cloud sandboxes** — the page's named top relative multiplier, "the closest thing to hiring without hiring, but only safe behind real gates" — is precisely the cloud `/schedule` + sandbox capability the new charter centers; the page's insistence on "real gates" is the safety precondition (disable-model-invocation for side-effect skills, deterministic review). ## The single biggest move (one paragraph)

**Elevate "review-bandwidth ≥ generation-bandwidth" from a buried caveat to an explicit, deterministically-enforced V2 design invariant — and build the verification half of the fleet to match the generation half.** This is the move the vision synthesis should pick up first because it is the one place this source supplies a *first-order architectural law*, not a wiring fix: a fleet that raises agent output without raising review/verification throughput is net-negative, proven by the +98% PRs / +154% size / zero-DORA finding. The harness today is lopsided exactly this way — a rich generation side (`/queue`, 23 agents, worktrees, and now cloud `/schedule`) bolted to an overwhelmingly advisory review side (`/cr` rationalizable, `.cr-ok` never verified in CI). Under the new autonomy charter this asymmetry is no longer a risk to manage but a guaranteed failure: the moment agents open PRs while the laptop is closed, an advisory review floor is no floor at all. World-class means the verification fleet (deterministic `.cr-ok` CI gate, visual render gate, property-based money-math tests, MCP-trifecta verification) scales in lockstep with the generation fleet — and that invariant is what makes autonomy safe enough to be first-class.
