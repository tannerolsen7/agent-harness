# Ambition Re-mine — Basis: Canon/Not-Canon, Context Maintenance & Agent-Native Org Design

## What this source is (plain English, 2-3 sentences)

Basis is a production accounting-AI company that builds long-horizon agents (agents that work autonomously for many hours). Their Atlas team wrote up how they re-engineered their monorepo so that *agents* — not just humans — can onboard to any task from scratch thousands of times a month without tripping over stale or contradictory context. The core teaching: **context (AGENTS.md files, skills, docs) is now a production artifact with the same failure economics as code, so it needs the same lifecycle machinery** — declared ownership, CI validation, automated drift detection, and an automated repair loop.

## The full-ambition moves this source teaches

### Move: Context-as-a-maintained-artifact — the automated daily scanner + worker loop

- **Plain-English what & why:** Basis treats its context files (the agent-facing docs, AGENTS.md, skills) the same way it treats code: not as something you write once and let rot, but as something with a CI check on every merge, a daily robot that sweeps the whole corpus for staleness/contradictions/duplication/broken-references/missing-context-for-recent-changes, and daily workers that pick up the robot's tickets and fix them. The failure this prevents: a human reads a slightly-stale doc occasionally and shrugs; an agent re-onboards from that same doc *thousands of times a month* and reasons wrongly with full confidence every single time. Pass1: "every inconsistency or gap gets hit thousands of times instead of occasionally." Multiplicity converts a tolerable human-scale defect into a systematic, compounding one.
- **The mechanism:** Three concrete pieces, in order. (1) A **CI check** that validates every knowledge artifact on every merge — frontmatter present, owner field set, prose is instructional not descriptive, no broken cross-references. (2) A **scheduled scanner** (`/scan-context`, which is documented in our canon but absent on disk) that runs on a clock — via cloud `/schedule` — and opens tickets for: doc-stale, doc-fiction (phantom refs), internal contradictions (the canon-vs-canon §7 cases), and duplicated instructions (the triple-duplication in §4). (3) **Workers** that pick up scanner tickets and open scoped fix PRs. Our harness already has the substrate for all three: cloud `/schedule` exists and runs committed skills, `/cr` can review the worker's PR, and the prod-key firewall plus disable-model-invocation make a side-effecting worker safe.
- **Citation:** `[map §5]` — `/scan-context` "documented in canon but ABSENT on disk." `[map §0 correction log]` — the audit artifact `HARNESS-AS-IS.md` itself rotted and inherited four stale absence-claims that ground-truthed false; this is a *live, dated proof* our context rots undetected. `[map §3e]` — "Both agree the system is overwhelmingly advisory… no deterministic backstop." `[map §3f]` — CI exists for code (tsc/lint/vitest) but **no CI check validates any knowledge artifact**.
- **Conservative disposition:** SCALED-DOWN / DEFERRED. MASTER-FINDINGS folds the scanner into MOVE 3 as "the drift/context-rot detector" but pass3 explicitly cuts the loop in half: *"Keep maintenance detection automated; keep repair human-gated"* and *"Importing Basis's 'daily workers auto-implement scanner findings' would be actively dangerous here."* Pass3 also leans on "over-built for most shops" and "not something to import wholesale at solo scale."
- **RE-JUDGMENT under the new charter: ELEVATE.** The detection half is correct and should ship now — but the conservative cut of the *repair* half ("actively dangerous," "solo scale") fails the new charter on two counts. First, the "solo scale" reasoning is exactly the suppressed SCALE BIAS: a world-class engineer running parallel agent fleets across 5+ repos hits context rot *more* than Basis's thousands/month, not less, because every repo multiplies the surface. Second, the "repair is dangerous" objection was written under the OLD charter where autonomy was deferred and the machine slept. Under the new charter both premises are dead: cloud `/schedule` runs committed skills on Anthropic infra, and `disable-model-invocation:true` makes a side-effect worker safe by removing it from the model's own context. The worker does not need unrestricted mutation — it opens a *PR*, which runs through `/cr`, the deterministic pre-commit/pre-push floor, and human merge. That is the same trust boundary every other agent change already passes. The honest residual constraint is narrow and real (see Autonomy angle): the worker must be **forbidden from editing guard files / settings / the destructive-op floor** — but that is a path-scope on the worker, not a reason to keep the whole repair loop manual. How much bigger: from "manual `/scan-context`, weekly, human-run" (pass1's own scaled-down target) to a **scheduled scanner + auto-PR-opening worker fleet, gated by `/cr` and a guard-file denylist** — the self-improving context loop that is a first-class charter goal.

### Move: Canonicality as a declared, decaying truth-claim — with an explicit precedence rule

- **Plain-English what & why:** Basis splits every artifact into **canon** (asserts "this is how the system works *now*" — AGENTS.md, skills, docs, comments) and **not-canon** (asserts "this is what we intend/intended" — specs, tickets, notes). The failure it prevents: an agent reads a spec for an abandoned direction or a ticket for a never-built feature, treats it as the current truth, and "reasons incorrectly with complete confidence." Pass2 sharpens the real insight past the article's own framing: canonicality is **not where a file lives, it's what truth-claim it makes about the present, and that claim decays** — a docs page describing a since-refactored pattern is canon-by-location but not-canon-by-truth. The label lies over time, which is *why* the scanner has to exist.
- **The mechanism:** (1) An `authority-map.md` (or per-artifact `canonical: true/false` frontmatter) that forces the question "is this a truth-claim about now, or a record of intent?" for every artifact in `.claude/` and `docs/`. (2) Critically — and beyond what the article offers — an **explicit, machine-checkable precedence rule** for canon-vs-canon conflicts. Our actual failures (§7) are not canon-vs-spec; they are *two canon pages disagreeing* (two feature loops, two reviewer names, Pages 12↔13). A binary canon/not-canon label does nothing for those. We already have an undocumented "later-dated page wins" convention — make it a declared `supersedes:` / `version:` field the scanner can enforce.
- **Citation:** `[map §7]` — nine canon-internal contradictions with no label saying which side wins except the undocumented "later-dated page wins." `[map §0]` — "the canon is also internally inconsistent… bidirectional drift." `[map §3a]` (absence) — no `authority-map.md` row exists anywhere in the governance-doc inventory.
- **Conservative disposition:** §E PARTIALLY-BUILT + pass3 "too crude." Pass3: the distinction "is not absent here — it is implemented as separate stores rather than as a declared per-artifact label," and "Two-bucket canon/not-canon is too crude for our actual failure… we need a precedence rule." MASTER-FINDINGS does not surface the authority-map / precedence-rule as a named move at all — it is implicit inside MOVE 3.
- **RE-JUDGMENT under the new charter: ELEVATE (and partly NEW).** Pass3 is *right* that the two-bucket label alone is too crude — that is a genuine, well-named limitation, not conservative bias. But the conservative synthesis then under-delivered: it noted the gap and dropped it into MOVE 3's slipstream without making the **precedence rule a first-class deliverable**. Under "clarity beats minimalism / more mechanisms is fine when each earns its place," the precedence rule earns its place loudly: §7 documents nine live contradictions that *no other move resolves*, and a machine-checkable `supersedes:`/`version:` field is exactly the kind of obvious-job mechanism the new charter welcomes. It also has a clear failure mode it prevents (an agent picks the wrong side of two contradicting canon pages — the §7 cases are real, not hypothetical), which satisfies the §9 golden rule. So: NEW first-class candidate — "a declared precedence/authority schema that the scanner enforces" — elevated out of MOVE 3's shadow.

### Move: The default-no authoring gate — instruct, don't describe; embed priority; localize

- **Plain-English what & why:** Basis names three precise authoring diseases and a stance. (1) **Describing instead of instructing**: "SRC is where we put source code" teaches an agent nothing; "Never use inline imports to work around circular deps; fix the module structure" changes behavior. (2) **Everything marked must-follow**: when every line is important, none is — priority has to be embedded in the prose itself. (3) **Cross-folder knowledge in the wrong place**: fix by moving it into on-demand skills. The stance is **default-no**: every token auto-loaded is a tax, so default-exclude forces each line to justify itself; stated negatively on purpose because the softer "be selective" invites drift.
- **The mechanism:** A default-no authoring gate applied to CLAUDE.md / AGENTS.md / skill bodies — cut descriptive lines, rewrite to instruction form, embed priority in prose, push directory-specific rules into nested files or on-demand skills. Pass1 calls this "the most actionable item, requires no new tooling."
- **Citation:** `[map §9]` — our canon's Page-13 Model Capacity Audit, golden rule "if you can't name a failure mode the constraint prevents, the constraint is overhead." `[map §3b]` — 26 project skills loaded on trigger; cross-cutting knowledge already in on-demand skills. `[map §3e]` — overwhelmingly advisory.
- **Conservative disposition:** §E ALREADY-BUILT (stronger form). Pass3: "Default-no / curation already operates as a hard rule, not a vibe… our Page 13… golden rule… is default-no applied to *rules themselves*, which is stronger than Basis's default-no applied to *context lines*." MASTER-FINDINGS MOVE 4 is the §9 re-audit, which *is* default-no-as-deletion-engine.
- **RE-JUDGMENT under the new charter: UPHELD-CUT (as a *new* move) — genuinely already world-class, with one real upgrade carved out.** This is the rare case where the "already built" claim survives the new charter's "is it world-class?" bar honestly. Our §9 golden rule ("name a failure mode or it's overhead") is *stronger* than Basis's default-no — it applies the discipline to rules themselves, not merely to lines, and it predates the article. Re-proposing a default-no authoring gate wholesale would be a phantom. **But** the §9 golden rule is a *human-run* judgment criterion; Basis's contribution that we do *not* have at world-class quality is the **CI frontmatter/prose check that enforces default-no deterministically on every merge** — the "describing instead of instructing" lint, the "owner present" check. That specific deterministic enforcement is genuinely absent (`[map §3f]`: no CI validates any knowledge artifact) and folds into the scanner move above. The named failure mode that justifies *not* re-building the broader gate: re-proposing default-no as doctrine duplicates the §9 golden rule and burns review bandwidth on a rule we already hold more rigorously — the anti-duplication gate would (correctly) kill it. So the cut stands on the doctrine; the deterministic-enforcement sliver elevates into the scanner.

### Move: The dependency-ordered verification stack — scanner → standards-enforcer → verifier

- **Plain-English what & why:** Basis runs two pre-PR sub-agents the article presents as parallel siblings. Pass2's penetrating read: they are not siblings, they are a **dependency chain doing two different jobs**. The **verifier** (diff-scoped tests + hooks) checks *behavioral correctness* — does the code work. The **standards-enforcer** checks *canon-conformance* — does the code obey the AGENTS.md/skill rules. And the enforcer is downstream of the scanner: *you cannot enforce code against canon that is itself stale or contradictory.* The failure this ordering prevents: a naive adopter builds the enforcer first and spends its effort enforcing code against rot — holding new code to rules that are themselves wrong.
- **The mechanism:** Sequence our context machinery so the dependency holds: scanner keeps canon true → standards-enforcer holds code to canon → verifier confirms behavior. Concretely, our `/cr` already does canon-conformance (layer violations, doc drift) and the pre-commit/pre-push chain does behavioral verification — but neither is *guaranteed to run against fresh canon*, because there is no scanner upstream keeping the canon honest. The diff-scoped piece is a narrow tooling check: does vitest support changed-path test selection (pass3 flags this as a 10-minute verification, not research).
- **Citation:** `[map §3c]` — `/cr` 9-pass + adversarial over branch diff (our standards-enforcer, strongest form). `[map §3e]` — pre-commit/pre-push chain (our verifier). `[map §5]` — `/scan-context` absent (the missing *upstream* of the chain). `[map §3f]` — no CI validates knowledge artifacts.
- **Conservative disposition:** §E ALREADY-BUILT for both downstream nodes. Pass3: verifier is "substantially built, and broader than Basis's"; standards-enforcer "we have its strongest form" (`/cr`). The *ordering insight* — that both depend on an upstream scanner we lack — is present in pass2 but MASTER-FINDINGS does not carry the dependency-chain framing forward; it treats the scanner as one item inside MOVE 3 rather than as the *root* the existing verification stack silently depends on.
- **RE-JUDGMENT under the new charter: ELEVATE the ordering, UPHELD-cut the downstream rebuild.** Re-proposing the verifier or standards-enforcer is a phantom — `/cr` is genuinely world-class here ("more review rigor than any tool the corpus studies"), and pass3's "already built, broader than Basis" survives the world-class bar. That part is honestly cut. **But** the conservative synthesis missed the load-bearing consequence of pass2's dependency-chain read: *our world-class `/cr` is enforcing code against canon that §7 proves is internally contradictory and §0 proves rots undetected.* The strongest enforcer in the corpus is partly wasted because its input (the canon it enforces against) has no upstream freshness guarantee. That reframes the scanner from "a nice-to-have detection loop" to **the missing root of a chain we already paid to build** — which is a much stronger argument for shipping it now than MASTER-FINDINGS makes. Elevate: make "scanner is the upstream that makes `/cr`'s canon-conformance trustworthy" an explicit dependency in the build plan, not an isolated MOVE-3 line item.

## Autonomy angle

This source is **substantially about a self-improving loop**, which is a first-class charter goal — though not about bug→PR or Slack/Linear summon. The relevant teaching:

- **Self-improving context loop (directly on-charter).** Basis's scanner→worker loop is precisely "self-improving loops" from the charter: a scheduled agent detects context decay, opens scoped fix PRs, and the system gets healthier without a human kicking it off. Under cloud `/schedule` (confirmed to exist, runs committed skills on Anthropic infra) this is buildable *now*, not deferred. The conservative synthesis deferred the *repair* half on durability and solo-scale grounds — both moot under the new charter (scheduler durability is resolved; solo-scale dismissal is the suppressed SCALE BIAS).
- **The one honest safety boundary, named precisely (pass2's deepest find).** Pass2: the loop has "no external ground-truth anchor" and "can converge on internally consistent but wrong." The `owner` field is "not metadata; the owner is the out-of-loop verifier that stops the loop eating its own tail." This is the real constraint on autonomy here, and it is *constructive*, not prohibitive: the autonomous worker is safe **iff** every canonical artifact it can touch has a declared human owner who reviews the worker's PR, AND the worker is denied write access to guard files / settings / the destructive-op floor (`[map §9]` keep-verbatim; memory "no agent edits to guard files"). That is a path-scope + ownership requirement, not a reason to keep repair manual. So: the autonomy is in-scope *with* the owner-field and guard-file-denylist as its safety design — which is exactly the charter's "designed in, with the failure mode named."
- **Not present:** bug→PR front-door, Slack/Linear summon — none. This source teaches the *maintenance/self-healing* flavor of autonomy, not the *triggered/summoned* flavor.

## The single biggest move (one paragraph)

**Ship the automated context-maintenance loop — scheduled scanner plus auto-PR-opening worker — as a first-class self-improving system, not a deferred detection-only half.** This is the move the vision synthesis should pick up first because it is the one mechanism in this source that is (a) genuinely absent at any quality (`[map §5]`: `/scan-context` documented in canon, absent on disk; `[map §3f]`: no CI validates any knowledge artifact), (b) backed by a *live, dated proof of the failure it prevents* (`[map §0 correction log]`: our own audit artifact rotted and shipped four false absence-claims), and (c) the unrecognized **root of a dependency chain we already paid for** — our world-class `/cr` enforces code against canon that §7 proves contradicts itself, so the scanner is what makes the existing enforcement trustworthy rather than an extra feature bolted on. The conservative synthesis cut the repair half on two premises the new charter retires: "dangerous at solo scale" (the suppressed SCALE BIAS — fleets across 5+ repos rot faster, not slower) and "the machine sleeps" (moot: cloud `/schedule` runs committed skills on Anthropic infra). The world-class version is the full loop with its safety design built in, not bolted on: a declared `owner` + `supersedes:`/`version:` precedence schema on every canonical artifact (the out-of-loop human anchor pass2 identifies as the thing that stops the loop eating its tail), the worker scoped *away* from guard files and the destructive-op floor, and every fix landing as a `/cr`-reviewed, human-merged PR. That is canon borrowing code's own SDLC — ownership, CI, drift-detection, automated repair — which pass2 correctly identifies as this source's single genuinely novel contribution.
