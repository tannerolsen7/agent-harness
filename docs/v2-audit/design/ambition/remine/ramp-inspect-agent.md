# Ambition Re-mine — Ramp: Inspect Agent, Agent Architecture & Org-Wide AI Adoption

## What this source is (plain English, 2-3 sentences)
Ramp (a 50,000-customer finance-automation company, "one of the most documented AI-native engineering organizations publicly available") built **Inspect**, an internal background coding agent that does not just write code — it spins up a real sandboxed clone of the dev environment, runs the tests, queries feature flags, takes before/after screenshots against the actual app, and only then opens a PR. The source bundles four more things: a "meet engineers where they are" multi-surface front door (Slack, Chrome extension, voice, GitHub comments, web VS Code), an architecture pivot from hundreds of narrow agents to one general agent composing "thousands of skills," an org-adoption ladder (L0–L3), and a Claude Code PM skill that fans out 6–10 parallel research subagents. The page's own deepest read is that all of this is **three applications of one principle: give the agent the real environment and let it operate like a human, instead of building bespoke scaffolding per task.**

## The full-ambition moves this source teaches

### Move: The closed self-verification loop — agent proves its own work before it asks for review
- **Plain-English what & why:** Most coding agents write code and stop. Inspect closes the loop: every session runs in a sandboxed VM carrying the full stack (Vite, Postgres, Temporal, Redis, RabbitMQ), and the agent *runs its own verification against the same observability stack the humans use* — automated tests, feature-flag queries, visual screenshots, live preview URLs — before the PR exists. The failure this prevents: a human reviewer becomes the regression-catcher of first resort, which does not scale, so the agent's output is never trusted and adoption stalls. When the agent verifies itself, the human's job shifts from "catch the regression" to "review intent and design." The source attributes ~30% of all merged PRs (independently sourced) and voluntary org-wide adoption *with no usage mandate* directly to this trust.
- **The mechanism:** A **machine-enforced self-verification gate** that fires at task-completion — a `Stop` / `PostToolUse` hook that, before a subtask is reported "done," runs `npm run test` + `npx tsc --noEmit` (this repo's stack), blocks on red, and for any UI-touching diff requires a Chrome-MCP screenshot artifact. Critically: a *hook*, not a CLAUDE.md sentence or a skill-body instruction. Pass-2 sharpens this with two non-negotiable qualifiers: (1) it must be **machine-enforced, not advisory** — the whole point is it cannot be rationalized away; (2) it buys **regression-trust, not correctness-trust** — the human semantic checkpoint stays, and the gate must NOT write `.cr-ok` (that would launder a regression check into a capability unlock, which §9 forbids).
- **Citation:** Confirmed absence — `[canon §3e]` "Net enforcement picture: the system is overwhelmingly advisory… neither has a deterministic backstop for the bulk of skill bodies, CLAUDE.md rules"; there is **no PostToolUse/Stop hook that asserts tests-green/typecheck-clean at task completion**. The natural home is also absent: `session-end.sh (Stop → memory candidates)` is canon-declared but **absent on disk** `[canon §5; §3e]`.
- **Conservative disposition:** Pass-3 §(b) called this "the one real, high-leverage gap" and **did** route it to a hook — so this is the closest the conservative synthesis came to keeping a big move. But MASTER-FINDINGS collapsed it into the "6 cautious wiring-tweak MOVES," scoped it tightly to "regression-trust only," and gated even the build on first answering a "what can a Stop hook intercept?" research question (pass-3 §d). The framing throughout is *minimal gate, narrow envelope, do the cheap half.*
- **RE-JUDGMENT under the new charter: ELEVATE (substantially).** This is the headline autonomy mechanism, not a wiring tweak. Under "bug → reviewed PR" as a first-class design goal, the self-verification loop is *the thing that makes an autonomous PR trustworthy enough to exist*. The conservative synthesis was right that it belongs in a hook and right to keep the human semantic checkpoint — but it under-built it in three ways the charter reverses. (1) **Scope: not just test+typecheck.** Ramp's loop reads Sentry/Datadog/LaunchDarkly. Pass-2 dismissed that as "doesn't transfer at solo scale" — but the *real* scale is parallel fleets across 5+ repos with cloud `/schedule` running committed skills and calling connectors. A fleet-grade verification gate should pull the deployment's runtime logs (Vercel MCP `get_runtime_logs`, `get_deployment_build_logs` are in this session's tool surface) and the visual artifact, not only the local two-command check. (2) **It should gate the autonomous PR open, not just a subtask.** Wire it into `pr.sh` / the `.cr-ok` chain as the *evidence bundle* (test output + screenshot + log scan) the PR carries — so a human or a scheduled review agent reviews intent over proof, exactly Ramp's shift. (3) **The "name a failure mode" golden rule §9 is satisfied loudly here:** the failure mode is "an autonomous agent reports done, opens a PR, and the regression ships because nothing deterministic re-ran the suite" — precisely the advisory-enforcement gap §3e already documents we live with. The old reasoning was conservative bias in *sizing* (one tweak among six) and in *scope* (test+typecheck only because "the observability half doesn't transfer at solo scale"). Build it as the central verification subsystem.

### Move: Give the agent the REAL interface — "computer-use yourself" before you wrap it
- **Plain-English what & why:** Ramp's "Fatal Flaw" insight: when you bolt an agent onto the *backend*, you must hand-build one tool-wrapper per endpoint forever — an endless march to feature parity that is really an org-structure problem. Their fix: connect the model to the **frontend** — spin up a browser with the user's credentials, navigate the real UI — and you get feature-completeness day one, reuse the frontend team's work, and inherit auth/permissions for free. Generalized (pass-2's sharper thesis): **remove the bespoke intermediary between the agent and ground truth** — whether ground truth is "does it work" (real tests/observability) or "what can it do" (the real UI). The failure prevented: building and maintaining a fragile abstraction layer that lags the real system and rots on every change.
- **The mechanism:** A standing principle plus its one cheap concrete: **prefer giving the agent the real thing over building a wrapper**, and **require a real-browser visual artifact (Chrome MCP screenshot) for any UI change** before "done." Chrome MCP is already present in the tool surface; what's absent is any rule/hook/agent-contract that *requires* its use for a UI slice.
- **Citation:** Confirmed absence — `[canon §3e]` hook inventory "contains nothing visual"; the §3a context-doc inventory (SOUL/CONTEXT/AGENTS/CLAUDE/agent-contract) "contains no such rule." The capability (Chrome MCP) is present in the tool surface this session; the guardrail using it is absent.
- **Conservative disposition:** Pass-3 §(a) marked the *capability* "already partially built (Chrome MCP)" and §(b) flagged the *guardrail* as a real gap — but ranked it "the cheap half." Pass-2 went harder against the principle's *frontend-driving* form: "anti-applicable to a product still under construction… there is nothing finished to computer-use," and "a pre-MVP product has the opposite problem — the frontend is the thing being built." So: principle accepted, mechanism shrunk to a screenshot, the frontend-driving ambition rejected for this product.
- **RE-JUDGMENT: ELEVATE the screenshot guardrail; UPHELD-CUT the frontend-driving-as-feature-completeness form (with a named failure mode).** Two halves, two verdicts. **(a) The visual-artifact guardrail — ELEVATE.** It is the transferable half and it is genuinely missing. Make it a hard sub-clause of the verification gate above: "no UI-touching diff is `done` without a Chrome-MCP before/after screenshot in the evidence bundle." Pass-3 calling it "the cheap half" undersells it — at fleet scale a screenshot is the only way a *human reviewing five repos' PRs* can confirm a visual change without checking out each branch; it is the review-throughput multiplier, not a cheap extra. **(b) Frontend-driving for feature-completeness — UPHELD-CUT, narrowly.** The named failure mode is twofold and concrete: (i) **the safe envelope is read-mostly/idempotent** — pass-2 caught that even Ramp demos it only on a "bounded, testable admin action" (card branding) while admitting stateful multi-step workflows are "qualitatively different," and the operations most worth automating at a finance company (irreversible mutations) are exactly the ones a browser-driving agent should least fat-finger; this collides head-on with our PocketOS destructive-operation rules (§9 keep-verbatim). (ii) **No finished frontend to drive** — the product is the thing under construction. The cut is honest, not conservative bias: the *principle* (remove the intermediary) survives and is adopted via the screenshot guardrail and the "real tests/real env" verification loop; only the specific *spin-up-a-browser-to-do-mutations* mechanism is a bad fit, and it would still be a bad fit at fleet scale because the failure mode is about irreversibility, not about being solo.

### Move: Multi-surface front door — "meet the agent where you are" (Slack, voice, Chrome ext, GitHub, web IDE)
- **Plain-English what & why:** Ramp deliberately refused one interaction pattern. You can summon/steer the agent from Slack, a Chrome extension (highlight a UI element), a web UI, GitHub PR comments, web VS Code, or **voice** — and every session is multiplayer by default, syncing changes regardless of entry surface. The failure prevented: a powerful agent that nobody reaches for because invoking it requires leaving the tool you're already in; the cost of reaching for the agent is what gates adoption. Pass-1 explicitly ties this to **AFK / background workflows** — being able to fire and steer from Slack is what makes "keep working while I'm away" real.
- **The mechanism:** A real **trigger front-door**: bug/issue → reviewed PR, summoned from Slack or Linear/GitHub, plus cloud `/schedule` routines that run committed skills unattended. Concretely: a GitHub-issue/PR-comment trigger and a Slack summon that hand a task to a worktree-isolated agent which runs the verification loop and opens a PR; `disable-model-invocation:true` on the side-effecting skills (open-PR, deploy, send-Slack) so they're safe to leave in the autonomous path.
- **Citation:** Confirmed absence of any trigger front-door in canon/disk — the harness has worktrees + `/queue` + a `WorktreeCreate` hook `[canon §3e, §3f]` but **no inbound trigger** (no Slack/Linear/GitHub-issue → agent path) anywhere in the hook, skill, or script inventory `[canon §3b, §3e, §3f]`.
- **Conservative disposition:** Pass-3 barely engaged this surface — it treated multi-interface accessibility as an org-adoption nicety and folded "AFK workflows" into the already-existing UNATTENDED worktree mode. MASTER-FINDINGS §C is where the broader synthesis explicitly **deferred the autonomous trigger front-door (bug→PR)** as hypothesis-gated. The implicit reasoning: a solo dev doesn't need a Slack summon; the durability objection ("machine asleep") killed schedulers.
- **RE-JUDGMENT: ELEVATE — this is exactly the deferral the new charter reverses (and the KEY RESOLVED FACTS moot the old objection).** "Autonomy is first-class… bug → reviewed PR, summoned from Slack/Linear… designed in, never deferred." Ramp is the proof-of-existence that a multi-surface summon drives *organic* adoption — the 30% number came *without a mandate*, because reaching for the agent was cheap from wherever you already were. The old "solo dev doesn't need it" dismissal fails twice: (1) the real scale is parallel fleets across 5+ repos, where a Slack/Linear summon is the only ergonomic way to dispatch and steer dozens of concurrent sessions; (2) cloud `/schedule` **exists** on Anthropic infra, clones the repo, runs committed skills and calls connectors — so the "machine asleep / no durability" objection that killed the front-door in §C is settled MOOT. This should move to in-scope-now: a GitHub-issue/Slack inbound trigger + verification-gated autonomous PR is the spine the whole charter is organized around, and Ramp is the cleanest world-class evidence that it pays off in adoption, not just capability.

### Move: Skills are standards, not shortcuts — gates emit an evaluable pass/fail artifact
- **Plain-English what & why:** "A prompt is a shortcut. A skill is a standard." A skill should produce an *evaluable output* — something that passes or fails an explicit bar — so it "raises the floor and makes the floor visible." The PM skill, for example, forces the PM past a 7-question framing gate and pushes back when answers are weak; the output is graded against intent, not just generated. The failure prevented: skills that are vibes — they run, produce prose, and no one can tell whether the bar was actually cleared, so quality silently drifts per-invocation.
- **The mechanism:** Give skill gates a defined pass/fail contract that emits a gradeable artifact, the way `/cr` emits MUST-FIX/NEEDS-HUMAN/SUGGESTION tiers and the `.cr-ok` sentinel. Per-skill: the PM/spec skill outputs "all 7 framing questions answered above bar / not"; the verification skill outputs the evidence bundle (tests, screenshot, logs) as a pass/fail object.
- **Citation:** Confirmed absence — `[canon §3b]` lists ~26 skills; **none except `/cr` emit a defined pass/fail bar**; the only evaluable artifacts are the `.cr-ok` sentinel and `/cr`'s tiers `[canon §3c]` — and `.cr-ok`-as-capability-gate is on the §9 *replace* list `[canon §9]`.
- **Conservative disposition:** Pass-3 §(b) called this a "real gap, **low-priority, per-skill**," noting the page itself concluded "likely per-skill." Genuinely minor in the conservative synthesis.
- **RE-JUDGMENT: ELEVATE — from "low-priority per-skill" to a cross-cutting contract, because it's the foundation that makes self-improving loops and autonomy auditable.** "Clarity beats minimalism; more mechanisms is fine when each earns its place." A pass/fail output contract on every gate is precisely how you make a *self-improving loop* measurable — you can only improve what you can grade, and a fleet running unattended needs every skill to emit a machine-checkable verdict so a scheduled review agent (or a human reviewing 5 repos) can triage by pass/fail instead of re-reading prose. The §9 tension is real but cuts *for* this move, not against it: `.cr-ok` is being retired *as a capability unlock*, which is the right call, but it should be *replaced* by a richer evaluable-output contract (the evidence bundle), not by nothing. The "per-skill, low-priority" framing was conservative because it scoped the work to individual skill bodies rather than seeing the cross-cutting standard — at fleet scale the evaluable-output contract is the substrate of observability over autonomous runs.

### Move: "Skill not agent" — consolidate when the model's capability outgrew the specialization
- **Plain-English what & why:** Ramp ran *hundreds* of narrow agents (expense policy, invoice processing, etc.). After early-2026 model releases, maintaining them "became unsustainable" — per-agent context/prompting/failure-modes × hundreds × every model upgrade — and one general agent could "reason across skills and compose them situationally." The failure prevented: paying ongoing maintenance tax on specialization the model no longer needs. Pass-2's sharpening: this is a **capability-clock reading, not timeless architecture** — a threshold claim (overhead is debt *above* some count) dressed as a universal, and the trigger was capability-driven, the same family as our §9 "retire the scaffold the model outgrew."
- **The mechanism:** Treat the skill as the durable unit and the agent as orchestrator; default new capabilities to skills; periodically audit whether the agent roster's specialization still earns its maintenance against the current model.
- **Citation:** Real but different gap than the page's excitement — `[canon §3d]` we have **23 agents on disk** vs canon's contradictory **7–10 roster** ("8 specialist agents" header over a 9-row table; "Ten" templates over 8 roles) `[canon §3d, §7.6]`. The §9 Model Capacity Audit `[canon §9]` is the matching framework (made against Sonnet 4.6, re-audit due on the Opus 4.8 update).
- **Conservative disposition:** Pass-3 §(b) explicitly **refused the architecture pivot**: "the gap is **not** 'collapse 23 agents into skills' (premature below threshold; §9 keeps reasoning-discipline) — it is 'the agent roster is undefined/contradictory and needs one canonical count.' Cite §3d, not the article's 'hundreds→one' excitement." Reframed as taxonomy cleanup.
- **RE-JUDGMENT: UPHELD-CUT on the wholesale "collapse 23 → 1" pivot (named failure mode), ELEVATE the model-capacity re-audit it implies.** The collapse-to-one pivot is genuinely a bad fit even at fleet scale, and the named failure mode is precise: **23 ≪ hundreds, so the maintenance-tax that justified Ramp's consolidation does not exist for us, while the clarity the §9 keep-list protects (reasoning-discipline lenses: assumption/composition/cascade/abuse, hotfix-guard, security-reviewer) is real and load-bearing** — collapsing them would erase distinct reasoning roles to save a maintenance cost we aren't paying, the exact inverse of the §9 golden rule. That UPHELD-CUT holds at any scale because it's a threshold argument, not a solo argument. **But** the *re-audit obligation* underneath it should ELEVATE: canon's §9 Model Capacity Audit was made against Sonnet 4.6 and is explicitly due for re-run on the Opus 4.8 update `[canon §9]`. Ramp is the live evidence that model upgrades retire scaffolds — so the in-scope-now move is to *run the §9 re-audit against Opus 4.8 and reconcile the 23-vs-7–10 roster contradiction to one canonical count*, not to chase "one agent, thousands of skills."

## Autonomy angle
This source is **richly about autonomy** — arguably the strongest autonomy-teaching source in the corpus, which the conservative synthesis systematically drained.
- **Bug → reviewed PR:** Inspect *is* this — a background agent that takes a task, verifies in a real environment, and opens a PR; ~30% of merged PRs, organically. The self-verification loop is the mechanism that makes the autonomous PR trustworthy enough to merge.
- **Slack/Linear summon:** directly taught — the multi-surface front door (Slack, Chrome ext, voice, GitHub comments) is the *adoption* engine, and pass-1 ties it explicitly to AFK/background workflows.
- **Self-improving loops:** the "80% of Inspect written by Inspect" / "the tool builds itself" claim is the recursive-improvement story — though pass-2 correctly bounds it: it's vendor-disowned (Modal-sourced) *and* category-specific to code-producing agents (you can't `pnpm test` whether a memory-model decision was correct). So adopt the *pattern* (verification-gated agents improving the harness) without importing the 80% figure.
- **Cloud scheduling:** not named in the source, but the source's multi-surface + background-agent posture is exactly what cloud `/schedule` (now confirmed to exist on Anthropic infra) operationalizes for us — committed verification skills, run unattended, opening PRs.

## The single biggest move (one paragraph)
**The machine-enforced self-verification loop, built as the spine of an autonomous bug→PR front door — not a tightly-scoped "regression-only" wiring tweak.** This is the move the vision synthesis should pick up first because it is the one mechanism that makes every other autonomy ambition *safe to ship*: an agent that opens its own PR is only trustworthy if something deterministic re-ran the suite, scanned the deployment logs, and captured a before/after screenshot before the PR exists. Ramp is the world-class proof that closing this loop is what converts "an agent that writes code" into "an agent the org voluntarily routes 30% of its PRs through, with no mandate." Our harness has the inverse condition documented in cold ink: `[canon §3e]` says enforcement is "overwhelmingly advisory… no deterministic backstop," and the only Stop hook that could host the gate (`session-end.sh`) is `[canon §5]` declared-but-absent. The conservative synthesis correctly identified the gap and correctly put it in a hook — then shrank it to `test + typecheck`, scoped it to "regression-trust only," and ranked it one of six tweaks. Under the new charter it is the central verification subsystem: an evidence bundle (tests green + typecheck clean + runtime-log scan + Chrome-MCP visual artifact, emitted as an evaluable pass/fail object) that gates the autonomous PR, with the human/scheduled-agent semantic checkpoint preserved and `.cr-ok` kept as a readiness signal, never a capability unlock. Build that, and "bug → reviewed PR, summoned from Slack/Linear" stops being a deferral and becomes the harness's defining capability.
