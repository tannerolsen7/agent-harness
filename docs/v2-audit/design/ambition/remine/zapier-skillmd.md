# Ambition Re-mine — Zapier: SKILL.md Architecture, AI Fluency & Org-Wide AI Transformation

## What this source is (plain English, 2-3 sentences)
A curator's write-up of how Zapier builds and governs agent skills, drawn from the directly-inspectable `zapier/zapier-mcp` GitHub skill directory, Zapier's MCP/Skills blog posts, and Anthropic's 2026 Agentic Coding Trends report. Its two technical cores are: (1) a skill is a **directory** (`SKILL.md` + frontmatter contract + `references/` + `scripts/`), not a prose file — frontmatter makes a skill a routable module a system can discover without reading the body; and (2) the highest-leverage governance is **encoded structurally** (MCP token budgeting and action scoping mean an agent approved for "read issues" physically cannot write commits) rather than stated as advisory policy. It wraps these in org-scale theater (CPAITO, 89% adoption, ROI numbers) that is largely non-transferable.

## The full-ambition moves this source teaches

### Move: The enforcement-tier discipline — promote rules from prose into structure, matched to the receiver
- **Plain-English what & why:** Pass2 (§2.1, §2.7) recovered the article's real thesis, which the article itself only half-states and the conservative pass3 treated mostly as a "framing lens." Every rule in your harness sits in one of three tiers: **deterministic-structural** (the system *cannot* do the wrong thing — MCP scoping, a guard hook that hard-blocks `rm -rf`), **mechanically-shaped** (the system is *steered* but could deviate — a fixed report shape, a regex that auto-pulls ticket context), or **advisory** (the system is merely *told* — a sentence in CLAUDE.md). The world-class move is the test in pass2 §2.7: for each rule ask *which tier is it in, and does the tier match who's on the receiving end?* A safety rule aimed at an **unattended agent** that lives only in advisory prose is mis-tiered — "you can't enforce policy in a session that's not being watched." The failure it prevents: an unwatched agent silently violating a CLAUDE.md "NEVER" rule with nothing to physically stop it.
- **The mechanism:** Adopt the tier test as the governing rubric for every guard decision in V2, and use it to drive a deliberate **promotion campaign**: walk the bulk of advisory CLAUDE.md "NEVER" rules and the autoMode lists, and for each one that targets an unattended/background agent, build the deterministic backstop (a PreToolUse guard hook) instead of leaving it as prose. The two named missing guards below are the first two outputs of this campaign; the broader output is a standing principle in the harness doctrine: "a rule for an unattended receiver must be tier-1, not tier-3."
- **Citation:** Ground-truth §3e "Net enforcement picture": "**Both agree the system is overwhelmingly advisory** — neither has a deterministic backstop for the bulk of skill bodies, CLAUDE.md rules, or the autoMode lists" (CANONICAL-HARNESS-AS-IS.md lines 220-221).
- **Conservative disposition:** pass3 §(b)4 named this but **scaled it down to "a framing gap the article fills"** — it explicitly called this "one durable lens" and a "vocabulary" for prioritization, not a build. It contributed *the words* (policy vs infrastructure) but deferred *the work* of promoting the advisory bulk.
- **RE-JUDGMENT under the new charter:** **ELEVATE.** Under "autonomy is first-class," the receiver in V2 is by design an unattended agent (bug→PR, cloud /schedule running committed skills with nobody watching). That is precisely the receiver pass2 says makes advisory enforcement mis-tiered. The conservative move — treat the tier test as a *lens to think with* — fails the new charter because the charter has already decided the answer the lens produces: the system runs unattended, so the advisory bulk targeting agents is a live safety gap, not a thinking exercise. Much bigger: this becomes a **standing harness doctrine plus a promotion backlog**, not a one-line vocabulary note. World-class teams (Zapier's MCP scoping is the exemplar) do not ship unattended agents whose only restraint is prose.

### Move: Build the two missing deterministic guard hooks (`block-dangerous-bash.sh`, `enforce-scope.sh`)
- **Plain-English what & why:** These are the concrete tier-1 backstops the article's governance thesis demands, and the canon already specifies them. `block-dangerous-bash.sh` is canon's 3rd structural guard — it hard-blocks deploys, `rm -rf`, and writes to `.git`/`.husky`/`.claude` at the PreToolUse boundary. `enforce-scope.sh` blocks an agent from staging files outside its task's declared `## ALLOWED FILES` list — the infrastructure analogue of Zapier's MCP "action scoping" (an agent scoped to read GitHub issues cannot write commits). Both exist in canon; **both are absent on disk.** The failure they prevent: an unattended agent running `rm -rf`, force-pushing, editing its own guard files, or quietly touching files far outside its task scope — with nothing but a CLAUDE.md sentence (which the PocketOS incident proves agents violate) standing in the way.
- **The mechanism:** Write both PreToolUse guard hooks and wire them into settings.json. `block-dangerous-bash.sh` pattern-matches the bash command and exits 2 (block) on the canon-specified destructive set. `enforce-scope.sh` reads the task's `## ALLOWED FILES` and blocks `git add`/writes outside it. (Note: per project memory, guard-file edits and settings.json changes are a human handoff — surface paste-ready content, do not self-apply.)
- **Citation:** Ground-truth §5 — `block-dangerous-bash.sh` "Canon's 3rd guard — ABSENT on disk. Disk has no safety-floor bash guard" (line 206); `enforce-scope.sh` "Canon structural, absent on disk" (line 207). Cross-ref §3e/§5.
- **Conservative disposition:** pass3 §(b)2 and §(b)3 **named both as real gaps** and even called `block-dangerous-bash.sh` "the most defensible gap the article surfaces." This was correctly identified — but the conservative synthesis (MASTER-FINDINGS' collapse to 6 wiring-tweaks) treated them as candidates among many rather than the **first-priority autonomy prerequisites** they are.
- **RE-JUDGMENT under the new charter:** **ELEVATE** (to top priority, not in scope of severity). The charter makes these load-bearing: you cannot ship bug→PR or cloud /schedule (committed skills running unwatched on Anthropic infra) until the deterministic destructive-op floor exists. The conservative framing listed them; the new charter **sequences them first** — they are the safety gate that makes everything else in the autonomy program survivable. This is not bias-correction so much as re-prioritization: the old synthesis under-weighted them because, at "solo, attended" scale, a prose NEVER mostly holds. At "fleet of unattended agents across 5+ repos" scale, it provably does not (PocketOS). Note these are also the *literal* enforcement floor that makes `disable-model-invocation:true` side-effect skills (deploy, open-PR) safe — the charter's named safety primitive.

### Move: SKILL.md frontmatter contract + a real skill router (the directory-not-file insight)
- **Plain-English what & why:** Zapier's skill is a directory whose `SKILL.md` frontmatter declares `name`, `description`, trigger conditions, required MCP tools, and output format — machine-readable metadata that lets a system **route to and discover a skill without parsing its prose body.** Our runtime skill list today mixes every layer (`/cr`, `/queue`, `/dev`, `Notion:*`, third-party skills) with no signal for which layer owns each, which travels to another project, or what tools each needs. The failure it prevents: an agent (or an installer) cannot reason about its own skills programmatically — it can't tell a project skill from a portable plugin skill, can't pre-load required tools, can't build a marketplace/installer because there's no manifest to read.
- **The mechanism:** Add a frontmatter contract to every skill (`name`, `description`, **situational** trigger, `required-tools`, `owning-layer`, `portable: true|false`, and — for autonomy — `disable-model-invocation` for side-effect skills). Then **build the consumer**: a skill registry/router that reads the frontmatter to (a) drive the plugin+marketplace distribution the charter names as canon, (b) feed the thin `/init` per-repo template, and (c) let the agent filter its own skill list by owning-layer. Pass2 §2.2's warning holds and is now a *requirement* not a deterrent: frontmatter without a consumer is documentation — so build both halves.
- **Citation:** Ground-truth §1 — "The runtime skill list mixes all layers. When the agent sees `/cr`, `/queue`, `/dev` (project)... it cannot tell which layer owns each, nor which will travel to another project" (line 95); §3b confirms ~26 disk skills with no registry. Constraint: §9 (line 337) — "Phrase-keyed skill descriptions → trigger should be the situation, not the words."
- **Conservative disposition:** pass3 §(b)1 called this "the article's headline gap is real for us" but immediately **hedged it into a two-part conditional** — "(i) add a frontmatter contract, (ii) build/decide the thing that reads it... Proposing (i) alone would be the documentation-not-infrastructure trap." The hedge plus the §9 trigger caveat left it as a gated, deferred candidate rather than a build.
- **RE-JUDGMENT under the new charter:** **ELEVATE.** The charter resolves the exact uncertainty that gated this: "Distribution = plugin + marketplace + thin /init template" and "GitHub becomes the single source of truth." A plugin/marketplace **physically requires** a per-skill manifest — frontmatter *is* the consumer's input, and the consumer (the marketplace/installer) is now a committed workstream, not a hypothetical. So the conservative "no router exists, value is inert" objection is moot: the charter is building the router. This goes from gated-candidate to **foundational infrastructure for the entire distribution story.** The §9 caveat is real and survives — triggers must be situational, not keyword-keyed — but that constrains *how you write the trigger field*, not *whether to build the contract*. Much bigger: this is the schema the whole portable-harness vision serializes through.

### Move: Accountability as the named owner of the un-automatable residual (not a culture sentence)
- **Plain-English what & why:** Pass2 §2.3 recovered an insight the article files under "culture": you can deterministically stop an agent from writing a commit, but you **cannot** deterministically make a human read what they merge. Accountability is therefore not a peer 4th pillar — it is the **designated owner of the residual that no enforcement tier can cover.** "You own this code as if you wrote every line" is, read this way, an explicit assignment of the un-automatable remainder to a named human. The failure it prevents: in an autonomous bug→PR loop, the gap between "agent opened a clean-looking PR" and "a human actually understood and vouched for it" — the place where unattended automation quietly ships unreviewed judgment.
- **The mechanism:** Keep the existing agent-contract/SOUL language, but in the **autonomous PR path specifically**, make the accountability assignment a structured, visible artifact: the bug→PR flow must surface a named human reviewer/owner gate before merge (not an auto-merge), and the PR body should state which human owns the residual. This is the architectural reading, not a cosmetic sentence.
- **Citation:** Ground-truth §3a — `.claude/agent-contract.md` and `.claude/SOUL.md` both "Aligned"; CLAUDE.md carries the 3-question discipline rule (referenced in pass3 §(a)). Confirmed-present, so the gap is narrow.
- **Conservative disposition:** pass3 §(a) ruled the article's candidate "**largely redundant** with the existing human-walkthrough contract — its own open question resolves to *mostly yes*." Treated as already-built / minor.
- **RE-JUDGMENT under the new charter:** **UPHELD-CUT (as a contract sentence) — but recover the architectural half as part of the autonomy gate.** The sentence really is redundant; adding "you own this as if you wrote it" to a contract that already carries the 3-question walkthrough buys nothing — and a duplicated principle across two files is the kind of drift the harness should avoid. The named failure mode that justifies *not* adding the sentence: principle-duplication across agent-contract.md and SOUL.md creates two sources of truth for the same rule, and the next edit updates one and not the other. **However**, pass2's deeper reading (accountability = owner of the residual) is genuinely first-class *as the human gate in the bug→PR loop* — that is auto-merge-vs-human-gate, an autonomy design decision, not a culture sentence. So: cut the sentence, keep the gate. The gate is covered by the autonomy program, not this contract edit.

## Autonomy angle
The source does not name bug→PR, Slack/Linear summon, or cloud scheduling as features, but it teaches the **enabling discipline** for all of them, and one direct autonomy primitive:
- **Direct primitive:** pass1 (line 35) records CTO Bryan Helmig **personally built the Slack-emoji → Claude → merge-request workflow** — i.e., a real-world **Slack-summon → agent → PR** loop, built by the most senior engineer at a world-class shop. This is precisely the charter's "summoned from Slack/Linear → reviewed PR" target, and it is direct evidence the pattern is world-class, not speculative.
- **Enabling discipline:** the entire enforcement-tier thesis (pass2 §2.1/§2.3/§2.7) is *about* the unattended receiver — "you can't enforce policy in a session that's not being watched." Cloud /schedule runs committed skills with nobody watching; that is the exact receiver. The two missing guard hooks and the `disable-model-invocation` frontmatter field are the safety floor that makes unattended side-effect skills (deploy, open-PR, send-Slack) survivable. Accountability-as-residual-owner is the human gate that keeps bug→PR from becoming auto-merge-without-judgment.

## The single biggest move (one paragraph)
**Adopt the enforcement-tier doctrine and execute it as a build, not a lens — starting by shipping the two missing deterministic guard hooks (`block-dangerous-bash.sh`, `enforce-scope.sh`) as the safety floor for unattended autonomy.** This is the move the vision synthesis should pick up first because it is the literal precondition for everything else in the charter: you cannot responsibly ship bug→PR, cloud /schedule, or `disable-model-invocation` side-effect skills until the destructive-op and file-scope rules are promoted from advisory CLAUDE.md prose (which the PocketOS incident proves agents violate) into tier-1 hooks the unattended agent physically cannot bypass. The conservative synthesis correctly *named* these gaps but treated the tier test as vocabulary and the guards as candidates-among-many; under "autonomy is first-class," they are the gate. It is world-class because it matches the exact pattern Zapier uses to let agents run without direct credentials — structural least-privilege that holds when nobody is watching — and because the canon already specifies both hooks, this is recovering a pre-authorized build the conservative pass under-sequenced, not inventing one.
