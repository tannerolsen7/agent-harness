A REJECT verdict closes the PR with an exact command when the approach is fundamentally wrong. Fix attempts are capped at 2 — on the third failure the review hands back to the human with the exact failing test and stops.

The harness gates code at PR → CI → merge, but manual deploy steps (migrations, env variable changes, feature flags) happen after that boundary with no gate. A sibling project's ungated manual migration broke production. Proposed: a deploy-targets manifest + a deterministic check in CI (free, no creds) as the first slice.

No lightweight path exists between a quick inline search and the full 5-agent /spike pipeline. Proposed: (1) inline — quick factual, fits in context; (2) /deep-research — background knowledge; (3) /spike — gates a build decision and needs a go/no-go + a test that confirms the approach works.
