Linear delegation → Claude Code CLI on Railway (the front door)
A lightweight always-on server (Railway) receives Linear AgentSessionEvents, verifies the Linear-Signature header, checks that the issue is agent-cleared and checkpoints-complete, and spawns a Claude Code CLI process to run the task. Feature work runs here — not via Routines — so there is no daily cap. Pure API token cost. Works identically for GitHub and GitLab repos; the server maps each Linear team to its git provider and credential set. Task state machine: pending → claimed → running → blocked | complete | failed. State is persisted to a SQLite file on a Railway volume — not in memory — so a server restart does not lose in-flight task state. A watchdog process detects CLI processes that have died without updating state and moves them to error with a Slack notification. Idempotency: the Linear-Delivery header is used as a deduplication key, stored in the same SQLite file. Linear may retry webhook delivery; the server must reject duplicates. Repo strategy for v1: fresh clone per task — slower but no stale-state risk. Kill switch: a single AGENT_ENABLED=false environment variable on Railway stops all webhook processing immediately without taking down the server. Set this before diagnosing any misbehavior. v1 runs one task at a time. The queue interface is designed for parallel upgrade from day one: tasks enter a queue, a worker pool (size=1 in v1) claims and runs them. Upgrading to parallel means increasing pool size and adding per-worktree port isolation — no queue redesign needed. The CLI receives the Linear issue serialized into TASK-TEMPLATE.md field format as the prompt context. The ticket must specify which skill to invoke (feature, queue, hotfix) as a required template field — the server does not infer it. On task start: set Linear session externalUrl to the Claude Code session URL. On BLOCKING question: post to #agent-blocking, set Linear session to awaitingInput, pause the CLI process. On completion: post PR link to #agent-status, close Linear session, update task state to complete.
