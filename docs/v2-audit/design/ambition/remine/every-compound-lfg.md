# Ambition Re-mine — Every.to Compound Engineering, `/lfg` & Plugin Architecture

## What this source is (plain English, 2-3 sentences)

Every is a ~6-person team that publicly shipped "compound engineering" — a named, runnable methodology where one command (`/lfg`) drives a fixed five-step loop (brainstorm → plan → work → review → compound) from idea to opened PR, unattended. It is distributed as a real MIT-licensed Claude Code plugin (50+ agents, 38+ skills), backed by a STRATEGY.md middle-context layer, a deterministic three-tier review with a four-technique adversarial reviewer, severity/routing orthogonality, multi-model task routing, and — uniquely — a publicly documented list of seven production failure modes. It is the single closest external analog to the autonomous overnight harness this project is trying to build.

The deep stance pass 2 isolated — **"deterministic seams, agentic cells"** — is the spine: make the *boundaries* between agent actions deterministic, and let the model be agentic only *inside* the boxes. Under the new charter this stance is not a footnote; it is arguably the most important single architectural principle any of the 37 sources teaches for safe autonomy.

## The full-ambition moves this source teaches

### Move 1: `/lfg` — the autonomous brainstorm→plan→work→review→compound→PR loop as a *first-class shipped command*

- **Plain-English what & why:** Every wired the entire idea-to-PR pipeline as one command that runs the five phases back-to-back with no human between steps, and surfaces a reviewed PR at the end. The failure it prevents is the "AFK is a someday-feature" trap: most teams treat unattended runs as an aspiration bolted on later, so the loop never actually closes and every task still needs a human babysitter at each handoff. Every made closing the loop the *product*, which forced them to confront — and publish — exactly where it breaks.
- **The mechanism:** A single `/lfg`-equivalent orchestrator skill on disk that sequences our existing pieces — a brainstorm/divergent step, a plan/convergent step (these are *separate*, see Move 2), `/dev` or `/feature` for work, `/cr` for review, `/compound` for capture — and ends by calling `scripts/pr.sh`. It runs inside UNATTENDED worktree mode with the Tier-0 prod-key firewall already on disk (`[map §6]` worktree-create + prod-key firewall). The side-effecting tail (open-PR, deploy) is gated behind `disable-model-invocation:true` skills so the model can't fire them off-loop. This is the *integration spine* the harness lacks: we have all the cells, but no committed command that runs them as one deterministic sequence to a PR.
- **Citation:** Confirmed absence. `[map §3b]` lists `/dev`, `/feature`, `/cr`, `/compound` as separate disk skills; there is **no orchestrator that chains them to an opened PR**. UNATTENDED worktree mode + prod-key firewall exist `[map §6, §3e]` but only provision isolation — they don't drive the loop. The map's headline calls the multi-project autonomous harness aspirational, not built (`[map §0]`).
- **Conservative disposition:** §C DEFERRED, dressed as "already our north star." Pass 3 §(a)5: "*The autonomous-loop north star is already our explicit target… Every corroborates the direction; it does not introduce it.*" MASTER-FINDINGS treated `/lfg` as external confirmation of a direction already chosen, and therefore *added nothing* — it generated zero build move. The "we already aim at this" framing let the synthesis skip building the actual orchestrator.
- **RE-JUDGMENT: ELEVATE (to the single biggest in-scope-now move).** "We already aim at it" is precisely the conservative bias the new charter retires — *aiming* at AFK and *having a committed command that closes the loop to a PR* are different things, and the map confirms we have the second nowhere. Under "autonomy is first-class, designed in, never deferred," the orchestrator is the keystone deliverable, not a corroborated aspiration. Every is the proof-of-existence that a 6-person team ran this in production: the question is no longer "should we" but "build the `/lfg` orchestrator now and let the seven failure modes (Move 4) be its guardrails." This is the largest suppressed move in the file: the conservative synthesis collapsed a *build the loop* mandate into a *we already think about the loop* nod.

### Move 2: Brainstorm-before-plan as a *structural* separation (divergent and convergent are different commands)

- **Plain-English what & why:** Every deliberately split the loop's first two steps — brainstorm (explore widely, stay divergent) and plan (commit to one path, converge) — into separate phases that cannot be collapsed. The failure it prevents is *premature commitment*: when one step does both, the agent locks onto the first plausible approach and produces a plan that's technically correct but misses the better alternative it never explored. This is a failure mode at the *planning* altitude, not the implementation altitude — and it's invisible because the resulting plan looks fine.
- **The mechanism:** In the `/lfg` orchestrator (Move 1), make brainstorm and plan two distinct, ordered sub-steps with a hard seam between them — the plan step receives the brainstorm's divergent output as input and is forbidden from re-opening exploration. This is the "deterministic seam" stance applied at the front of the loop. Our current `/feature` and `/design` skills blend ideation and planning; no committed primitive enforces "diverge fully, *then* converge."
- **Citation:** Confirmed absence. `[map §3b]` shows `/design` and `/feature` on disk but no divergent/convergent split; `[map §5]` lists `/ideate` as backlog-only ("To-Think-About #6"), i.e. the divergent-half primitive is explicitly *not built*.
- **Conservative disposition:** §D MINOR / folded away. MASTER-FINDINGS never broke this out as a candidate; pass 3 didn't list it among the "real gaps" in §(b), treating it as internal to `/lfg` (which it deferred). Effectively summarized to nothing.
- **RE-JUDGMENT: NEW.** The synthesis lost this entirely by deferring the loop it lives inside. Recovered as a first-class candidate, it's a small but genuinely load-bearing seam: it's the cheapest insurance against the most expensive autonomous failure (a confidently-wrong plan executed overnight). Under "clarity beats minimalism — more steps are fine when each earns its place," a separate divergent step *earns* its place by naming a specific failure (premature commitment) it prevents — passing the §9 golden rule. Not as big as Move 1 or 4, but it must be designed *into* the orchestrator, not bolted on.

### Move 3: Severity × routing orthogonality in review output (split "how bad" from "who acts")

- **Plain-English what & why:** Every's reviewer attaches *two independent* facts to each finding — severity (how serious) and routing (who should act: the author, a product/design decision-maker, or the tech-debt backlog). The failure it prevents is *false blocking*: a medium-severity finding that actually needs a human product decision hard-blocks the merge, while a genuinely serious issue that's really tech-debt never gets triaged because "tech-debt" reads as "ignorable." Conflating the two axes means the merge gate fires on the wrong things.
- **The mechanism:** `/cr`'s output today uses MUST FIX / NEEDS HUMAN / SUGGESTION — a severity-ish tier set where "NEEDS HUMAN" smuggles a routing concept into a severity slot. The disciplined fix (pass 2 §B-2 correctly narrowed this from a full 3×3 grid to one real bug): split NEEDS HUMAN into *needs-design-decision* (surface it, **do not** hard-block the merge) vs. *must-fix-now* (hard-block). A two-value routing flag on each finding, not an orthogonal axis.
- **Citation:** Real gap, cited. `[map §3c]`: disk `/cr` is "9 parallel passes + Pass 11 (4 lenses), **no REJECT tier**, no routing dimension." Confirmed absence of any routing field in `/cr`'s pipeline resolution. (Note: the article aimed this at `/cr-feature`, which is **retired** — `[map §3b]`, "folded into `/cr`" — so the target is `/cr`.)
- **Conservative disposition:** §C-but-narrowed / partially-applied. This is one of the few items pass 3 *kept* as a "real gap" (§(b)1), but immediately shrank it: "*the actual fix is small: split NEEDS HUMAN into needs-design-decision vs. must-fix-now.*" MASTER-FINDINGS folded it into "existing V2 review-output design," not a standalone move.
- **RE-JUDGMENT: ELEVATE — but modestly, and the narrowing was *correct*.** This is the rare case where the conservative instinct to shrink the 3×3 grid to one flag was right (pass 2's own analysis backs it; a full orthogonal grid would be over-engineering even at fleet scale — most cells are near-empty). But the *priority* deserves elevation under the autonomy charter: in an unattended loop, false-blocking is catastrophic — a design-decision finding that hard-blocks an overnight `/lfg` run *stalls the entire loop* with no human present to unblock it. So the routing flag isn't a nice-to-have review polish; it's a **prerequisite for autonomy not deadlocking on judgment calls**. Elevate from "fold into review-output design later" to "ships with the `/lfg` orchestrator." The mechanism stays small; the priority moves to in-scope-now.

### Move 4: Failure-mode-as-guard — turn each documented failure into a deterministic check

- **Plain-English what & why:** Every published seven concrete, reproducible production failure modes (encoding disasters, context drift, agent stalls, non-determinism, compound-timing criticality, skill-cache staleness, cross-skill file-reference breaks). Each one is a *detectable condition*, not a vague risk. The world-class move pass 2 §D-1 recovered — and which the article itself, astonishingly, proposed *zero* adoption actions for — is to convert each failure mode into a guard or a check: encoding → a normalization/lint pass; context drift → a task-version staleness check; skill-cache → a session-restart/cache-invalidation rule; cross-skill refs → a reference-integrity test that fails CI on a dangling skill reference. The failure it prevents: an unattended loop that silently does the wrong thing for hours because the harness has no deterministic backstop for its own known failure classes.
- **The mechanism:** A small battery of deterministic guards added to our enforcement floor, each keyed to a named failure mode. Two of the seven map directly onto *confirmed disk pathologies we already suffer*: (1) **cross-skill reference-integrity check** — a script/CI step that greps every skill body for `@agent` and `/skill` references and fails on any that don't resolve; we already have dangling phantom refs (`learned-patterns.md`, `review-log.md`, `triage-inbox.md`, `/prototype-interface`, `/scan-context`, `@benchmark-runner`) `[map §6]`. (2) **skill-cache / session-restart rule** — a hook or documented rule that mid-session skill edits require a session restart to take effect; no such rule exists `[map §3e]`. The other five become guards *as we run `/lfg` at volume*, but encoding-normalization and an agent-stall watchdog are cheap enough to design in now.
- **Citation:** Real gaps, cited. Cross-skill refs: `[map §6]` "Phantom refs… Referenced on disk, never built." Skill-cache: confirmed absence in `[map §3e]` hook table (session-start does remote npm install; no cache-invalidation handled). Enforcement floor overall: `[map §3e]` net-picture — "*overwhelmingly advisory… no deterministic backstop.*"
- **Conservative disposition:** §C/§D — *the single best material in the source, and the synthesis kept only the smallest slice.* Pass 3 §(b)2 conceded these are "the article's richest artifact, unmapped," and admitted "*we already suffer this failure mode (dangling references) with no reference-integrity check.*" But it then **disciplined-down to only two of seven** and folded them into "existing enforcement-floor work," explicitly demoting the other five to "watch-items, not mapped absences."
- **RE-JUDGMENT: ELEVATE — the largest under-valuation in the file.** The "only two are citable gaps *now*" reasoning is exactly the conservative existence-bar bias the new charter rejects. The other five aren't watch-items at fleet scale — they're the *operating risks of the autonomy you've now made first-class*. The moment `/lfg` runs unattended across 5+ repos, context drift, agent stalls, and non-determinism stop being hypothetical and become the daily failure surface; a world-class harness instruments them *before* the first overnight run, not after it bites. The map's own §9 golden rule ("name a failure mode the constraint prevents, or it's overhead") is *satisfied by every one of the seven* — Every literally named the failure mode for you. This is the strongest argument in the source for building deterministic guards, and the conservative synthesis shrank it from "a seven-guard safety battery for autonomy" to "two CI greps folded into existing work." Elevate to a named workstream: **the failure-mode guard battery** is what makes Move 1 (the loop) safe to leave unattended.

### Move 5: Multi-model task-type routing encoded as rules

- **Plain-English what & why:** Every routes each task to a model by *type* — a strong primary for hard reasoning, cheaper/faster models where capability allows — and encodes the routing as explicit rules in CLAUDE.md rather than picking ad hoc. It also cites the Anthropic finding that an Opus-lead + Sonnet-sub-agent orchestration beats single-Opus ~90% on research tasks at ~15× the tokens. The failure it prevents: paying top-model cost (and latency) on every trivial step of a long autonomous loop, or under-powering the one step that actually needed the strong model.
- **The mechanism:** A task-type→model routing doctrine in CLAUDE.md, plus an orchestration economics note for the Opus-lead/Sonnet-sub pattern inside `/lfg`'s work step. Our global config has `effortLevel: xhigh` and `switchModelsOnFlag` `[map §2]` but **no routing doctrine**.
- **Citation:** Real gap, cited but pinned to a planned effort. `[map §2]` (no routing rules) + `[map §9]` (model-capacity re-audit pending; Every's claim is pinned to Opus 4.6, we're on Opus 4.8).
- **Conservative disposition:** §C DEFERRED into an existing effort. Pass 3 §(b)3 / §(d): "*The gap is real but should be folded into the §9 re-audit, not adopted as Every stated it… Re-researching now would duplicate a planned effort.*"
- **RE-JUDGMENT: UPHELD-CUT (as a standalone Every-driven move) — with one carve-out.** The deferral is genuinely correct: Every's specific routing numbers are pinned to a model two versions stale (Opus 4.6 vs our 4.8), and we have a *pre-authorized* model-capacity re-audit `[map §9]` that owns this exact question. Adopting Every's routing table verbatim would hard-code stale capability assumptions — the named failure mode that justifies the cut. **However**, the carve-out the synthesis missed: the *orchestration economics fact* (90% better / 15× tokens for lead+sub) is load-bearing for `/lfg` cost at fleet scale and should be a one-line confirmatory check *inside* the §9 re-audit, not a deferred watch-item — because once you run loops across 5+ repos, the token multiplier is a real budget line, not trivia. Cut the standalone move; promote the economics fact into the re-audit's scope.

## Autonomy angle

This source is **the most autonomy-rich of the 37** — it is the only one that ships the bug-to-PR loop as a real product:

- **Bug → reviewed PR:** `/lfg` *is* the loop — brainstorm→plan→work→review→compound→opened PR, no human between steps (pass 1 §1, §3.1). It maps one-to-one onto the harness's UNATTENDED north star and is the direct template for Move 1's orchestrator.
- **Self-improving loops:** `/compound` runs as the loop's final step (pass 1 §3.13) — the system captures what it learned before the session ends. Pass 2 §D-3 sharpened this into a real principle: *compounding is a context-eviction deadline, not a pipeline step* — the nuance lives in the model's active context and is lost when the window evicts, so capture must run before the session closes. That's a direct constraint on any self-improving design: the capture step is non-skippable and time-boxed to the session.
- **Cloud scheduling:** Not addressed by name, but `/lfg`'s "unattended overnight run" framing is exactly what cloud `/schedule` now makes durable — the resolved fact that cloud scheduling exists on Anthropic infra removes the article's implicit "is overnight reliable?" objection (its own open question #1). The seven failure modes (Move 4) are precisely the reliability instrumentation a scheduled `/lfg` needs.
- **Slack/Linear summon:** None.

The honest autonomy caveat the source itself surfaces: a 6-person team publishing *seven* production failure modes for an "unattended" loop is evidence the loop is *frequently not actually unattended* (pass 2 §B-3). That doesn't argue against autonomy — under the new charter it argues *for building the failure-mode guard battery (Move 4) as the price of admission* to leaving the loop alone.

## The single biggest move (one paragraph)

**Build the `/lfg` orchestrator (Move 1), and make the seven-failure-mode guard battery (Move 4) its guardrails.** The conservative synthesis's defining error on this source was treating `/lfg` as "a direction we already aim at" and therefore generating zero build move — when the ground truth confirms we have every *cell* of the loop (`/dev`, `/feature`, `/cr`, `/compound`, UNATTENDED worktree mode, the prod-key firewall) but **no committed command that closes them into a deterministic sequence ending in an opened PR** `[map §3b, §6]`. That gap *is* the gap between "we think about autonomy" and "we have autonomy." Every is the existence proof that a small team ran this in production, and — crucially — published the seven exact ways it breaks. So the world-class move is not to admire the loop but to ship it with its failure modes wired in as deterministic guards from day one: the orchestrator embodies the "deterministic seams, agentic cells" stance (fixed step order, agentic freedom only inside work/review), the routing flag (Move 3) keeps a judgment-call finding from deadlocking the loop overnight, the brainstorm/plan seam (Move 2) prevents a confidently-wrong overnight plan, and the guard battery (Move 4) gives the unattended run the deterministic backstop the entire harness currently lacks (`[map §3e]` "overwhelmingly advisory… no deterministic backstop"). That single integrated deliverable — loop + seams + guards — is the most world-class thing this source teaches, and the conservative synthesis suppressed all of it down to a nod and two CI greps.
