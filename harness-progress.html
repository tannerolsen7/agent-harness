Phase 1 — Trust
Bug-catch test suite with a real-defect scoreboard
13 seeded defects (security holes, logic bugs, type errors, trap cases — changes that look trivial but aren't). A score script measures the catch rate and gates the upcoming review-consolidation work. 59 test cases; 100% recall on trap cases.
Unforgeable CI pass required before any review
cr-ok.sh records a branch + commit SHA after CI passes. The review skill refuses to run if the token is absent or stale. /cr now diffs against origin/main so a stale local main branch can't cause misclassification.
Bug fixed: the old flow consumed the token before running preconditions — a failed review destroyed it. Now preconditions run first; a trap restores the token on failure.
4-lens adversarial reviewer wired into /cr
Four independent AI reviewers attack every PR from different angles: abuse (wrong usage), assumptions (what's taken for granted), cascades (what breaks downstream), composition (conflicts with existing code). All four run in parallel.
Bug fixed by /cr on itself: the reviewer was missing the Task tool and couldn't spawn the four lens agents. Fixed; a regression test now verifies the spawn wiring.
Each agent uses the right model for its job
Audit of all 23 agents mapped each role to the right model tier. Reviewers → Opus. Doc-update agent → Haiku (fast/cheap). Model assignments live in OS-locked guard files — the AI cannot change its own tier.
Code review hard-stops broken approaches; 2-attempt ceiling
A REJECT verdict closes the PR with an exact command when the approach is fundamentally wrong. Fix attempts are capped at 2 — on the third failure the review hands back to the human with the exact failing test and stops.
Automatic risk score on every change (HIGH / MEDIUM / LOW)
A deterministic script classifies every diff by path and content — no AI judgment. Over-classifies to HIGH when uncertain. 59 test cases; 100% recall on "trap" cases (changes that look trivial but are high-risk). Feeds the bug-catch scoreboard.
Rules for when to use sub-agents documented (SOUL.md)
Exactly three justifications for spawning a sub-agent: independence, parallelism, or scale. Anything else stays in one context. Prevents agent sprawl.
Git hook blocks direct commits or pushes to main/master/develop
Pre-commit + pre-push hook rejects any direct write to protected branches. Tested with a stub-git harness. Fixed to handle git -C <dir> calls (PR #32) and to work correctly from inside a worktree (PR #45).

Phase 2 — The build loop
Design review required before any code is written
A design-confirmed sentinel is written after the design is approved. /feature refuses to start implementation if it's absent or stale. Covers data shape, edge cases, DB migration SQL, and a UI mockup. Small/Tiny tasks and pure bug fixes are exempt.
/cr MUST FIX caught + fixed: the ancestry check in the gate was using the wrong base commit in sub-worktrees. Fixed before merge (PR #31).
Design agent — schema + API + frontend in one pass
One agent (@designer) designs the full feature slice — database shape, API contract, and frontend architecture. A second agent (@design-griller) stress-tests it before any implementation begins.
Feature doc hub + patterns registry
Each feature produces one doc linking its spec, implementation choices, and review verdict. /compound captures non-obvious patterns into a searchable registry after merge — so the next feature can find and reuse what was learned.
Incident triage packet
When /incident runs, it produces a thorough human-actionable packet — classification, reproduction steps, evidence gathered, and a proposed fix route. Human always drives the recovery decision.
Security red-team pass added to /cr-security
For diffs touching authentication, payments, or public endpoints, /cr-security runs an active-exploit pass — it doesn't just flag issues, it tries to prove they're exploitable before reporting them.
/feature is now the one adaptive front door — no router skill needed
/feature Step 0 sizes work as Tiny / Small / Medium / Large and drives /tdd as the engine underneath. A dedicated /goal router skill was built (PR #22) and removed (PR #28) — it duplicated what /feature already does and collided with Anthropic's built-in /goal primitive.
/queue rewrite: resumable overnight batch runner
Replaced /queue Step 3+ with a resumable Workflow — three phases: Setup (idempotent worktree creation), Execute (pipeline of task-runner agents), Push (sequential push + PR). A session that dies mid-run resumes without re-running completed tasks.
Design doc required before /queue accepts large tasks
LARGE and FEATURE tasks require a design: reference in TASKS.md before /queue accepts them. task-runner also checks at startup and stops before any pipeline work if the gate is not met.
Learning loop + knowledge integrity check
After each task, the doc-updater reads back what it wrote to improve context docs over time. A new check-integrity.sh verifies that cross-references between docs are intact — catches broken links before they rot. 14 tests, wired into CI.
Context slicing — only the relevant code reaches the AI
Instead of sending whole files, the task-runner assembles only the slice of code relevant to the current task. Reduces noise and keeps the AI focused on what matters.
Progress narration hook — plain-language session summary
A session-stop hook fires automatically when Claude stops working. It emits three sections: what was done, what's in flight, and the exact command to continue next session. No setup required — fires on every session end.
Hooks
scan-context: checks whether context docs are stale
A new /scan-context skill checks context docs for freshness using a context-meta convention — each doc records when it was last validated, so the AI knows when its information is likely out of date before starting work.
task-runner: review findings triaged, recurring patterns tracked
The task-runner now auto-triages non-must-fix review findings (fix-now / backlog / drop) instead of surfacing raw flags to the human. A RECURRING-FINDINGS.md ratchet tracks patterns that keep appearing across multiple reviews so they can be addressed at the source.
