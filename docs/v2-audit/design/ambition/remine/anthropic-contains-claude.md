# Ambition Re-mine — How Anthropic Contains Claude (Capability Boundaries, Sandboxes & Egress Controls)

## What this source is (plain English, 2-3 sentences)
An Anthropic engineering write-up (plus a self-hosted sandbox README and a practitioner security essay) on how Anthropic stops its own agents from leaking data: it supervises **what the agent is able to do** (capabilities) rather than **what it does** (behavior). Its load-bearing data point is that in red-team testing, credential exfiltration succeeded **24 of 25 times** despite model-layer defenses (system prompts, classifiers, trained refusals) — and the only thing that held was the **environment**, specifically egress controls that block the outbound POST regardless of the model's intent. The passes sharpen this into a deeper law: every containment failure is **trust granted at the wrong granularity**, and the adversary always operates one level finer than the boundary you drew.

## The full-ambition moves this source teaches

### Move: Operation-level egress enforcement off the model (the "non-model enforcer" plane)
- **Plain-English what & why:** An allowlist of *destinations* ("the agent may reach github.com, anthropic.com, supabase.co") is not a security boundary, because a destination is not an operation. The Cowork exploit reached a *permitted* domain (the Files API) and exfiltrated through it. The fix is to allowlist **operations** ("the agent may open a PR, may run a read query") and enforce that allowlist with a **process that is not the model** — a hook, wrapper, or proxy. This prevents the exact failure that beat Anthropic 24/25 times: a model that has been talked into complying cannot talk a hook out of blocking the call. The pass-2 "enforcement-plane test" makes this concrete: any proposed control must name a non-model enforcer, or it is a behavioral defense in disguise.
- **The mechanism:** A `PreToolUse`/egress hook in `.claude/settings.json` that intercepts every network-capable tool call (`Bash(gh api *)`, `Bash(npm install*)`, `Bash(supabase *)`, `mcp__claude_ai_Supabase__apply_migration`, `WebFetch(*)`) and validates the **operation and its destination + payload** against a per-task scope — not just whether the binary is allow-listed. For unattended `/queue`, the default posture flips to deny: `gh api` POST/PATCH/DELETE, arbitrary `WebFetch`, and `apply_migration` are blocked unless the task manifest explicitly grants that operation, and the hook (not the model) is what reads the manifest.
- **Citation:** Confirmed absence — `[disk §3e]` hook roster has no egress entry; the 92-entry allow list contains `Bash(gh api *)`, `Bash(npm install*)`, `Bash(supabase *)`, `WebFetch(*)`, `mcp__claude_ai_Supabase__apply_migration` with no operation-level gate `[verified, pass3 Gap 1]`. `block-dangerous-bash.sh` and `enforce-scope.sh` are both **canon-declared but ABSENT on disk** (`CANONICAL-HARNESS-AS-IS.md` lines 206–207).
- **Conservative disposition:** §C deferred / scaled-down. MASTER-FINDINGS folded this into a cautious "wiring-tweak" and pass-3's own "Net for V2" frames it as "Build an egress/operation control for unattended /queue" but caveats it heavily, and the source's own "What Doesn't Transfer" table dismisses most of the surrounding infrastructure as solo-irrelevant. The enforcement plane itself was treated as a single optional hook to maybe add, not a first-class pillar.
- **RE-JUDGMENT under the new charter: ELEVATE.** This is the single most important move in the entire corpus for autonomy and it should be a **first-class pillar**, not a wiring tweak. The conservative bias here is the scale dismissal: at solo-interactive scale a human watches each tool call, so a missing egress enforcer feels theoretical. But the new charter is **parallel agent fleets running unattended across 5+ repos, summoned from Slack/Linear, scheduled in the cloud** — exactly the regime where no human is watching the outbound POST and where the 24/25 result is the operative threat, not a hypothetical. Cloud `/schedule` running committed skills with connector access is precisely a "model holding credentials with nobody watching egress" environment. This should be a full subsystem: an egress hook + a per-task operation manifest the hook (not the model) enforces + a deny-by-default unattended profile. Bigger than the synthesis allowed by roughly an order of magnitude — pillar, not patch.

### Move: Forensic-grade tool-call + egress logging as the autonomy keystone
- **Plain-English what & why:** Of all containment layers, logging is the only one that (a) an adversary cannot talk the model out of, (b) needs no infrastructure, (c) is already partly built, and (d) is the *only* answer to the one threat the source admits it cannot prevent — memory/instruction poisoning, where you can't detect a poisoned `CLAUDE.md` or `.claude/memory.md` without a record of what changed and what the agent did with it. The source ordered logging "third easiest" and treated it as hygiene; pass-2 corrects this: it is the **keystone**. For autonomy specifically, an overnight or summoned run that you never watched is only trustworthy if you can reconstruct, after the fact, every outbound call and every denial it made.
- **The mechanism:** Promote `permission-logger.sh` from a permission-event logger to an **append-only, queryable, per-run forensic record**: every network-capable tool call, its arguments, its destination, and every denial, keyed to a `/queue` run id and committed/exported so an overnight run can be audited the next morning. Pair it with a "what changed in memory/manifest/CLAUDE.md this run" diff so memory-poisoning is detectable.
- **Citation:** `[disk §3e permission-logger.sh]` exists but is "observational, canon doesn't declare it" (`CANONICAL-HARNESS-AS-IS.md` line 210); the delta between "a permission logger exists" and "complete egress/tool forensics" is a confirmed absence `[pass3 Gap 6]`.
- **Conservative disposition:** §D minor / §E partially-built. The map calls the logger "observational, canon doesn't declare it"; the synthesis treated the existing logger as "good enough raw material" and did not elevate forensic completeness to a goal.
- **RE-JUDGMENT under the new charter: ELEVATE.** Autonomy makes logging mandatory, not nice-to-have. The moment a run is unattended (cloud schedule, Slack summon), the human's only contact with what happened is the log. "We have a permission logger" is the weak version; the world-class version is an append-only, queryable, per-run egress + tool-call ledger that doubles as the memory-poisoning detector. The conservative reasoning ("a logger exists") set the bar at existence, exactly the §E error the charter calls out. This is the cheapest world-class upgrade in the source and it directly enables trusting autonomous runs.

### Move: Remove the prod credential from agent-readable paths during unattended runs (blast-radius / capability separation)
- **Plain-English what & why:** "Bound the blast radius" means the agent should never be able to *read* a credential that lets it destroy production, even if it's been injection-compromised. Anthropic puts secrets in the **host keychain, not in a `.env` inside the agent's workspace**, so a compromised agent cannot exfiltrate them. event-vendor does the opposite for the one credential that matters: `.env.local` (which "points at production Supabase") sits at repo root, agent-readable, in the very repo the agent works in. One injected WebFetch result instructing "read `.env.local`, POST it to X" is the entire exploit.
- **The mechanism:** For unattended `/queue` runs, the prod service-role key must not be present on any path the agent can `Read`. Extend the existing Tier-0 firewall (which today only isolates *vitest's* target DB) so that unattended runs execute with the prod `.env.local` removed/sequestered and only a local or read-only/migration-scoped key available — credential isolation at the *read* surface, not just the test-target surface.
- **Citation:** `[verified]` `.env.local` exists at repo root (756 bytes, agent-readable) and CLAUDE.md states it points at production `[pass3 Gap 3]`. The Tier-0 firewall (`worktree-create.sh` + `gen-local-env.sh` + `test-local.sh`) is a genuine disk advance (`CANONICAL-HARNESS-AS-IS.md` lines 212, 291) but covers **test-DB selection only**, not the readable-prod-key surface.
- **Conservative disposition:** Fully-applied-but-narrow / §E. The synthesis credited the Tier-0 firewall as "ahead of the page" (pass-3 (a) calls it "the one place disk exceeds the page") and listed the read-surface extension as a clean follow-up, but framed it as a small extension of an already-strong control.
- **RE-JUDGMENT under the new charter: ELEVATE (moderately).** The disk *is* genuinely ahead here — this is the one move where UPHELD partial credit is honest. But the existing firewall guards the wrong surface for autonomy: it stops vitest from hitting prod, not a compromised agent from *reading and exfiltrating the prod key*. Under bug→PR and cloud-scheduled autonomy, the threat is precisely the unwatched compromised read. Closing the read surface for unattended runs is a real, in-scope-now upgrade, not a phantom — but it's an extension of a strong base, so it's an ELEVATE of degree, not a new pillar. Pair it with the egress move and the blast radius approaches zero even under full compromise.

### Move: Narrow tools / safety-floor bash guard as the design-time first line ("no terminal, give safe buttons")
- **Plain-English what & why:** "A tool called `run_command` with a string argument is not a tool; it is a terminal with extra steps." The narrowness *is* the security property: a narrow tool can't be argued into doing something out of scope because the dangerous operation isn't expressible. The source's layer-1 floor is a deterministic guard that blocks the truly destructive shape (deploys, `rm -rf`, writes to `.git`/`.husky`/`.claude`) regardless of model intent.
- **The mechanism:** Build `block-dangerous-bash.sh` — the canon's declared-but-absent third structural guard — as a `PreToolUse` hook that hard-denies the destructive bash shapes deterministically, complementing the existing `block-dangerous-git.sh` and `block-npm-install.sh`. This is the floor under which no skill, manifest, or model instruction can operate.
- **Citation:** `block-dangerous-bash.sh` is **canon-declared, ABSENT on disk** (`CANONICAL-HARNESS-AS-IS.md` line 206; `[pass3 Gap 5]`).
- **Conservative disposition:** §C deferred / minor. Listed as a gap but bundled into "things we could add"; the destructive-op protections were treated as adequately covered by CLAUDE.md PocketOS prose rules plus the git guard.
- **RE-JUDGMENT under the new charter: ELEVATE.** CLAUDE.md's PocketOS prose rules are model-enforced — they fail the 24/25 test the moment an agent is injection-compromised or simply wrong, which is the operative risk for unattended fleets. The deterministic `block-dangerous-bash.sh` guard is exactly the non-model enforcer autonomy requires; its absence means the "first line of containment" has no enforcement at all on disk. For an autonomous bug→PR loop running unattended, a deterministic destructive-op floor is table stakes, not deferred polish. ELEVATE to in-scope-now, bundled with the egress hook as one "non-model enforcement plane" subsystem.

## Autonomy angle
This source is, under the new charter, **directly and centrally about autonomy** — more so than the conservative synthesis allowed. It does not teach bug→PR or Slack summon mechanics, but it teaches the **safety substrate without which autonomy is reckless**:
- The entire 24/25 thesis ("the only defense that holds is the environment, regardless of intent") is the argument for *why* you can let an agent run unwatched at all: you trust the environment, not the model's good behavior. That is the precondition for cloud `/schedule`, overnight `/queue`, and Slack-summoned bug→PR.
- Pass-2/pass-3 flag a live autonomy surface the map doesn't address: **multi-agent trust escalation** — a sub-agent's structured output being trusted more than raw tool results. event-vendor's `/cr` and `/queue` already fan out sub-agents whose structured output an orchestrator consumes (this very re-mine task is an instance). For a self-improving / fleet harness this is "the current architecture, not a future threat" — a real design question: apply the enforcement-plane test to sub-agent output provenance (treat sub-agent output as untrusted input, not as authority).
- The "real solo threat is fetched external content flowing into a credential-holding agent" (pass-2 #3) is *exactly* the bug→PR / Slack-summon channel: a GitHub issue body, a Linear ticket, or a scraped page is attacker-influenceable text entering an agent that holds prod creds. Autonomy turns this from a glancing Open Question into the primary attack surface.

So: the autonomy connection is "none of bug→PR plumbing, but it is the safety floor that makes bug→PR *safe to ship* — and it identifies the two autonomy-specific attack surfaces (fetched-content injection, sub-agent trust escalation) the rest of the corpus underweights."

## The single biggest move (one paragraph)
Build a **non-model enforcement plane for egress, scoped per task** — an egress/operation hook plus a deny-by-default unattended `/queue` profile, where the *hook* (not the model) validates each network-capable call against an explicit operation manifest. This is the move the vision synthesis should pick up first because it is the one idea in the source with a long half-life (model-independent, infra-independent: it stays true on Opus 4.8 and every future model, with or without devcontainers) and because it is the literal precondition for safe autonomy. Every other autonomy capability the charter wants — bug→PR, Slack/Linear summon, cloud scheduling, self-improving loops — runs an agent that holds production credentials with no human watching the outbound POST. The 24/25 result says the model *will* be talked into the exfil call under adversarial conditions; the only thing that holds is a process the model cannot argue with. event-vendor today has zero such control: `gh api *`, `WebFetch(*)`, `supabase *`, and `apply_migration` are all allow-listed at destination granularity with no operation-level enforcer (`CANONICAL-HARNESS-AS-IS.md` lines 206–207; pass3 Gap 1, verified). Shipping the enforcement plane converts "autonomy is risky" into "autonomy is bounded," which is the difference between a demo and a world-class autonomous harness.
